## 완료 로그 (원문, `PARITY_BACKLOG.md`의 "완료 로그" 섹션에서 이관)

- **2026-08-20 — P1-42**: `mentionList`가 프로젝트 멤버+조직 그룹멤버(또는 query 검색)만 후보로 삼던 문제 수정. yona `ProjectApp.java`의 `collectAuthorAndCommenter`/`addProjectAuthorsAndWatchersList`/`addSharers`/`addProjectNameToMentionList`/`addOrganizationNameToMentionList`를 모두 이식.
  - `mentionList` 엔드포인트에 `number`/`resourceType` 쿼리 파라미터 추가(원래 yona에는 아예 없었음 — 이 두 값이 없으면 `collectAuthorAndCommenter`/`addSharers`가 어떤 이슈/게시글 컨텍스트인지 알 수 없어 애초에 동작 불가능했다).
  - `collectAuthorAndCommenter`: ISSUE_POST/BOARD_POST 댓글을 오래된 순으로 조회한 뒤, "이미 리스트에 있으면 제거 후 끝에 재추가 → 전체 뒤집기"로 최근 댓글 작성자가 먼저 오도록 정렬(legacy와 동일한 알고리즘), 마지막에 게시물 작성자를 추가.
  - `collectProjectAuthorsAndWatchers`(yona `Project.findAuthorsAndWatchers`): 프로젝트의 이슈/게시글 작성자(`authorId`)와 PR contributor, 그리고 `Watch(resourceType=PROJECT)` 워처를 모두 후보에 포함.
  - `collectSharers`: ISSUE_POST에 한해 `issue.sharers`를 후보에 포함.
  - `addProjectNameToMentionList`/`addOrganizationNameToMentionList`: "@project all:"/"@group all:" 특수 항목을 후보 리스트 크기에 따라 특정 위치(9번째 근처)에 삽입, 이미지는 기존 `/projects/{id}/logo`·`/organizations/{id}/logo` 라우트를 재사용.
  - **의도적 편차 1건**: legacy `addOrganizationNameToMentionList`는 리스트 크기가 9를 넘으면 인덱스 9에 삽입하고 **또** 맨 끝에 추가해 "@group all:" 항목이 중복 등록되는 버그가 있음을 확인 — 이는 명백한 원본 결함으로 판단해 그대로 포팅하지 않고 한 번만 삽입하도록 정정했다(코드 주석에 명시).
  - **범위는 여전히 유지되는 미구현**: `mentionListAtCommitDiff`/`mentionListAtPullRequest`(커밋/PR 화면 전용 변형, 커밋 작성자·코드댓글 작성자·PR contributor 추가)는 [[tickets/p1-43|P1-43]]으로 계속 분리 상태.
  - 테스트: `MentionControllerSpec.kt` — 기존 4개 테스트에 "@project all:"/"@group all:" 추가분 반영(assertion 갱신), 신규 3 tests(댓글 작성자 최근순+게시물 작성자, 프로젝트 작성자/워처 포함, 이슈 공유자 포함). 인접 회귀: `web/MentionControllerSpec`, `web/Issue*`, `web/Board*`, `YonaApplicationTests` 전체 재실행 통과.
  - 검증: `./gradlew compileKotlin compileTestKotlin`, `./gradlew test --tests "com.github.yonaprojects.yona.web.MentionControllerSpec" --tests "com.github.yonaprojects.yona.web.Issue*" --tests "com.github.yonaprojects.yona.web.Board*" --tests "com.github.yonaprojects.yona.YonaApplicationTests"` 모두 통과.
