## 완료 로그 (원문, `PARITY_BACKLOG.md`의 "완료 로그" 섹션에서 이관)

- **2026-08-22 — P2-32**: noreferrer 처리(`Markdown.java checkReferrer()`)가 yona에서는 알림메일 렌더링 경로에만 있고 일반 마크다운 렌더링(`MarkdownServiceImpl.renderCore()`)에는 없어, 게시글/댓글 본문에 외부 링크를 걸어도 `rel=noreferrer`가 붙지 않던 문제를 수정.
  - `MarkdownServiceImpl`에 `@Value("\${application.noreferrer:false}") noreferrerEnabled: Boolean`, `@Value("\${yona.hostname:localhost}") hostname: String` 생성자 파라미터 추가(legacy `application.conf`의 `application.noreferrer`/`application.hostname` 대응). 새 private 메서드 `checkReferrer(source)`가 `noreferrerEnabled`가 꺼져 있으면 그대로 반환하고, 켜져 있으면 Jsoup으로 `href` 속성이 있는 모든 요소를 순회해 호스트가 `hostname`으로 시작하지 않는 링크에만 기존 `rel` 값에 `" noreferrer"`를 덧붙임(legacy `checkReferrer` 로직 그대로 — URI 파싱 실패 시 해당 링크는 건너뜀).
  - sanitizer 정책의 `a` 요소 허용 속성 목록에 `"rel"` 추가(기존엔 `href`/`name`/`target`만 허용해 OWASP 정책이 `rel`을 조용히 제거하고 있었음).
  - `renderCore()` 파이프라인에 `renderer.render(document)` → `checkReferrer(html)` → `sanitize(...)` 순서로 연결.
  - 테스트(TDD, 레드 확인 후 그린): `MarkdownServiceImplSpec.kt`에 `describe("MarkdownServiceImpl noreferrer 처리 (P2-32)")` 신규 4 tests(noreferrer 활성화 시 외부 링크에 rel=noreferrer 추가/같은 hostname 링크는 제외/noreferrer 비활성화 시 아무 것도 추가 안 함/비활성화 테스트가 활성화 테스트와 동일 소스 텍스트를 쓰면 `MarkdownRenderCache`(source.hashCode() 키의 전역 싱글턴 캐시) 오염으로 거짓 실패가 나는 걸 발견해 서로 다른 소스 텍스트로 분리).
  - 검증: `./gradlew test --tests "com.github.yonaprojects.yona.domain.support.MarkdownServiceImplSpec"` 전체 통과.
