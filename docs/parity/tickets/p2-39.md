## 완료 로그 (원문, `PARITY_BACKLOG.md`의 "완료 로그" 섹션에서 이관)

- **2026-08-22 — P2-39**: [[tickets/p1-106|P1-106]]에서 PR "conversation" 탭에 댓글 스레드를 이벤트와 함께 타임라인으로 병합해 보여주던 기능이 legacy `git/view.scala.html`(conversation 탭은 `pullRequestEvents`만 표시, 댓글은 오직 "changes" 탭 diff 인라인에서만 노출)의 원본 범위를 넘어선 확장이었음을 사용자에게 확인받아(AskUserQuestion, "legacy에 맞춰 되돌리기" 선택) 제거.
  - `PullRequestViewController.viewPullRequest()`의 `tab == "conversation"` 분기에서 `commentThreadRepository.findByPullRequest(pullRequest)` 조회와 `commentThreads` 모델 속성 주입을 제거 — `timeline`은 이제 `pullRequestEventRepository`에서 조회한 이벤트(렌더링 대상 타입만: STATE_CHANGED/MERGED/REVIEW_STATE_CHANGED)만으로 구성된다.
  - `PullRequestTimelineItem` 데이터 클래스에서 THREAD/EVENT 구분용 `kind: String`과 `thread: CommentThread?` 필드를 제거(이제 이벤트 전용이라 판별자 자체가 불필요) — `date`/`event` 두 필드만 남김.
  - `pullrequest/view.html`(Thymeleaf 템플릿, 이미 존재하는 UI)에서 `item.kind == 'THREAD'` 분기의 댓글 스레드 렌더링 블록(작성자/상태뱃지/코드범위/댓글목록/답글폼)과, 그 옆에 있던 "PR 대화에 새 의견 남기기"(conversation 탭 전용 신규 댓글 작성 폼 — 되돌리는 기능과 짝을 이루는 UI라 함께 제거하지 않으면 작성해도 어디서도 보이지 않는 죽은 기능이 됨) 폼을 제거. 이벤트 렌더링 블록은 `item.kind == 'EVENT'` 조건만 제거하고 그대로 유지.
  - 이 작업 중 `TimelineTemplateRenderingSpec.kt`(실제 Thymeleaf 렌더링을 검증하는 기존 테스트)가 템플릿의 이제-존재하지-않는 `item.kind`/`item.thread`를 참조하다 `TemplateProcessingException`으로 깨지는 것을 전체 스위트 실행으로 발견 — 별도 항목이 아니라 이번 되돌리기 작업의 직접적 여파라 같은 커밋에서 함께 수정.
  - 테스트(TDD, 레드 확인 후 그린): `PullRequestViewControllerSpec.kt`의 기존 timeline 테스트를 "이벤트만 시간순으로 담기고 댓글스레드는 제외되어야 한다"로 재작성(댓글스레드 픽스처 제거, `commentThreadRepository.findByPullRequest`가 호출되지 않음과 `commentThreads` 모델 키 자체가 없음을 검증 추가).
  - 검증: `./gradlew test --tests "com.github.yonaprojects.yona.web.PullRequestViewControllerSpec" --tests "com.github.yonaprojects.yona.web.TimelineTemplateRenderingSpec"` 전체 통과, 전체 스위트 `./gradlew test` 1230개 전체 통과(실패 0).
