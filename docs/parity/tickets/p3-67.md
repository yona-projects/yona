# P3-67: 웹훅 등록 폼에 Payload URL 필수 입력 클라이언트측 검증이 없음

## 배경

`service/yona.project.Webhook.js`는 웹훅 등록 폼(`project/setting_webhook.html`)의
`payloadUrl` 필드가 비어 있으면 `submit` 이벤트를 막고
`$yona.alert(Messages("project.webhook.payloadUrl.empty"))`로 안내 메시지를 보여주는
클라이언트측 검증을 제공한다(legacy에서도 동일한 파일이 동일 화면에 로드됨,
`app/views/project/setting_webhook.scala.html` 대조 확인).

`project/setting_webhook.html`의 실제 인라인 스크립트는 JSON 타입 선택 시 "Git Push" 이벤트를
강제 체크하는 로직만 있고, `yona.project.Webhook.js` 자체는 어디에도 `<script src>`로 로드되지
않는다(`$yona.loadModule`도 아님 — 이 파일은 `service/` 디렉터리에 있지만 legacy 방식대로
직접 `<script src>`로 로드되는 파일이었다).

## 실제 영향

- 사용자가 Payload URL을 비운 채 "웹훅 등록" 버튼을 누르면 클라이언트측에서 아무 안내 없이
  그대로 폼이 제출된다.
- 서버측(`WebhookController.kt:82`, `payloadUrl.isBlank()` 체크)이 최종 방어선으로 남아있어
  **데이터 무결성 문제는 없다** — 빈 값으로 웹훅이 실제로 생성되지는 않는다. 다만 서버 응답이
  legacy가 제공하던 즉각적인 인라인 안내(`Messages("project.webhook.payloadUrl.empty")`)만큼
  친절한 UX인지는 미확인(리다이렉트+플래시 메시지인지, 별도 확인 필요).
- 우선순위: 낮음(보안/데이터 문제 아님, 순수 UX 격차).

## 완료 기준

- [ ] `project/setting_webhook.html`에 `yona.project.Webhook.js`를 실제로 로드(`<script src>`
      또는 동등한 초기화 호출)하고, 빈 Payload URL 제출 시 클라이언트측에서 즉시 차단+안내되는지
      Playwright로 확인.
- [ ] 위 배선 후 `_isFormValid()`가 실제로 이 폼의 `payloadUrl` 필드(`name="payloadUrl"`)를
      정확히 찾는지(마크업 계약 일치) 확인 — 포팅 과정에서 name/id가 달라졌을 가능성 배제 필요.
- [ ] 서버측 거부 시(현재 동작) 응답이 사용자에게 최소한의 안내를 주는지 별도 확인, 필요시
      함께 개선.

## 감사 방법론 참고 (재사용 가능)

`static/javascripts/{common,service,template}`의 JS 파일이 실제로 "적용"되는 경로는 3가지이며,
이 중 하나라도 없으면 죽은 파일이다:

1. 템플릿의 `<script src="...">`(또는 `th:src="@{...}"`) 직접 로드.
2. `support-script/js-bundle/minify-js.sh`의 `--js` 재료 목록에 포함되어
   `yona-lib.js`/`yona-common.js`/`yona-layout.js` 번들에 컴파일됨(이 스크립트의 재료 목록
   자체가 SSOT — 여기 없으면 번들에도 없다).
3. `service/` 파일 한정, `$yona.loadModule("X.Y")` 동적 로드(`common/yona.Common.js`의
   `loadModule()`이 `service/yona.<X.Y>.js`를 런타임에 fetch) — 파일명이 아니라
   `loadModule("...")` 호출 문자열로 검색해야 함(파일명 자체는 템플릿에 전혀 안 나타남).

이번 감사에서 위 3가지 전부에 해당하지 않은 파일은 최종적으로 이 티켓(Webhook) 하나만
남았다 — 나머지는 P3-52가 이미 "다른 방식으로 재구현됨/원래 죽은 코드"로 결론 낸 것과
일치하거나(`yona.Interval.js`/`yona.Sha1.js`), 템플릿 인라인 주석에 "REST API로 직결,
loadModule 대신"이라고 이미 설계상 대체가 문서화돼 있음(`yona.organization.Member.js`/
`yona.project.Member.js` — `project/members.html`/`organization/members.html`이 REST API를
직접 호출), 또는 legacy에도 로드되지 않던 완전한 죽은 코드였다(`yobi.WatcherList.js`/
`yobi.ui.Mergely.js`/`yobi.CodeTemplate.js`).
