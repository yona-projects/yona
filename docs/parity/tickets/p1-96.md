## 완료 로그 (원문, `PARITY_BACKLOG.md`의 "완료 로그" 섹션에서 이관)

- **2026-08-20 — P1-96**: `AttachmentController`의 `getFile()`(다운로드/인라인 조회)·`getFileList()`(목록 조회)에 권한 체크 자체가 없어, PRIVATE 프로젝트 첨부파일도 비로그인 사용자가 id 또는 containerType/containerId만 알면 그대로 열람 가능하던 보안 결함 수정. [[tickets/p1-85|P1-85]] 1b에서 추가한 `accessControl.isAllowedAttachment(user, attachment, Operation.READ)`(컨테이너를 동적으로 해석해 위임)를 두 엔드포인트에 배선.
  - `getFile()`: `principal` 파라미터 추가, `attachmentRepository.findById(id)`로 조회한 실제 `Attachment`로 READ 권한 확인 후 실패 시 403.
  - `getFileList()`: 특정 첨부가 아니라 컨테이너 단위 질의라 `Attachment(containerType, containerId)` 더미 인스턴스(id/name/hash 등은 판정에 안 쓰여 비워도 안전)를 만들어 동일한 `isAllowedAttachment()`를 재사용, 실패 시 403.
  - **[[tickets/p1-85|P1-85]] 1b 자체의 버그 발견·수정(부수)**: `isAllowedAttachment()`의 `USER_AVATAR` 케이스가 READ까지 본인 전용으로 막고 있어(UPDATE/DELETE만 본인 전용이어야 함), 이 항목을 실제로 배선하는 과정에서 그대로 뒀다면 **모든 사용자의 아바타 이미지가 본인 외에는 아무도 못 보게 되는 회귀**를 만들 뻔했다. legacy `AccessControl.java:130-138`(`isGlobalResourceAllowed`의 READ 분기 — "PROJECT가 아닌 리소스는 누구나 읽을 수 있다")를 다시 확인해, READ는 항상 허용하고 UPDATE/DELETE만 본인 확인하도록 수정.
  - 테스트: `AttachmentControllerSpec.kt` +3(다운로드 권한없음 403/목록조회 권한없음 403 신규, 기존 2건은 principal+권한 스텁 보강) — 기존 5건 포함 총 8 tests. `AccessControlSpec.kt`의 USER_AVATAR 테스트에 READ 허용(본인 아님/익명 둘 다) 케이스 보강.
  - 검증: `./gradlew test --tests "AttachmentControllerSpec" --tests "AccessControlSpec"` 전체 통과, `./gradlew compileKotlin compileTestKotlin` 전체 컴파일 성공.
