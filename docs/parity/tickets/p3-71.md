# P3-71: 프로젝트 가져오기 화면의 "저장소 인증정보" 체크박스가 반전 동작함

## 배경

`project/importing.html`(레포지토리 가져오기 화면)에서 "인증정보 사용" 체크박스를 클릭하면
`#repoAuth` 패널이 슬라이드로 열려야 하는데, 실제로는 **체크하면 닫히고 언체크하면
열리는 반전 동작**을 한다.

## 근본 원인(P3-70 라운드5에서 소스 레벨로 확정)

`project/importing.html`의 `$(function(){...})`(현재는 vanilla로 전환됨)가 같은
`#useRepoAuth`의 `change` 이벤트에 핸들러를 **두 개** 등록한다:

1. 템플릿 자체의 단순 핸들러(먼저 등록) — 체크 시 `#repoAuth`를 즉시 보이는 상태로 만듦.
2. `$yona.loadModule("project.New", ...)`가 붙이는 `project.New.js`의
   `_attachEvent()`(나중에 등록) — `.toggle("slide")`(jQuery UI) 애니메이션으로
   열고/닫는다.

jQuery UI의 `.toggle(effect)`는 `lib/jquery/jquery-ui.custom.js:11151`에서 **호출되는
바로 그 순간의 현재 가시성**을 보고 열지/닫을지를 정한다
(`mode = $(this).is(':visible') ? 'hide' : 'show'`). 두 핸들러가 등록 순서대로 실행되므로:

1. 체크 → 핸들러1이 `#repoAuth`를 먼저 "보임"으로 만듦
2. 곧바로 핸들러2의 `.toggle("slide")`가 "지금 이미 보인다"고 판단해 **반대 방향(닫힘)**
   애니메이션을 실행

언체크도 대칭적으로 반전된다. **이 결함은 vanilla 전환 이전(순수 jQuery 시절)부터
있었다** — git 히스토리상 두 핸들러가 같은 이벤트에 이중으로 걸리는 구조 자체가 원래
설계였고, P3-70은 이 구조를 그대로(반전 동작까지 포함해) 정확히 이식했을 뿐이다.

## 완료 기준

- [ ] 두 핸들러 중 하나로 통합하거나(권장: `project.New.js`의 `_toggleSlide`가
      `#useRepoAuth.checked`를 직접 참조해 판단하도록 하고, 템플릿의 단순 핸들러는
      제거) 등가의 방법으로 반전을 해소.
- [ ] 체크 시 패널이 열리고 언체크 시 닫히는 것을 Playwright로 확인.
- [ ] `disabled` 속성 토글(체크박스 상태와 직접 연동, 이 반전과 무관하게 이미 정상)은
      회귀 없이 유지.
- [ ] 관련 스펙(`ProjectControllerSpec`/`ProjectViewControllerSpec`/
      `TemplateEquivalenceSpec`) 회귀 없음 확인.
