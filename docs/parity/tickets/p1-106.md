## 완료 로그 (원문, `PARITY_BACKLOG.md`의 "완료 로그" 섹션에서 이관)

- **2026-08-21 — P1-106**: 이슈/PR 상세 화면에 상태·담당자·라벨·마일스톤·이동/병합/리뷰완료 타임라인 이벤트 렌더링 배선.
  - Serena LSP로 yona `app/views/issue/partial_event_timeline.scala.html`/`app/views/git/partial_pull_request_event.scala.html`을 심볼 단위로 재확인 — 이벤트 타입별 메시지 i18n 키(`issue.event.*`/`pullRequest.event.*`)가 yona `messages_ko.properties`에 **이미 이식돼 있었지만 어느 템플릿도 참조하지 않고 있었음**을 확인(순수 배선 누락이었다는 원 등록 판단이 정확했음).
  - **이슈**: `domain/issue/IssueTimelineItem.kt`(신규, kind로 COMMENT/EVENT 판별) — `IssueViewController.viewIssue()`가 `issueCommentRepository`+`issueEventRepository`(ISSUE_BODY_CHANGED는 legacy와 동일하게 제외)를 시간순으로 병합해 `timeline` 모델 속성으로 전달. `issue/view.html`의 기존 `th:each="comment : ${comments}"` 루프를 `th:each="item : ${timeline}"` + `th:if`+`th:with`로 감싸 기존 댓글 렌더링 내부 마크업은 건드리지 않고, STATE_CHANGED/ASSIGNEE_CHANGED/MILESTONE_CHANGED/MOVED/LABEL_CHANGED 5종 이벤트 렌더링을 신규 추가.
  - **PR**: `domain/pullrequest/PullRequestTimelineItem.kt`(신규) — `PullRequestViewController.viewPullRequest()`의 conversation 탭이 `commentThreadRepository`+`pullRequestEventRepository`를 병합, legacy 파샬이 실제로 렌더링하는 STATE_CHANGED/MERGED/REVIEW_STATE_CHANGED 3종만 표시(legacy도 NEW_PULL_REQUEST/COMMIT_CHANGED는 `case _ => {}`로 건너뜀 — 그대로 재현). `pullrequest/view.html`의 `th:each="thread : ${commentThreads}"` 카드 루프도 동일한 감싸기 기법으로 이벤트 카드를 추가.
  - **데이터 모델 차이로 인한 의도적 조정(투명하게 기록)**: yona의 `IssueEvent`/`PullRequestEvent`는 legacy와 달리 담당자/마일스톤을 **이름 문자열**로 저장하고(ID 아님), 라벨 변경은 **전체 라벨 목록의 전/후 문자열**로 저장(legacy는 단일 라벨 add/delete diff) — 이 때문에 (a) 담당자 이벤트에서 "나에게 배정" 여부를 판별하는 legacy의 loginId 비교를 재현할 수 없어 항상 일반 배정 문구 사용, (b) 마일스톤 이벤트에 legacy식 클릭 가능한 마일스톤 링크 대신 이름 텍스트만 표시, (c) 라벨 이벤트는 legacy의 개별 추가/삭제 문구 대신 "before → after" 형태의 신규 메시지 키(`issue.event.label.changed`, `messages.properties`+`messages_ko.properties`에 추가)로 대체. (d) 발신자도 표시 가능한 필드가 `senderLoginId`뿐이라 legacy의 아바타+이름 링크 대신 로그인ID 텍스트로 표시. 모두 이벤트 자체가 안 보이던 원래 결함(핵심 문제)과는 무관한, 기존 스키마 제약에서 나온 표시 방식 차이.
  - 테스트: `IssueViewControllerSpec.kt` +1(댓글+이벤트 병합 순서, ISSUE_BODY_CHANGED 제외 검증), `PullRequestViewControllerSpec.kt` +1(댓글스레드+이벤트 병합 순서, NEW_PULL_REQUEST 제외 검증) — 두 스펙 모두 새 리포지토리 의존성(`IssueEventRepository`/`PullRequestEventRepository`) 추가로 인한 생성자 변경도 함께 반영.
  - **템플릿 렌더링 자체 검증**: 브라우저는 이 headless 환경에 없어 직접 클릭해보지 못했지만, mockk 기반 컨트롤러 단위 테스트는 실제 Thymeleaf를 태우지 않아 마크업 오류를 못 잡는다는 한계가 있어 `TimelineTemplateRenderingSpec.kt`(신규, `MockMvcBuilders.webAppContextSetup()`로 실제 ViewResolver를 태움)를 추가해 실제 HTML 응답에 이벤트 메시지 문자열이 나타나는지까지 확인했다. 이 스펙이 실제로 다음 두 버그를 잡아냈다: **①** `th:switch`/`th:case`에 `T(FQCN).ENUM` 형태를 바로 못 씀(OGNL/th:case 파서가 SpEL 타입 표현식을 못 받아들임, `Could not parse as expression` 오류) — `th:if="${event.eventType.name() == 'ENUM_NAME'}"` 문자열 비교로 두 템플릿 모두 수정. **②** `pullrequest/view.html`의 diff 렌더링 코드(내가 손대지 않은 기존 코드, "changes" 탭)에 `<td>` 태그의 `class` 속성이 두 번 선언된 **기존부터 있던 마크업 오류**가 있어 attoparser가 템플릿 전체를 파싱조차 못 하고 있었음(`Attribute "class" appears more than once`) — 이걸 고치지 않으면 conversation 탭을 포함해 이 템플릿을 쓰는 페이지 전체가 항상 500 에러였을 것으로 보임(브라우저로도 지금까지 아무도 이 탭들을 실제로 렌더링해본 적이 없었다는 뜻) — `class="linenum add-comment-btn-cell"`로 병합해 해결(2곳).
  - 검증: 관련 스펙 개별 통과 확인 후 `./gradlew test` 전체 1020 tests 통과(회귀 없음 확인).
