# P3-55: PR "Changes" 탭의 코드리뷰 댓글 UX가 두 갈래로 쪼개져 있고, 그중 라인 댓글 쪽은
마크다운 에디터가 아예 안 붙어있음

## 배경

`pullrequest/view.html`의 "Changes" 탭(`/{owner}/{project}/pull/{number}/changes`)에는
코드리뷰 댓글을 작성하는 경로가 실질적으로 두 갈래가 있다.

1. **`common/reviewForm.html`(`#review-form`)** — 프로젝트당 하나, "범위 없는(코드 전체 대상)"
   리뷰 댓글을 시작하는 폼. `<yona-markdown-editor>`가 정상적으로 붙어있고 CM6
   렌더링/타이핑/툴바 9개/멘션 3트리거/미리보기 전부 정상 동작함을 이번에 Playwright로 직접
   확인했다. **다만 이 폼은 기본적으로 `display:none`이고, 이걸 보이게 만드는 트리거
   (`yobi.CodeCommentBox.js`의 `.show()`)를 호출하는 코드가 이 페이지 어디에도 없다** —
   `yobi.code.Diff.js`(원래 이 트리거를 담당하는 스크립트)가 어느 템플릿에서도
   `<script src>`로 로드되지 않는다(이 세션에서 반복 확인된 "소스는 있지만 로드가 안 되는"
   패턴과 동일 종류). 즉 `#review-form`은 현재 UI 어디서도 사용자가 열 수 없는 죽은 화면
   요소다.
2. **라인별(ranged) 댓글** — `pullrequest/view.html`의 인라인 `<script>`가 diff 라인의
   `.add-comment-btn-cell` 클릭을 자체적으로 가로채, `common/reviewForm.html`/
   `<yona-markdown-editor>`를 전혀 쓰지 않고 순수 문자열 결합으로 `<textarea name="contents">`
   폼을 즉석에서 DOM에 삽입한다(`pullrequest/view.html` "Changes" 탭 인라인 스크립트,
   `formHtml = '<tr>...<textarea name="contents" ...></textarea>...'` 부분). 서버 제출
   자체(`ReviewViewController.newPullRequestComment`)는 정상 동작하지만, 사용자는 이 경로로는
   툴바/멘션(`@`/`:`/`#`)/서버 렌더링 미리보기를 전혀 못 쓴다 — P3-46이 다른 15개 화면에서
   구축한 CM6 에디터 경험이 이 경로에만 빠져 있다.

두 경로 모두 최종적으로 `ReviewViewController`의 같은 두 엔드포인트
(`POST /{owner}/{project}/pullRequest/{id}/comments`,
`POST /{owner}/{project}/commit/{commitId}/comments`)로 제출되므로 서버 측 로직은
문제없다 — 순전히 화면(뷰) 배선의 문제다.

## 확인된 사실 (이번 세션에서 직접 재현)

- `#review-form`을 Playwright로 강제로 `style.display='block'`시켜서 확인한 결과, 안의
  `<yona-markdown-editor>`는 렌더링/타이핑/light DOM textarea 동기화/툴바 9개 전부/미리보기/
  멘션(`@`/`:`/`#`) 3트리거 전부 정상 동작한다 — **컴포넌트 자체는 문제 없음**, 순수하게
  "아무도 이 폼을 보여주지 않는다"는 배선 문제.
- `grep -rl "yobi.code.Diff.js" src/main/resources/templates`가 0건 — 로드하는 템플릿이
  아예 없다.
- 라인별 댓글 삽입 폼(`pullrequest/view.html` 인라인 스크립트)은 실제로 diff 라인을 클릭하면
  뜨고, 제출도 서버에 정상 도달한다(302) — 다만 정말 순수 `<textarea>`만 있고
  `<yona-markdown-editor>`/툴바/멘션/미리보기가 전혀 없다.

## 제안하는 다음 단계 (설계 판단 필요 — 착수 전 코디네이터 확인)

세 가지 방향이 있고 어느 쪽이 맞는지는 제품 의도에 대한 판단이 필요해 보여 백로그로만
등록한다:

1. **`#review-form`을 완전히 제거**하고, 라인별 댓글 경로만 유지하되 그 경로에도
   `<yona-markdown-editor>`를 붙인다(현재 죽어있는 "범위 없는 리뷰 댓글 시작" 기능 자체를
   포기하는 방향 — GitHub 스타일과는 다름).
2. **`#review-form`을 실제로 살린다** — `.add-comment-btn-cell` 클릭 시(또는 별도의
   "일반 댓글 추가" 버튼을 새로 만들어) `yobi.CodeCommentBox.show()`를 호출하도록 배선하고,
   라인별 댓글은 계속 지금의 인라인 삽입 방식을 쓰되 그 안의 `<textarea>`도
   `<yona-markdown-editor>`로 교체한다(두 경로 모두 CM6 에디터를 쓰게 통일).
3. 라인별 댓글 폼을 서버 렌더링(Thymeleaf fragment 재사용, `pullrequest/partial_comment_form_on_thread.html`처럼)으로 바꿔 애초에 클라이언트 문자열 조립을 없애고, 그 김에
   `<yona-markdown-editor>`를 자연스럽게 붙인다(가장 아키텍처적으로 깔끔하지만 작업량 최대).

착수 시 TDD로 "라인 댓글 폼에 CM6 에디터가 있어야 한다"는 회귀 스펙을 먼저 세우고 진행할 것.
