## 완료 로그 (원문, `PARITY_BACKLOG.md`의 "완료 로그" 섹션에서 이관)

- **2026-08-20 — P1-25**: git push 시 커밋 알림용 `NotificationEvent`는 저장되고 있었지만 아무도 구독하지 않는(=`eventPublisher.publishEvent()`를 호출하지 않는) 채로 방치돼 있어, push(NEW_COMMIT)에 대해서는 웹훅이 한 번도 발송되지 않던 문제 수정(yona `Webhook.sendRequestToPayloadUrl(List<RevCommit>, List<String>, User)` 대응).
  - **설계 방향(원안과 다르게 결정, 이유 명시)**: 백로그 원안은 "`WebhookServiceImpl`에 COMMIT 케이스를 추가하고 `processCommitsNotification`에서 `eventPublisher.publishEvent()`를 호출"하는 방식을 제안했지만, 실제로 그 경로(`WebhookNotificationEventListener.resolveResource()`)는 `resourceId`로 DB 엔티티를 재조회해 소속 프로젝트를 알아내는 구조라 커밋(DB 엔티티가 아니고, 커밋 SHA만으로는 어느 프로젝트인지 알 수 없음)에는 애초에 맞지 않는다. yona 원본도 실제로는 이 범용 경로를 쓰지 않고 `Webhook.sendRequestToPayloadUrl(commits, refNames, sender)`라는 **커밋 전용 직접 호출 경로**를 따로 두고 있었다(`Webhook.java:659-703`). 이를 그대로 좇아, `project`/`commits`를 이미 들고 있는 `GitPostReceiveEventListener.processCommitsNotification()`에서 `webhookService.sendWebhook()`을 직접 호출하도록 구현 — `WebhookNotificationEventListener`를 거치지 않는다.
  - 신규 `domain/webhook/PushedCommits.kt`(마커 데이터 클래스, `commits: List<RevCommit>` + `refNames: List<String>`)를 `WebhookServiceImpl.sendWebhook()`의 `resource: Any` 자리에 전달. `getResourceType`/`getResourceId`/`buildTextMessage`에 `PushedCommits` 케이스 추가(`getResourceType` → `ResourceType.COMMIT`, `getResourceId` → 첫 커밋 SHA, 텍스트 메시지는 "N개의 커밋을 X 브랜치로 푸시했습니다"). `shouldDeliverToWebhook`의 `gitPush` 플래그 게이팅([[tickets/p0-04|P0-04]]에서 이미 구현)은 그대로 재사용되므로 추가 변경 불필요.
  - `processCommitsNotification`을 `private`→`internal`로 변경해 단위테스트 가능하게 함(기존 `recordReferredIssues`와 동일 패턴).
  - **범위를 벗어나 식별한 것([[tickets/p1-46|P1-46]]으로 분리)**: 이번엔 웹훅만 고쳤고, 같은 `NotificationEvent`가 메일 알림([[tickets/p0-01|P0-01]])까지 타려면 `receivers` 계산 + `eventPublisher.publishEvent()` 호출이 필요한데 둘 다 빠져 있어 push 커밋에 대한 메일은 여전히 발송되지 않는다.
  - 테스트: `GitPostReceiveEventListenerSpec.kt` +2(신규 — 커밋이 있으면 알림 저장+웹훅 발송 확인, 커밋이 없으면 아무 것도 안 함) — `RevCommit`은 실제 값이 필요해(protected 생성자) `InMemoryRepository`(JGit DFS)로 진짜 커밋을 만들어 테스트. 기존 4건 포함 총 6 tests(이후 [[tickets/p1-46|P1-46]]에서 같은 파일에 1건이 더 추가돼 현재는 총 7 tests). `WebhookServiceSpec`/`WebhookNotificationEventListenerSpec`/`YonaApplicationTests` 재실행으로 회귀 없음 확인.
  - 검증: `./gradlew test --tests "GitPostReceiveEventListenerSpec" --tests "com.github.yonaprojects.yona.domain.webhook.*" --tests "YonaApplicationTests"` 전체 통과, `./gradlew compileKotlin compileTestKotlin` 전체 컴파일 성공.
