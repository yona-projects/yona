- **2026-08-20 — P1-80**: 이슈 라벨 배타(exclusive) 카테고리 제약을 서버에서 검증하도록 이식.
  - `IssueServiceImpl.checkExclusiveLabelCategories()` 신규 — yona `Issue.checkLabels()`와 동일하게, 라벨을 순회하며 이미 본 배타 카테고리가 다시 나오면 거부. `updateIssue()`의 라벨 재할당 직후에만 호출한다(yona도 `AbstractPostingApp.editPosting()`, 즉 **수정 시에만** 호출하고 생성 시에는 호출하지 않는 것을 그대로 재현 — `IssueApp.java`/`Posting.checkLabels()`(board는 no-op) 전수 확인으로 검증).
  - `IssueLabelExclusiveCategoryException` 신규(`IssueService.kt`) — `@ResponseStatus(BAD_REQUEST)`로 yona `badRequest(e.getMessage())`와 동일한 관찰 가능 동작(다른 서비스의 `DuplicatedPullRequestException` 등과 동일한 기존 패턴 재사용, 컨트롤러 코드 변경 불필요).
  - 테스트: `IssueServiceSpec.kt` +2(같은 배타 카테고리 라벨 2개 이상 붙이면 예외/서로 다른 배타 카테고리는 각각 하나씩 정상 첨부).
  - 검증: `./gradlew compileKotlin compileTestKotlin`, `IssueServiceSpec` 29 tests 전체 통과.
