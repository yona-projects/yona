## 완료 로그 (원문, `PARITY_BACKLOG.md`의 "완료 로그" 섹션에서 이관)

- **2026-08-20 — P1-87**: `WebhookController`의 `webhooks()`/`newWebhook()`/`deleteWebhook()` 세 엔드포인트 전부에 로그인/권한 체크가 전혀 없던 취약점 수정. legacy `@IsAllowed(Operation.UPDATE)`(resourceType 기본값 PROJECT)를 Serena LSP로 `IsAllowedAction.java`/`IsAllowed.java`/`Resource.getResourceObject()`까지 직접 대조해 추적한 결과, resourceType=PROJECT는 project 자신을 GlobalResource로 돌려줘 `isGlobalResourceAllowed()`의 PROJECT 케이스(`ProjectUser.isManager || OrganizationUser.isAdmin`, 매니저/조직관리자 전용)를 타는 것을 확인 — **착수 당시 이 항목에 적혀 있던 "isMemberOf만 있으면 허용"이라는 서술은 부정확했으며, 그 부정확한 서술 그대로 구현했다면 legacy보다 과도하게 허용하는 새로운 결함을 만들 뻔했다.**
  - `WebhookController`에 `AccessControl` 주입 + `getLoginUser(authentication)`/`checkWebhookPermission(project, user) = accessControl.isAllowed(user, project, Operation.UPDATE)`([[tickets/p1-85|P1-85]] 1b에서 신규 추가된 PROJECT 오버로드 사용) 추가, 세 엔드포인트 모두 `authentication: Authentication?` 파라미터를 받아 권한 검사 후 실패 시 403 반환.
  - **부수 수정**: 이 파일에 파일-로컬로 정의돼 있던 가짜 `ResponseStatusException(status, reason)` 클래스가 `status` 인자를 완전히 무시하고 `@ResponseStatus(NOT_FOUND)`로 고정돼 있어(생성자 파라미터가 죽은 코드), `ResponseStatusException(HttpStatus.FORBIDDEN, ...)`을 던져도 실제 응답은 항상 404가 되는 잠재 버그를 발견 — 이 코드베이스의 다른 모든 컨트롤러가 쓰는 진짜 `org.springframework.web.server.ResponseStatusException`(동적 status)으로 교체하고 가짜 클래스는 삭제.
  - 테스트: `WebhookControllerSpec.kt` +3(비로그인 조회 403, 비매니저 생성 403, 비매니저 삭제 403) — 기존 3건(정상 경로, 매니저 인증 스텁 추가로 계속 통과)까지 총 6 tests.
