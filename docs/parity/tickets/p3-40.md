# P3-40: annotated 태그로 커밋 히스토리 조회 시 500(`IncorrectObjectTypeException`)

## 배경

사용자가 "저장소 브라우저에 태그 보는 기능이 있냐"는 질문에 코디네이터가 실제 `git` CLI로
저장소를 만들고 annotated 태그(`v1.0.0`)를 push해 검증하던 중, 사용자가 직접 서버를 열어
`GET /admin/tagtest/commits/v1.0.0`(그 태그 시점부터의 커밋 히스토리 화면)에 접속했다가 실제
500 에러를 재현해 보고했다.

**근본원인**: annotated 태그는 Git 객체 모델상 브랜치/lightweight 태그와 달리 ref가 커밋을
직접 가리키지 않고 별도의 "태그 오브젝트"(RevTag)를 가리킨다. `GitRepository.getHistory()`가
`repo.resolve(rev)`로 얻은 `ObjectId`를 peel(태그 오브젝트를 실제 커밋까지 따라가는 것) 없이
그대로 JGit `LogCommand.add()`에 넘겨, annotated 태그 이름을 넘기면
`IncorrectObjectTypeException: Object ... is not a commit`이 발생했다.

`GitRepository.kt`의 다른 모든 `repo.resolve()` 호출부(14곳)는 전부 `RevWalk.parseCommit()`
또는 `parseTree()`로 peel한 뒤 사용해 이 문제가 없었다 — `getHistory()` 딱 하나만 그 관례를
빠뜨리고 있었다(전수 검색으로 확인, 다른 곳은 전부 안전함을 재확인).

## 범위

`GitRepository.getHistory()`에서 `logCommand.add(objectId)`를
`logCommand.add(RevWalk(repo).parseCommit(objectId))`로 교체.
