## 완료 로그 (원문, `PARITY_BACKLOG.md`의 "완료 로그" 섹션에서 이관)

- **2026-08-20 — P1-29**: 메일로 이슈/댓글을 만들 때([[tickets/p0-02|P0-02]]) 첨부파일이 통째로 유실되던 문제 수정(yona `CreationViaEmail.saveAttachments()` 대응). 본문 HTML 서식 보존과 cid 인라인 이미지 치환은 [[tickets/p1-47|P1-47]]로 분리.
  - `InboundEmailMessage`에 `attachments: List<InboundAttachment> = emptyList()` 추가(`InboundAttachment(fileName, contentType, bytes)`) — 기본값이라 기존 생성 코드/테스트는 영향 없음.
  - `ImapMailboxPoller`에 `extractAttachments()` 추가 — MIME 파트 트리를 재귀 순회하며 `multipart/*`는 하위 파트를 계속 펼치고, 파일명이 있는 파트(본문 텍스트 파트는 보통 파일명이 없음)를 첨부파일로 추출해 바이트로 읽어들인다. `toInboundEmailMessage`를 `private`→`internal`로 바꿔 실제 `jakarta.mail` 객체(`MimeMessage`/`MimeMultipart`/`MimeBodyPart`)를 구성해 IMAP 서버 없이도 단위테스트 가능하게 했다 — 이 클래스는 그동안 "글루 코드라 테스트 제외" 관례로 전혀 테스트되지 않았는데, MIME 파싱 로직 자체는 순수 로직이라 이번에 커버리지를 추가했다(연결 부분인 `connectAndProcess`는 기존 관례대로 계속 제외).
  - `IncomingMailProcessingService`에 `AttachmentService` 주입, 이슈/댓글 생성 성공 직후(`processTarget`) 첨부파일들을 생성된 리소스(`ResourceType.ISSUE_POST`/`BOARD_POST`)에 연결해 저장하는 `attachAttachments()` 추가. yona처럼 커밋 스레드/코드리뷰 스레드로의 첨부는 다루지 않음(원래도 그 스레드 타입 자체가 [[tickets/p1-30|P1-30]]으로 미지원).
  - **발견 후 별도 등록**: cid 인라인 이미지 치환(본문 HTML의 `cid:xxx` 참조를 저장된 첨부파일 URL로 바꾸는 것)과, HTML 전용 메일의 서식 보존(당시엔 jsoup으로 태그를 벗겨 순수 텍스트만 남김)은 이번 패스에 포함하지 않음 — **[[tickets/p1-47|P1-47]]로 별도 등록**, 이후 완료됨(`[x]`).
  - 테스트: `IncomingMailProcessingServiceSpec.kt` +3(신규 이슈 생성 시 첨부 연결, 기존 이슈 댓글 생성 시에도 첨부 연결, 첨부 없으면 AttachmentService 미호출) — 기존 9건 포함 총 12 tests. `ImapMailboxPollerSpec.kt`(신규, 이 클래스 최초의 테스트) 3 tests(단일 text/plain 본문 추출, multipart/mixed에서 첨부파일 추출, 첨부파일 여러 개 전부 추출) — 실제 `jakarta.mail` 객체로 구성.
  - 검증: `./gradlew test --tests "com.github.yonaprojects.yona.domain.mail.*" --tests "com.github.yonaprojects.yona.domain.attachment.*" --tests "YonaApplicationTests"` 전체 통과, `./gradlew compileKotlin compileTestKotlin` 전체 컴파일 성공.
