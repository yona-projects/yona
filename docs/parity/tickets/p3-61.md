# P3-61: 이슈 목록 화면(프로젝트 범위 + 내 이슈)에서 마일스톤으로 필터링해도 마일스톤 진행률
카드가 안 보임

## 배경

`docs/TEMPLATE_BACKLOG.md` #153(`milestone/partial_status.scala.html`)은 TASK-0253에서
"project/home.html 사이드바에 완전히 빠져있던 위젯을 신규 구현했다"고 기록하면서, 다음과 같이
결론지었다:

> legacy의 나머지 2개 호출부(`issue/partial_searchform.scala.html`,
> `issue/my_partial_search.scala.html`)는 프로젝트에 종속되지 않는 "내 이슈"(cross-project)
> 화면 전용이고 yona에 해당 컨트롤러/라우트 자체가 없어(포팅 범위 밖) 제외 — 프로젝트 홈
> 사이드바라는 핵심 호출부는 완전히 이식했다.

**이 판단이 두 가지 모두 틀렸다.**

## 재검증 결과 (Twirl 컴파일러 산출물 기반)

`legacy-yona/target/scala-2.10/twirl/main/views/html/issue/partial_searchform.template.scala`
(컴파일된 Scala 소스, 정규식 추정이 아니라 실제 컴파일러가 해석한 호출 관계)를 직접 대조한
결과:

1. **`issue/partial_searchform.scala.html`은 cross-project 전용이 아니다.** 이 파일의
   시그니처 자체가 `@(param: models.support.SearchCondition, project: Project)`로 **project를
   필수 파라미터로 받는다.** 그리고 실제 호출부는 `issue/partial_list_wrap.scala.html:42`의
   `@partial_searchform(param, project)`인데, 이 `partial_list_wrap`은 **프로젝트 범위 이슈
   목록 화면(`issue/list.scala.html` → yona `issue/list.html`)에 인라인되는 검색 사이드바**다
   (`docs/TEMPLATE_BACKLOG.md` #116/#118 등에서 이미 이 관계가 확인돼 있었다). 즉 이 파일은
   "내 이슈" 화면이 아니라 **가장 흔하게 쓰이는 프로젝트별 이슈 목록 화면 자체**에서 쓰인다.

2. **`issue/my_list.scala.html`(cross-project "내 이슈" 화면)도 실제로는 yona에 이식돼
   있다.** `UserViewController.kt:220`이 `"issue/my_list"` 뷰를 반환하는 라우트를 갖고 있고,
   실제 템플릿 `src/main/resources/templates/issue/my_list.html`/`my_partial_search.html`도
   존재한다 — "라우트 자체가 없다"는 전제가 틀렸다.

## legacy 원본

```scala
// legacy-yona/app/views/issue/partial_searchform.scala.html:106-113
@if(param.milestoneId != null){
    @defining(Milestone.findById(param.milestoneId)){ milestone =>
        @if(milestone != null){
            @views.html.milestone.partial_status(milestone, project)
            <hr>
        }
    }

```

`issue/my_partial_search.scala.html:52`에도 동일한 패턴이 있다. `milestone/partial_status`
본체는 마일스톤 제목(링크)/마감일(+기한초과 강조)/진행률 바(닫힌 이슈 수/전체 이슈 수)를
보여주는 정보 카드다.

## 현재 yona 상태 (격차 확정)

- `src/main/resources/templates/issue/list.html`(126~144행): 마일스톤 select2 드롭다운(열림/
  닫힘 optgroup)까지는 있지만, 특정 마일스톤이 선택됐을 때 그 아래 진행률 카드를 보여주는
  로직이 전혀 없다(`.milestone-info`/`partial_status` 마크업 grep 0건).
- `src/main/resources/templates/issue/my_partial_search.html`: `milestoneId`/`milestone-info`
  관련 마크업이 전혀 없다(grep 0건) — 애초에 마일스톤 필터 자체가 이 화면에 없는 것으로
  보인다(별도 확인 필요, 아래 참고).

## 참고

- `milestone/partial_status.html` 프래그먼트 자체(`th:fragment="status(milestone, project)"`)와
  `TemplateHelper.getMilestoneProgress(milestone)` 헬퍼는 TASK-0253에서 이미 만들어져 있다 —
  project/home 사이드바에서 재사용 중이므로, 이번 작업은 그걸 이슈 목록 두 화면에 추가로
  배선하기만 하면 된다(새 백엔드 로직 불필요할 가능성이 높음).
- `issue/my_partial_search.html`에 애초에 마일스톤 필터 UI 자체가 있는지부터 확인이 필요하다
  (없다면 이건 별도의 더 큰 범위 — "내 이슈 화면에 마일스톤 필터 자체가 없음" — 일 수 있다).

## 제안

1. `issue/list.html`의 마일스톤 select 드롭다운 바로 아래에, `milestoneId`가 선택된 상태일 때
   `milestone/partial_status :: status(milestone, project)`를 조건부로 삽입한다(컨트롤러가
   선택된 마일스톤 엔티티를 모델에 담아 넘기도록 배선 필요 — `IssueViewController`의 이슈
   목록 액션 확인).
2. `issue/my_partial_search.html`에 마일스톤 필터 UI 자체가 있는지 먼저 확인하고, 있다면
   동일하게 배선한다.
3. `docs/TEMPLATE_BACKLOG.md` #153의 "제외 결정" 서술을 정정한다(잘못된 판단이었음을 기록).
4. TDD로 "마일스톤으로 필터링한 이슈 목록에 진행률 카드가 보인다" 회귀 스펙을 먼저 세울 것.

본 티켓은 순수 조사 산출물이며 구현은 하지 않았다.
