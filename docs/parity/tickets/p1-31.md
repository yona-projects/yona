## 완료 로그 (원문, `PARITY_BACKLOG.md`의 "완료 로그" 섹션에서 이관)

- **2026-08-20 — P1-31**: 메일 처리가 거부되거나(권한 없음/형식 오류) 발신자가 도움말을 요청해도 로그에만 남고 발신자에게는 아무 회신도 가지 않던 문제 수정(yona `EmailHandler.getHelpMessage()`/`reply()` 대응).
  - `MailService`에 `sendReply(toEmail, toName, subject, textContent, inReplyToMessageId)` 신규 추가 — `Reply-To`([[tickets/p1-28|P1-28]], 미래 답장의 수신처)와는 다른 개념으로, `In-Reply-To`/`References` 헤더를 원본 메일의 Message-ID로 설정해 메일 클라이언트가 이 회신을 원본 스레드에 바로 묶어서 보여주게 한다(yona `reply()`와 동일). 제목은 원본이 이미 "Re:"로 시작하지 않으면 붙여준다. 발송 자체가 실패해도(SMTP 오류 등) 예외를 전파하지 않고 로그만 남긴다 — yona `reply()`도 실패를 삼키고 경고만 남기는 것과 동일(회신 발송 실패가 메일 처리 전체를 실패시키면 안 되므로).
  - `IncomingMailProcessingService.processTarget()`에 yona `getProjects()`의 `detail=="help"` 분기 대응 — 수신 주소의 plus-address detail이 정확히 "help"(대소문자 무시)면 프로젝트/이슈 처리를 하지 않고 사용법 안내 메일만 회신하고 `IncomingMailOutcome.HelpRequested`를 반환한다.
  - `process()`에 yona `handle()`의 "errors.size() > 0이면 회신" 분기 대응 — 한 메일이 여러 수신 대상(프로젝트)에 걸쳐 처리될 때, 그중 하나라도 `Rejected`(권한 없음, 프로젝트 없음, 형식 오류 등)면 그 사유들을 모아 도움말과 함께 한 통으로 회신한다(성공한 대상이 있어도 실패 사유는 별도로 알려준다 — yona와 동일).
  - i18n 메시지 번들(yona `Messages.get("viaEmail.help.*")`)은 이식하지 않고 이 저장소의 다른 사용자 안내문과 같은 기조로 한국어 고정 문구로 단순화.
  - 테스트: `IncomingMailProcessingServiceSpec.kt` +3(help detail로 도움말 회신 및 다른 처리 생략 확인, Rejected 발생 시 사유가 포함된 회신 확인, 정상 처리 시 회신 없음 확인) — 기존 14건 포함 총 17 tests.
  - 검증: `./gradlew test --tests "com.github.yonaprojects.yona.domain.mail.*" --tests "YonaApplicationTests"` 전체 통과, `./gradlew compileKotlin compileTestKotlin` 전체 컴파일 성공.
