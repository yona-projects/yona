## 완료 로그 (원문, `PARITY_BACKLOG.md`의 "완료 로그" 섹션에서 이관)

- **2026-08-21 — P0-21**: 조직 REST API(`OrganizationController.kt`)의 `isOrgAdmin()`에 사이트매니저 전역 우회 추가.
  - Serena LSP로 yona `AccessControl.java:119-203 isGlobalResourceAllowed()`의 ORGANIZATION 케이스(`user.isSiteManager() || isOrganizationAdmin`)를 재확인 — yona `config/security/AccessControl.kt`의 `isAllowed(user, organization, operation)` 오버로드([[tickets/p1-85|P1-85]] 1b에서 이미 구현)는 이 규칙을 정확히 갖고 있었지만, REST 컨트롤러 `OrganizationController.kt`는 이를 재사용하지 않고 독자적인 `private fun isOrgAdmin(orgId, userId)` 헬퍼로 ORG_ADMIN 역할만 검사하고 있어 사이트매니저가 5개 엔드포인트(설정변경/멤버추가/역할변경/멤버제거/조직삭제) 전부에서 403을 받는 회귀였음을 확인.
  - `isOrgAdmin()`에 `userRepository.findById(userId).map { it.isSiteManager }` 우회 분기를 최상단에 추가(ORG_ADMIN 역할 검사보다 먼저 평가) — 시그니처(ID 기반)는 유지해 5개 호출부 전부 수정 없이 자동으로 적용됨.
  - [[tickets/p2-16|P2-16]]의 "ORGANIZATION은 yona와 일치해 문제없음" 종결 판정을 재검토 — 해당 조사는 웹 화면(`OrganizationViewController.kt`)만 대조했고 REST API는 대조 대상에서 누락돼 있었음을 확인, 판정을 "웹 화면 한정"으로 정정(코드 재작업 없음, 문서 정정만).
  - 테스트: `OrganizationControllerSpec.kt`(신규) — 사이트매니저(조직관리자 아님)의 설정변경/조직삭제 허용 2건, 조직관리자도 사이트매니저도 아닌 사용자의 403 1건, 조직관리자(사이트매니저 아님)의 정상 동작 회귀 확인 1건(총 4건).
  - 검증: `./gradlew test --tests "...OrganizationControllerSpec"` 전체 통과, 이어서 `./gradlew test` 전체 통과(회귀 없음 확인).
