- **상태(원본 체크박스)**: `[x]`

- **yona 대상**: `domain/notification/NotificationMailDigestScheduler.kt`, `domain/mail/MailServiceImpl.kt`
- **비고(원문)**: **완료** — 당시 대상이던 `NotificationMailEventListener.kt`는 [[tickets/p1-27|P1-27]]에서 삭제됨. Reply-To 로직은 살아있고 오히려 프로젝트 단위→리소스 상세 단위로 개선됐으나 위치가 이동함(2026-08-20 코드 대조 검증에서 확인, 표를 최신 경로로 갱신)

## 완료 로그 (원문, `PARITY_BACKLOG.md`의 "완료 로그" 섹션에서 이관)

- **2026-08-20 — P1-28**: 알림 메일에 IMAP 답장용 `Reply-To` 헤더가 전혀 없어, 알림 메일을 받은 사용자가 그냥 답장을 보내도 IMAP 수신 처리([[tickets/p0-02|P0-02]])가 아예 받을 수조차 없던 문제 수정(yona `NotificationMail.getReplyTo()` 대응).
  - `MailService`에 `sendHtmlMailWithReplyTo(toEmail, toName, subject, htmlContent, replyTo)` 신규 메서드 추가(기존 `sendHtmlMail(toEmail, toName, subject, htmlContent)`와 파라미터 개수만 다르면 JVM 시그니처가 충돌해 이름을 분리함). `MailServiceImpl`은 `replyTo`가 있으면 `MimeMessageHelper.setReplyTo()`로 헤더를 붙인다.
  - `NotificationMailEventListener`가 이제 이벤트의 `resourceType`/`resourceId`로 리소스를 재조회([[tickets/p0-03|P0-03]]의 `WebhookNotificationEventListener.resolveResource()`와 동일한 패턴, 신규로 `IssueRepository`/`PostingRepository`/`IssueCommentRepository`/`PostingCommentRepository` 주입)해 그 프로젝트의 `owner/name`을 detail로 담은 plus-address(`EmailAddressDetail`, [[tickets/p0-02|P0-02]]에서 이미 이식됨)를 `Reply-To`로 설정.
  - **발견 후 별도 등록, 이후 해소**: 당시 yona의 IMAP 수신 처리(`IncomingMailProcessingService`)가 `owner/project`까지만 detail을 해석해, 이번 구현도 detail을 `owner/project`까지만 채워 정확한 스레드 연결 없이("프로젝트에 새 이슈로 생성") 답장을 받았다([[tickets/p0-02|P0-02]]에서 식별, **[[tickets/p1-32|P1-32]]로 별도 등록**). [[tickets/p1-32|P1-32]]가 `owner/project/<resourceType>/<resourceId>` 전체 경로 파싱을 지원하도록 완료되며, Reply-To 생성 쪽(`NotificationMailDigestScheduler.getReplyTo()`)도 함께 리소스 상세 경로까지 채우도록 갱신돼 정확한 스레드 연결까지 완료됨(`[x]`). 커밋([[tickets/p1-25|P1-25]]와 동일한 이유로 DB 엔티티가 아님) 리소스 타입은 여전히 Reply-To를 만들지 않고 조용히 스킵.
  - 테스트: `NotificationMailEventListenerSpec.kt` +3(ISSUE_POST 리소스면 정확한 plus-address 설정 확인, IMAP 주소 미설정 시 Reply-To 없음, 리소스 조회 실패 시 Reply-To 없음) — 기존 6건은 신규 리포지토리 의존성 주입에 맞춰 생성자 호출과 `sendHtmlMail`→`sendHtmlMailWithReplyTo` 목 검증 구문만 갱신(동작 자체는 변경 없음, `replyTo` 값은 `any()`로 완화). 총 9 tests. `com.github.yonaprojects.yona.domain.mail.*`/`PasswordResetControllerSpec`/`SiteApiControllerSpec`/`ProjectViewControllerSpec`/`UserServiceSpec`/`YonaApplicationTests`(다른 `sendHtmlMail` 호출부들) 재실행으로 회귀 없음 확인.
  - 검증: `./gradlew test --tests "com.github.yonaprojects.yona.domain.notification.*" --tests "com.github.yonaprojects.yona.domain.mail.*" --tests "PasswordResetControllerSpec" --tests "SiteApiControllerSpec" --tests "ProjectViewControllerSpec" --tests "UserServiceSpec" --tests "YonaApplicationTests"` 전체 통과, `./gradlew compileKotlin compileTestKotlin` 전체 컴파일 성공.
