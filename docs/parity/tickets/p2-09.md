## 완료 로그 (원문, `PARITY_BACKLOG.md`의 "완료 로그" 섹션에서 이관)

- **2026-08-20 — P2-09**: git 프로토콜(clone/fetch/push)로만 접근하는 사용자도 "최근 방문 프로젝트"에 기록되도록 이식.
  - `RecentProjectRepository.kt`에 `recordVisit(user, project)` 공용 default 메서드 신규 — 기존에 `ProjectViewController.addVisitHistory()`에 사설로 중복돼 있던 로직(기존 기록 삭제 → 새로 저장 → 30건 초과 시 가장 오래된 것부터 정리)을 저장소 계층으로 승격해 웹/git 양쪽에서 공유. `ProjectViewController`는 이 메서드를 호출하는 얇은 래퍼로 축소.
  - **부수적으로 발견·수정한 버그**: `deleteByUserIdAndProjectId()`(삭제)와 뒤이은 `save()`(삽입)를 같은 트랜잭션 안에서 flush 없이 연달아 호출하면 `(user_id, project_id)` unique 제약 위반이 발생하고, 이게 기존 코드의 광범위한 `try/catch(Exception)`에 조용히 삼켜지면서 Hibernate 세션이 손상돼(널 식별자 엔티티 잔존) 이후 쿼리에서 `AssertionFailure`로 터짐 — 같은 (user, project) 쌍을 한 트랜잭션 안에서 두 번 방문 기록하는 케이스가 지금까지 한 번도 테스트/실행되지 않아 드러나지 않았던 기존 결함. `deleteByUserIdAndProjectId()` 직후 `flush()`를 명시적으로 호출해 해결.
  - `config/git/GitProjectVisitRecorder.kt` 신규 — yona `GitApp.java:88-137 service()`의 `user.visits(project)` 호출 지점 대응. **advertise 단계(GET .../info/refs)가 아니라 실제 RPC 처리 단계(POST git-upload-pack/git-receive-pack)에서만** 방문을 기록하는 yona의 분기를 그대로 재현(`GitAuthorizationFilter`와 동일한 URI 정규식 재사용, 익명 사용자는 기록 안 함).
  - `config/GitServletConfig.kt`의 git 서블릿 디스패처에 `gitProjectVisitRecorder.recordIfApplicable(req)`를 실제 서비스 위임 직전에 배선.
  - 테스트: `RecentProjectRepositorySpec.kt` 신규 3건(최초 방문 기록/재방문 시 중복 없이 갱신/30건 초과 시 최오래 기록 정리), `GitProjectVisitRecorderSpec.kt` 신규 5건(clone RPC 기록/push RPC 기록/advertise 단계 미기록/익명 미기록/미존재 프로젝트 미기록), 기존 `ProjectViewControllerSpec.kt`에 `recentProjectRepository.recordVisit` 스텁 추가(기존엔 개별 메서드 미스텁으로 내부 try/catch가 조용히 삼키던 것이 default 메서드 자체 미스텁 시 MockK 예외로 드러남 — 실제 결함이 아니라 default 인터페이스 메서드는 MockK가 자동으로 호출-through 하지 않기 때문).
  - 검증: `./gradlew test --tests "...RecentProjectRepositorySpec" --tests "...ProjectViewControllerSpec" --tests "...GitProjectVisitRecorderSpec"` 전체 통과.
