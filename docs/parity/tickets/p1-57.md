## 완료 로그 (원문, `PARITY_BACKLOG.md`의 "완료 로그" 섹션에서 이관)

- **2026-08-20 — P1-57**: 조직 그룹멤버 읽기/일부 쓰기 권한(`AccessControl.isAllowedIfGroupMember()`)을 저장소 전체 컨트롤러에 이식.
  - `config/security/AccessControl.kt`의 `isAllowedIfGroupMember(project, user)`(기존에 `isAllowedToReadProject`/`isProjectResourceCreatable` 내부에서만 쓰이던 `private` 함수)를 컨트롤러들이 직접 호출할 수 있도록 공개.
  - 같은 `existsByProjectIdAndUserId(...)`(직접 멤버 여부) 단일 조건에 의존하던 21개 컨트롤러 파일의 `checkReadPermission`/`checkWritePermission`류 및 인라인 권한 체크 전부에 `|| AccessControl.isAllowedIfGroupMember(project, user)`를 추가: `BoardController`/`CommentController`/`IssueController`/`IssueLabelController`/`MentionController`/`MilestoneController`/`ProjectController`/`PullRequestController`/`VoteController`(named-helper 패턴, 직접 처리) + `BoardViewController`/`BranchApiController`/`BranchViewController`/`CodeViewController`/`CompareViewController`/`IssueViewController`/`MilestoneViewController`/`ProjectMemberController`/`ProjectViewController`/`PullRequestViewController`/`ReviewThreadController`/`StatisticsViewController`(인라인 중복 패턴, fork 위임 후 diff 검증) — yona `AccessControl.java`가 READ/UPDATE/ACCEPT/CLOSE/REOPEN/WATCH에는 이 규칙을 적용하고 DELETE에는 적용하지 않는 것과 동일하게, DELETE 전용 엔드포인트(`BranchApiController.deleteBranch`, `MilestoneViewController.deleteMilestone`)와 그 뒤에 별도 MANAGER 전용 체크가 이어져 group-member OR을 더해도 결과가 바뀌지 않는 설정 페이지(`ProjectViewController.projectSetting`/`projectChangeVCSForm`)는 의도적으로 제외.
  - 테스트: 12개 파일에 그룹멤버 접근 허용 회귀 테스트 1개씩(신규 `ProjectMemberControllerSpec.kt` 포함 — 기존에 스펙 파일 자체가 없었음) — 조직에는 속하지만 프로젝트 직접 멤버는 아닌 사용자가 PROTECTED 프로젝트 리소스에 접근 가능한지 확인.
  - 검증: `./gradlew compileKotlin compileTestKotlin` 전체 컴파일 성공, `./gradlew test` 783 tests(기존 대비 +13) — `DataBackupServiceIntegrationSpec` 1건만 실패(이 세션에 이미 여러 번 기록된 환경 이슈, 무관).
