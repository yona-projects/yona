## 완료 로그 (원문, `PARITY_BACKLOG.md`의 "완료 로그" 섹션에서 이관)

- **2026-08-21 — P1-132**: `WebhookServiceImpl.buildTextMessage()`가 만드는 모든 이벤트 텍스트 메시지에 yona `Webhook.buildRequestMessage()`(Slack 링크 문법 `" <url|text>"`) 대응 리소스 링크를 붙임.
  - 새 private `buildResourceLink(webhook, resource)`를 추가해 Issue/Posting/PullRequest는 "#번호: 제목"을, IssueComment/PostingComment/ReviewComment는 yona와 동일하게 댓글 자신이 아니라 부모 리소스(`Webhook.java:372` `eventComment.getParent()`, `:498` `eventPullRequest`)의 "#번호: 제목"을 링크 텍스트로 사용. URL은 새로 계산하지 않고 알림메일 경로가 이미 쓰는 `NotificationUrlResolver.getUrl(resourceType, resourceId)`를 재사용(기존 `getResourceType`/`getResourceId` 헬퍼와 조합) — `WebhookServiceImpl` 생성자에 `NotificationUrlResolver` 의존성 추가.
  - `DETAIL_SLACK` 타입만 링크 텍스트의 `>`를 `&gt;`로 이스케이프(yona `Webhook.java:185-189`와 동일 — Slack 링크 문법이 `>`로 닫히므로). URL 리졸브에 실패하면(리소스가 이미 삭제된 경우 등) 링크 없이 본문 텍스트만 반환하도록 graceful degradation.
  - PushedCommits(push 이벤트)는 yona도 `buildRequestMessage()`를 쓰지 않는 별도 경로(`Webhook.java:668` `buildRequestBody(commits, refNames, sender, title)`)라 그대로 링크 없이 유지. CommitComment는 yona `Webhook.java`에 대응하는 오버로드 자체가 없는 yona 전용 리소스라 기존 "의견: 내용" 텍스트는 유지하되, 링크 자체는 (URL이 계산 가능하므로) 함께 붙도록 통일.
  - 테스트: `WebhookServiceSpec.kt` +4(SIMPLE 웹훅 이슈 링크, DETAIL_SLACK `>` 이스케이프, 이슈 댓글이 부모 이슈 정보로 링크되는지, URL 리졸브 실패 시 링크 없이 본문만 반환). 기존 11건도 `NotificationUrlResolver` mock 주입(relaxed) 후 전체 통과.
