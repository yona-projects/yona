- **상태(원본 체크박스)**: `[x]`
- **yona 근거**: `app/controllers/IssueApp.java:267-269 issue()`(`if (issueInfo.isDraft && !issueInfo.authorLoginId.equals(UserApp.currentUser().loginId)) return forbidden(...)` — `AccessControl.isAllowed()`보다 먼저 실행되는 별도 체크. 즉 프로젝트 멤버여도 작성자 본인이 아니면 초안은 못 봄)

## 완료 로그 (원문, `PARITY_BACKLOG.md`의 "완료 로그" 섹션에서 이관)

- **2026-08-21 — P1-84**: 초안(draft) 이슈를 작성자 본인만 조회할 수 있도록 게이트 추가.
  - Serena LSP로 yona `IssueApp.java:267-269 issue()`를 재확인 — `AccessControl.isAllowed()` 호출보다 먼저 실행되는 독립적인 draft 전용 체크(`issueInfo.isDraft && !issueInfo.authorLoginId.equals(UserApp.currentUser().loginId)`)임을 확인.
  - `IssueController.kt getIssue()`에 동일한 순서(권한 판단 이전)로 게이트 추가: `issue.isDraft && (user == null || issue.authorLoginId != user.loginId)`면 403. 익명 사용자는 `user == null`로 자동 처리되어 yona의 "익명 loginId가 authorLoginId와 절대 같을 수 없어 자동 차단"과 동일한 관찰 가능 결과.
  - 테스트: `IssueControllerSpec.kt` +2(작성자 아닌 프로젝트 멤버가 초안 조회 시 403 / 작성자 본인은 비멤버여도 조회 가능). 테스트 작성 중 `Issue.isDraft`가 `state`와 별개 필드임을 놓쳐 `state = State.DRAFT`만 설정하고 `isDraft = true`를 빠뜨려 red가 안 되는 실수를 자체 발견/수정.
  - 검증: `./gradlew test --tests "...IssueControllerSpec"` 28 tests 전체 통과.
