# P3-60: 이슈/게시글 댓글 본문의 마크다운 작업목록(tasklist) 체크박스에 진행률 바가 없고,
`data-allowed-update` 속성도 빠져 있어 권한 없는 사용자도 체크박스를 조작할 수 있는 상태로
보임

## 배경

`docs/TEMPLATE_BACKLOG.md` #35(`common/tasklistBar.scala.html`)는 TASK-0229에서 "`.tasklist`
셸 마크업과 스크립트 로드가 두 페이지(issue/view, board/view) 모두에 전혀 없어 죽어있던
기능"을 복구했다고 기록하지만, **이슈/게시글 "본문"에만 복구됐고 "댓글" 각각에도 legacy가
동일하게 tasklistBar를 넣는다는 사실은 다루지 않았다**.

legacy는 본문뿐 아니라 댓글 하나하나에도 체크박스 진행률 바를 넣는다:

```scala
// legacy-yona/app/views/issue/partial_comment.scala.html:108-113
<div id="comment-body-@comment.id">
    @common.tasklistBar()
    <div class="comment-body markdown-wrap" data-allowed-update="@isAllowedUpdate" data-via-email="@OriginalEmail.exists(comment.asResource)">@Html(Markdown.render(comment.contents, project))</div>
    <div class="attachments pull-left" data-attachments="@toJson(AttachmentApp.getFileList(ResourceType.ISSUE_COMMENT.toString(), comment.id.toString()))"></div>
</div>
```

```scala
// legacy-yona/app/views/board/partial_comments.scala.html:67-70
<div id="comment-body-@comment.id">
    @common.tasklistBar()
    <div class="comment-body markdown-wrap" data-via-email="@OriginalEmail.exists(comment.asResource)" data-allowed-update="@isAllowedUpdate" >@Html(Markdown.render(comment.contents, project))</div>
    <div class="attachments" data-attachments="@toJson(AttachmentApp.getFileList(ResourceType.NONISSUE_COMMENT.toString(), comment.id.toString()))"></div>
</div>
```

`common/tasklistBar.scala.html` 본체:

```scala
<div class="tasklist">
    <div class="task-title">Tasks<span class="done-counter"></span></div>
    <div class="task-progress">
        <div class="bar red" style="width: 0;" title="Tasklist"></div>
    </div>
</div>
```

## 현재 yona 상태 (격차 확정)

`src/main/resources/templates/issue/view.html:264-265`:
```html
<div th:id="'comment-body-' + ${comment.id}">
    <div class="content markdown-wrap" th:utext="${markdownService.render(comment.contents, true, project)}">댓글내용</div>
```

`src/main/resources/templates/board/view.html:123-124`도 동일 패턴 — `.tasklist` 셸이
댓글 쪽엔 없고(본문 쪽엔 있음, 70행/56행 각각), `data-allowed-update` 속성도 댓글
`markdown-wrap`엔 없다(본문 `markdown-wrap`엔 `th:data-allowed-update="${isAllowedUpdate}"`가
있음 — issue/view.html:76, board/view.html:62).

`static/javascripts/common/yona.Tasklist.js`(9~15행, 95~114행)를 읽어보면 이 스크립트는
`$(".markdown-wrap")` **전체**(본문+모든 댓글 포함)를 순회하며 각 요소에 대해
`$tasklist = $this.prev()`로 "바로 앞 형제 요소가 `.tasklist`"라고 가정하고 진행률
바(`.done-counter`/`.bar`/`.task-title`)를 갱신하며, `disableCheckboxIfNeeds`도
`$this.data("allowedUpdate")`를 개별 markdown-wrap마다 확인해 체크박스를 비활성화한다.
즉 이 스크립트는 애초에 "모든 markdown-wrap(본문+댓글)이 각자 자기 tasklist 셸과
allowed-update 속성을 갖는다"는 legacy 구조를 전제로 짜여 있는데, yona는 본문에만 그 구조를
채워 넣었다.

결과적으로:
1. 댓글에 마크다운 체크리스트(`- [ ] foo`)를 쓴 사용자는 **진행률 바가 아예 안 보인다**
   (`$this.prev()`가 엉뚱한 형제 요소 — 댓글이면 보통 수정폼 관련 div — 를 가리키게 되어
   `.find(".bar")` 등이 빈 셀렉션이 되고 조용히 아무 일도 안 일어남).
2. **`data-allowed-update`가 없어 `disableCheckboxIfNeeds`가 댓글의 체크박스를 절대
   비활성화하지 못한다** — 즉 수정 권한이 없는 사용자도 댓글 안의 체크박스를 클릭할 수 있는
   상태로 남는다(클릭 시 PATCH 요청까지 나갈지는 `$this.closest("div[id]").prev().find("form")`
   탐색 경로가 댓글 구조에서 어떤 엘리먼트를 찾는지에 달려 있어 추가 확인 필요 — 최소한
   "막혀야 할 UI가 안 막힌다"는 점은 확정).

## 제안

- `issue/view.html`의 댓글 렌더링 블록(264행 부근)과 `board/view.html`의 동일 블록(123행
  부근)에 각각 `.tasklist` 셸(본문에 이미 있는 것과 동일 마크업)을 `markdown-wrap` 바로 앞에
  추가한다.
- 댓글 `markdown-wrap`에 `th:data-allowed-update="${isAllowedUpdate}"`(또는 댓글별 권한 변수 —
  본문과 동일 변수를 쓰는 게 맞는지, 아니면 댓글별로 별도 권한 계산이 필요한지 legacy의
  `isAllowedUpdate` 스코프를 확인할 것)를 추가한다.
- TDD로 "댓글 markdown-wrap 앞에 .tasklist가 있다" / "권한 없는 사용자의 댓글 markdown-wrap엔
  data-allowed-update=false가 붙어 체크박스가 비활성화된다" 회귀 스펙을 먼저 추가한다.
- 체크박스 클릭 시 PATCH 흐름(`$this.closest("div[id]").prev().find("form")`)이 댓글 구조에서
  실제로 올바른 폼(`common/commentUpdateForm` 대응)을 찾는지도 Playwright 등으로 실측 확인할
  것(이 티켓 조사 범위에선 정적 코드 대조까지만 완료, 런타임 동작은 미확인 — "확실치 않음").

본 티켓은 순수 조사 산출물이며 구현은 하지 않았다.

## 완료 로그 (2026-09-12)

TDD로 구현 완료. 신규 회귀 스펙
`src/test/kotlin/com/github/yonaprojects/yona/web/CommentTasklistProgressBarTemplateRenderingSpec.kt`
(5개 케이스)를 먼저 추가해 RED(5/5 실패)를 확인한 뒤 구현했다.

- `issue/view.html`/`board/view.html`의 댓글 렌더링 블록(`#comment-body-{id}`)에 본문과 동일한
  `.tasklist` 셸을 `markdown-wrap` 바로 앞에 추가하고, `th:data-allowed-update="${canEditThisComment}"`를
  배선했다(`canEditThisComment`는 이미 같은 블록 스코프에 있던 "작성자 본인 또는 매니저" 변수 —
  commentUpdateForm에 이미 쓰이던 것과 동일).
- **체크박스 클릭 시 PATCH 흐름 실측 확인 중 추가로 발견한 실제 버그**: `yona.Tasklist.js`는
  체크박스를 클릭하면 `$this.closest("div[id]").prev().find("form")`로 찾은 폼의 `action`
  속성으로 PATCH를 보내는데, `common/commentUpdateForm.html`의 `<form>`에는 애초에 `action`
  속성 자체가 없었다(REST API 호출용 `data-api-base`만 있었음) — 댓글의 `.tasklist` 셸을
  추가하는 것만으로는 체크박스 클릭이 실제로 아무 데도 요청을 보내지 못하는 상태였다. 조사해보니
  legacy 호환 엔드포인트(`CommentController.updateIssueCommentLegacyPath`/
  `updatePostingCommentLegacyPath`, PUT+PATCH 모두 허용, `{content, original}` 필드명 —
  `yona.Tasklist.js`가 보내는 페이로드와 정확히 일치)가 이미 구현돼 있었으나 어떤 템플릿도 이
  경로로 폼 action을 연결하고 있지 않았다. `commentUpdateForm.html`에 `contentPatchUrl` 파라미터를
  추가하고 호출부(issue/view.html: `/{owner}/{projectName}/issue/{number}/comments/{commentId}`,
  board/view.html: `/{owner}/{projectName}/post/{number}/comment/{commentId}`, legacy와 동일하게
  post 쪽만 단수 "comment")가 각자 계산해 넘기도록 배선했다.
- TDD 스펙에 위 두 URL이 정확한지도 함께 검증(action 속성 값 assertion).

**Playwright 실측 검증(1회, 이슈+게시글 양쪽 모두)**: 기존 dev 서버(재사용)에서 실제 로그인
세션으로 체크리스트 댓글을 작성 → `.tasklist` 셸/체크박스 렌더링 확인 → 체크박스 실제 클릭 →
PATCH 요청이 정확히 `.../issue/1/comments/{id}`(이슈)와 `.../post/1/comment/{id}`(게시글)로
나가 200 응답을 받음을 네트워크 레벨에서 확인 → 페이지 새로고침 후에도 체크 상태가 유지됨
(서버에 실제로 저장됨)을 확인했다 — 티켓이 "확실치 않음"으로 남겨뒀던 부분을 정확히
검증했고, 실제로 깨져 있던 부분(commentUpdateForm의 action 누락)을 발견해 함께 고쳤다.
