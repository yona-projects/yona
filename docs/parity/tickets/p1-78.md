## 완료 로그 (원문, `PARITY_BACKLOG.md`의 "완료 로그" 섹션에서 이관)

- **2026-08-20 — P1-78**: PR 리뷰어 추가/제거의 인가 우회(프로젝트 비멤버도 임의 PR 리뷰어 조작 가능) 수정.
  - yona `AccessControl.java:288-291`을 확인한 결과 PULL_REQUEST의 `Operation.ACCEPT`는 `user.isMemberOf(project) || isAllowedIfGroupMember(project, user)` — MANAGER 같은 상위 권한이 아니라 yona의 기존 `checkWritePermission` 패턴과 정확히 동일한 규칙이었다.
  - `PullRequestController.addReviewer()`/`removeReviewer()`: `checkReadPermission`(PUBLIC이면 비멤버도 통과)을 `checkWritePermission`(멤버십 필수)으로 교체.
  - `ReviewApiController.review()`/`unreview()`: 로그인 확인만 있던 곳에 `ProjectUserRepository` 신규 주입 + `checkWritePermission` 헬퍼(`PullRequestController`와 동일 패턴) 추가, 실패 시 `"error/403"` 반환.
  - 테스트: `PullRequestControllerSpec.kt` +2(PUBLIC 프로젝트여도 비멤버는 리뷰어 등록/해제 불가), `ReviewApiControllerSpec.kt` +2(동일 시나리오). 기존 통과 테스트들은 이미 멤버십 스텁이 있어 `checkWritePermission`으로 바뀌어도 그대로 통과(추가로 `ReviewApiControllerSpec`의 기존 2개 테스트에 `existsByProjectIdAndUserId` 스텁 보강).
  - 검증: `./gradlew compileKotlin compileTestKotlin`, `PullRequestControllerSpec` 15 tests, `ReviewApiControllerSpec` 8 tests 모두 통과.
