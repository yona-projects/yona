## 완료 로그 (원문, `PARITY_BACKLOG.md`의 "완료 로그" 섹션에서 이관)

- **2026-08-21 — P1-137(마무리)**: 사용자 요청으로 P1-137의 2번 항목(hostname 체크)을 추가 조사해 마무리하고 항목 전체를 완료 처리.
  - yona `Config.java:26-39`의 체크는 Play `application.port`+`application.hostname` 두 설정을 조합해 URL을 만드는 `Config.getHostport()`가 있어야만 의미가 있는 Play 전용 함정(port만 설정하고 hostname을 빠뜨리면 port가 통째로 무시됨)이라, 이 두 필드 조합 구조 자체가 없는 yona에는 문자 그대로 이식할 대상이 없음을 확인.
  - 다만 yona가 이 체크로 막으려던 실제 문제("설정을 반쯤만 채워 절대 URL이 깨지는 것")는 yona에서도 다른 형태로 발생한다 — yona는 hostname/port 조합 대신 `yona.base-url` 단일 설정 하나로 웹훅/알림메일의 모든 절대 URL을 만드는데(`WebhookServiceImpl`/`NotificationUrlResolver`/`NotificationMailRenderer`/`NotificationMailBodyProcessor` 4곳에서 재사용), 이 값이 비어있으면 네 곳 전부에서 링크가 상대경로로 깨진다. yona 체크의 문자 그대로의 재현이 아니라 같은 문제(URL 생성 오설정)를 yona의 실제 설정 구조에 맞게 옮긴 것 — `DiagnosticService`에 `@Value("\${yona.base-url:}")`를 추가로 주입하고 `checkAll()`에 "yona.base-url이 비어있으면 경고" 체크를 신설.
  - 별개로 `Property.java`(3번, 중복설정 체크)는 지난 커밋에서 이미 조사·판정 완료(yona `Property` 엔티티가 `name` 컬럼에 DB 유니크 제약을 걸어놔서 이식 불필요, 그대로 유지).
  - 테스트: `DiagnosticServiceSpec.kt`(신규) 4건(base-url 공백/설정됨 각 1건, IMAP 폴러 비정상/빈 부재 각 1건). 전체 통과.

- **2026-08-21 — P1-137(부분)**: `DiagnosticService`의 진단 체크 3종이 yona 원본(메일수신/hostname/중복설정)과 전혀 다른 것으로 대체돼 있던 것 중 1)메일수신(IMAP idle-thread 헬스체크)만 이번에 이식.
  - `ImapMailboxPoller`에 `healthCheckMessage(): String?` 신설 — yona `MailboxService.java:177-188` `checkOne()`과 동일하게 `idleThread == null`이면 "미초기화", `!isAlive`면 "미실행" 메시지, 정상이면 null 반환. `DiagnosticService`에 `imapMailboxPoller: ImapMailboxPoller? = null`(조건부 빈이라 null 허용, 기존 `mailSender` 패턴과 동일) 주입 후 `checkAll()`에 연결.
  - 나머지 2종은 조사 결과: hostname 체크(yona `Config.java`)는 Play `application.port`/`application.hostname` 전용 함정이라 Spring Boot 이식 여부를 별도 판단해야 해 다음 세션으로 미룸. 중복설정 체크(yona `Property.java`)는 yona `Property` 엔티티가 이미 `name` 컬럼에 DB 유니크 제약을 걸어놔서 애초에 중복이 발생할 수 없어 — 이식 대상에서 제외(발생 불가능한 조건의 체크를 추가하는 건 무의미).
  - 테스트: `ImapMailboxPollerSpec.kt` +1(`start()` 호출 전 idleThread 미초기화 상태에서 올바른 메시지 반환). 전체 통과.

- **2026-08-21 — 긴급 수정: `DiagnosticService`의 `@Service` 어노테이션 유실 복구**: P1-137 작업 중 Serena `replace_symbol_body`로 `DiagnosticService` 클래스 전체를 교체하면서 `body` 파라미터에 기존 `@Service` 어노테이션을 포함하지 않아, 그 어노테이션이 통째로 사라졌던 것을 확인·복구.
