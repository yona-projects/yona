# P3-26: `/api/{owner}/{projectName}/pushedBranches` 응답이 순환 참조로 부풀고 비밀번호 해시까지 노출됨

## 배경

P3-22(Mercurial push 알림/웹훅/PushedBranch) 실사용 검증 중 발견. `ProjectController.
getPushedBranches()`가 `PushedBranch` 엔티티 목록을 DTO 변환 없이 그대로
`ResponseEntity.ok(branches)`로 반환하고 있었다 — `PushedBranch.project`→
`Project.projectUsers`→`ProjectUser.user`→`User.projectUsers`→... 양방향 관계가 Jackson
직렬화 시 끝없이 순환 참조되어 응답이 수십 KB로 부풀 뿐 아니라, **`User.password`/
`passwordSalt`(해시된 값이지만)까지 그대로 API 응답에 노출**되는 정보 노출 문제였다.
Git 프로젝트로도 동일하게 재현되는 것을 확인해 **VCS와 무관한 순수 기존 결함**임을
확정했다(이번 P3-2x 작업의 부산물이 아니라 원래부터 있던 버그).

## 완료 로그

**(2026-09-09) 발견 즉시 수정.** `ProjectController.kt`에 `PushedBranchDto(id, name,
pushedDate)`를 신설해 엔티티 대신 이 DTO로 응답하도록 수정 — 순환 참조/비밀번호 노출
둘 다 해소. 기존 테스트(`ProjectControllerSpec`의 `jsonPath("$[0].name")` 검증)는 필드명이
그대로 유지돼 회귀 없이 통과.

실사용 재검증: 실제 앱 기동 후 `GET /api/admin/hgpush1/pushedBranches` 호출 —
수정 전: 58.7KB, 비밀번호 해시 노출. 수정 후: `[{"id":1,"name":"protected-branch",
"pushedDate":"..."},{"id":2,"name":"open-branch","pushedDate":"..."}]`(정상, 순환 없음).
