- **2026-08-20 — P1-70**: 이슈 이동 시 `ISSUE_MOVED`가 이슈 타임라인(`IssueEvent`)에 기록되지 않던 문제 수정.
  - `IssueServiceImpl.publishIssueMovedNotification()`에서 `NotificationEvent`를 만든 직후, 동일한 `oldValue`/`newValue`(`"{owner}/{name}"` 쌍)로 `recordIssueEvent(issue, EventType.ISSUE_MOVED, mover.loginId!!, oldValue, newValue)`를 호출하도록 추가(yona `IssueEvent.addFromNotificationEvent(notiEvent, originalIssue, loginId)` 대응 — 알림과 타임라인 기록을 한 함수 안에서 함께 처리하는 것도 yona `addIssueMovedNotification()`과 동일한 구조).
  - `skipWaypoint` 기본값(true)을 그대로 사용 — yona `addFromNotificationEvent()`가 draft-time 병합/취소가 적용되는 `add()`(`addWithoutSkipEvent()`가 아님) 경로를 타는 것과 일치.
  - 테스트: `IssueServiceSpec.kt` +1(이동 후 `issueEventRepository`에서 `ISSUE_MOVED` 이벤트를 조회해 oldValue/newValue/senderLoginId 검증). 인접 회귀: 기존 26 tests 그대로 통과.
  - 검증: `./gradlew compileKotlin compileTestKotlin`, `IssueServiceSpec` 27 tests 전체 통과.
