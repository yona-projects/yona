## 완료 로그 (원문, `PARITY_BACKLOG.md`의 "완료 로그" 섹션에서 이관)

- **2026-08-20 — P1-39**: PR 생성 시점과 코드리뷰 리뷰어 참여/해제 시점에 `NotificationEvent`/`PullRequestEvent`가 전혀 기록되지 않던 문제 수정. yona `NotificationEvent.afterNewPullRequest`를 확인해 동일한 지점에 이벤트를 연결.
  - `PullRequestServiceImpl.createPullRequest()`: PR 저장(및 attemptMerge 시도) 이후 `EventType.NEW_PULL_REQUEST` `NotificationEvent`를 생성 — `IssueServiceImpl.createIssue()`의 `NEW_ISSUE` 패턴과 동일하게 `WatchService.findActualWatchers(baseWatchers=setOf(contributor), ...)`로 수신자를 계산(yona의 `getReceiversWithRelatedAuthors`보다 단순화됨 — 워처만 계산하고 관련 커밋 작성자까지는 포함하지 않음, 기존 `createIssue`와 동일한 수준의 근사). 이어서 `recordPullRequestEvent`로 `PullRequestEvent`도 기록. 이를 위해 `WatchService`를 신규 생성자 의존성으로 주입.
  - `CodeReviewServiceImpl.addReviewer/removeReviewer()`: 이미 만들고 있던 `NotificationEvent(PULL_REQUEST_REVIEW_STATE_CHANGED)` 바로 뒤에 동일한 정보로 `PullRequestEvent`를 저장하는 `recordPullRequestEvent` 헬퍼 호출을 추가(newValue="DONE"/"CANCEL"). `PullRequestEventRepository`를 신규 생성자 의존성으로 주입.
  - **새로 발견한 이슈([[tickets/p1-49|P1-49]]로 분리)**: 리뷰어 추가/해제가 `PullRequestService`(→`PullRequestController`)와 `CodeReviewService`(→`ReviewApiController`) 양쪽에 중복 구현돼 있고, 이번에 고친 건 `CodeReviewService` 경로뿐임을 발견. `PullRequestService.addReviewer/removeReviewer`는 여전히 무기록 상태 — 별도 항목으로 분리해 은폐하지 않고 기록.
  - 테스트: `PullRequestServiceSpec.kt` +1 test(PR 생성 시 NotificationEvent/PullRequestEvent 생성), `CodeReviewServiceSpec.kt` +1 test(리뷰어 추가/해제 시 NotificationEvent/PullRequestEvent 생성). 인접 회귀: `domain/pullrequest/*`, `web/PullRequest*`, `web/Review*`, `YonaApplicationTests` 전체 재실행 통과.
  - 검증: `./gradlew compileKotlin compileTestKotlin`, `./gradlew test --tests "com.github.yonaprojects.yona.domain.pullrequest.*" --tests "com.github.yonaprojects.yona.web.PullRequest*" --tests "com.github.yonaprojects.yona.web.Review*" --tests "com.github.yonaprojects.yona.YonaApplicationTests"` 모두 통과.
