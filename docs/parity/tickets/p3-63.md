# P3-63: 코드 파일 보기 화면에서 소스 내용 자체가 렌더링되지 않음 (Ace 에디터 미포팅의 부수 효과)

## 배경

legacy v1.6.1(`app/views/code/view.scala.html:127`)은 `$yobi.loadModule("code.Browser", {...})`로
`yobi.code.Browser.js`를 로드해, 폴더 트리를 AJAX로 지연 확장하고 파일을 클릭하면 Ace 에디터
(`ace.edit("showCode")`, `lib/ace/*`)로 문법강조된 소스를 보여줬다. 이 기능은 v1.6 시점부터
있었고 지금(legacy HEAD)까지 그대로 살아있다.

yona `src/main/resources/templates/code/view.html`(108~112행)에는 이미 다음 코멘트가 있다:

> legacy `.code-browse-wrap .list-wrap { display: none; }`는 legacy JS
> `$yobi.loadModule("code.Browser", ...)`의 `$(".list-wrap").show()`로 열리는 걸 전제로 한
> 규칙인데, yona는 이 SPA 트리 전개 JS 모듈을 포팅하지 않고 일반 페이지 이동 링크로
> 단순화했다.

즉 "AJAX 트리 확장을 포팅하지 않고 페이지 이동으로 단순화했다"는 것 자체는 과거에 이미 검토되고
문서화된 의도적 결정이다. 이번 조사는 그 단순화가 **부수적으로 더 큰 문제를 남겼는지** 확인하기
위해 진행했다.

## 현재 yona 상태 (격차 확정 — 예상보다 심각함)

`code/view.html`의 파일 뷰어 영역(288~294행):

```html
<div th:if="${markdownHtml == null}">
  <div id="codeVal" class="hidden" th:text="${fileInfo.get('data').asText()}">code</div>
  <pre id="showCode" class="code-wrap" th:data-mimetype="${fileInfo.get('mimeType').asText()}"></pre>
</div>
```

- 실제 파일 내용은 `#codeVal`에 서버가 정상적으로 채워 넣는다(`fileInfo.data`) — **하지만 이
  div에는 `class="hidden"`이 붙어있어 화면에 보이지 않는다.**
- 화면에 실제로 보이는 요소는 `#showCode`(`<pre>`)인데, **완전히 빈 채로 렌더링된다.**
  `#codeVal`의 내용을 `#showCode`로 복사하거나 Ace 에디터를 붙이는 코드는
  `service/yobi.code.Browser.js`(73행 `htElement.welShowCode = $("#showCode")`, 381행
  `_getEditor("showCode")`)에만 있는데, 이 파일은 앞서 확인한 대로 **어떤 yona 템플릿에서도
  로드되지 않는다**(grep 재확인 완료 — `code/view.html` 어디에도 `<script src>`나
  `$yobi.loadModule("code.Browser", ...)` 호출이 없음). 압축 번들(`yona-common.js`/
  `yona-layout.js`/`yona-lib.js`)에도 `showCode`/`codeVal` 관련 코드가 없음(grep 0건).
- **결론: 바이너리도 마크다운도 아닌 일반 텍스트/코드 파일을 코드 브라우저에서 열면, 파일
  내용이 사용자에게 전혀 보이지 않는다** (페이지 소스나 devtools로 `#codeVal`을 직접 봐야만
  내용을 알 수 있음). 이건 "Ace 문법강조가 없다"는 수준의 격차가 아니라 **핵심 기능(소스 보기)
  자체가 비어있는 화면으로 렌더링되는 버그**다.
- 이미지(binary + image/*)와 마크다운 파일(`markdownHtml != null`)은 각각 `#showImage`/
  `#codeVal.markdown-wrap`으로 정상 렌더링된다 — 이 버그는 "일반 텍스트/소스 코드 파일" 케이스에만
  해당한다.

## 원인

`code/view.html` 작성 시 legacy의 `#showCode`(빈 `<pre>`, JS가 채움)와 `#codeVal`(실제 데이터
보관용, `display:none` 대상)의 역할 분담을 그대로 마크업만 옮겨왔지만, 그 둘을 연결하던
`yobi.code.Browser.js`의 로딩 자체가 (SPA 트리 단순화 결정과 함께) 통째로 빠지면서, 연결
로직 없이 마크업만 남아 이런 상태가 된 것으로 보인다.

## 제안

이 티켓은 순수 조사 산출물이며 구현은 하지 않았다(사용자 지시로 백로그 등록만 완료). 착수 시
고려할 방향:

1. **최소 수정(권장 우선순위)**: Ace 에디터/AJAX 트리 확장 전체를 되살리지 않고도, `#codeVal`의
   `hidden` 클래스를 제거하거나 `#showCode`에 서버 렌더링 시점에 `th:text`로 파일 내용을 직접
   채워 넣는 것만으로 "내용이 안 보이는" 핵심 버그는 해소된다(문법강조 없이 plain text로라도
   보이게). highlight.js는 이미 다른 화면(마크다운 코드블록, PR diff)에서 쓰이고 있으니
   `.code-wrap`에 highlight.js를 붙이는 것도 저비용 개선책이 될 수 있다.
2. **완전 이식**: legacy와 동치로 Ace 에디터(`lib/ace/*`, 284개 파일 이미 vendoring돼 있음)를
   실제로 붙이고, `service/yobi.code.Browser.js`를 최소한 "파일 뷰어" 부분만이라도 재작성해
   로드한다. AJAX 트리 확장(SPA 폴더 탐색)까지 되살릴지는 별도 UX 결정 필요 — 현재의 "폴더
   클릭 시 페이지 이동" 방식이 오히려 더 단순하고 접근성 있게 동작한다는 반론도 가능해, 이
   부분만은 사용자 확인이 필요하다.
3. TDD로 "코드 파일을 보면 그 내용이 렌더링된 HTML 어딘가에 화면 표시 가능한 형태로 존재한다"는
   회귀 스펙을 먼저 세울 것(현재는 이 케이스에 대한 템플릿 렌더링 테스트 자체가 없을 가능성이
   높음 — 확인 필요).
