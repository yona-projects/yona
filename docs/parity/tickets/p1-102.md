## 완료 로그 (원문, `PARITY_BACKLOG.md`의 "완료 로그" 섹션에서 이관)

- **2026-08-21 — P1-102**: 이슈/댓글 동시편집 충돌 감지 3종 이식(`detectChange`/`updateIssueContent`/`updateIssueComment` 충돌검사).
  - Serena LSP로 yona `IssueApi.java`를 심볼 단위 재확인 — `detectChange()`(:551-584, 클라이언트가 계산해 보낸 체크섬/댓글수를 폴링으로 비교)와 `isModifiedByOthers()`(:538-548, 저장 직전 서버가 두 원문을 각각 SHA-1 해시해 비교)가 서로 다른 메커니즘임을 확인. 전자는 "변경 감지 폴링" API, 후자는 "저장 시점 충돌 차단"에 쓰이며 `updateIssueContent()`(:319-349, PATCH, 이슈 본문 인라인 수정)와 `updateIssueComment()`(:594-634, PUT, 댓글 수정) 양쪽에서 저장 직전에 호출됨을 확인.
  - `IssueController.kt`에 `POST /{number}/detectChange`(신규)와 `PATCH /{number}/content`(`updateIssueContent`, 신규) 추가 — 각각 yona 응답 구조(`issueBodyChanged`/`numOfComments`/`issueBodyChecksum`/`issueUpdateDate`/`result`/조건부 `commentAuthorName`, 그리고 409 `{"message":"Already modified by someone.", "storedContent": ...}`)를 그대로 재현.
  - `CommentController.kt`의 기존 `PUT .../comments/{commentId}`(`updateIssueComment`)에 동일한 충돌검사를 추가 — `CommentRequest.original: String? = null`(nullable, 하위호환 절충: 원문을 안 보내는 기존 프론트 호출은 검사 스킵)이 있을 때만 `isModifiedByOthers`로 비교, 불일치 시 409. 반환 타입을 `ResponseEntity<IssueComment>`에서 `ResponseEntity<Any>`로 변경(409 바디 타입이 다름).
  - `isModifiedByOthers`/`sha1Hex`를 `IssueController`/`CommentController` 양쪽이 필요로 하게 되면서, 각 클래스에 사설로 복제하는 대신 `domain/support/ChecksumUtils.kt`(신규) 공용 확장함수로 뽑아 양쪽이 재사용하도록 정리.
  - **범위 밖 발견 사항(착수 안 함)**: yona `BoardApi.java`에도 게시글(Board)에 대한 동일한 `conflicted`/`isModifiedByOthers` 패턴이 존재함을 grep으로 확인했으나, 이번 항목의 등록 스코프("이슈/댓글")를 벗어나 착수하지 않음 — 사용자 지시로 [[tickets/p1-107|P1-107]]로 정식 등록.
  - 테스트: `IssueControllerSpec.kt` +8(draft 게이트 회귀 없음 확인 포함 — upvoteWeight/downvoteWeight 3건, detectChange 4건, updateIssueContent 2건 중 fixture 공유 버그를 자체 발견/수정), `CommentControllerSpec.kt` +2(original 일치 시 정상 수정/불일치 시 409+storedContent+서비스 미호출 검증).
