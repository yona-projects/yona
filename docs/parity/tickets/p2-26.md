  - **⚠️ TODO(미해결, 버그로 의심됨)**: `JodaDateUtil.beforeByMillis(millis)`는 `now - millis`(과거 시점)를 반환하므로, yona의 실제 조건은 `createdDate >= (now - KEEPUP_TIME)` — 즉 **"오래 방치된" 파일이 아니라 "keepAlive 기간 이내에 최근 업로드된"** 파일을 정리 대상으로 삼는다. 메서드 취지("Remove all of temporary files uploaded by users", 24시간 간격 스케줄링)와 정반대 방향이라 yona 자체의 비교부호 버그로 강하게 의심된다 — 실사용 시 사용자가 방금 올린(아직 게시글에 첨부하지 못한) 임시 파일이 오히려 삭제되고, 정작 오래 방치된 파일은 영구히 남는다. 사용자 지시(2026-08-21)로 이번엔 레거시 동작을 그대로 포팅했으나, **향후 이 방향을 그대로 둘지 "의도(오래된 파일 정리)"에 맞게 반전할지는 별도 결정이 필요**하다.
  - `AttachmentRepository`의 `findByContainerTypeAndCreatedDateBefore`를 `findByContainerTypeAndCreatedDateGreaterThanEqual`로 교체(유일한 호출부인 이 스케줄러 전용).
  - 테스트: `AttachmentServiceSpec.kt` 기존 테스트 #4를 "최근 파일이 삭제됨"으로 방향 전환 + #4-1 신규("keepAlive보다 오래된 파일은 삭제되지 않음", 반대 방향임을 명시적으로 검증) 추가. 전체 11/11 통과.
