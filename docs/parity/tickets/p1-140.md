## 완료 로그 (원문, `PARITY_BACKLOG.md`의 "완료 로그" 섹션에서 이관)

- **2026-08-21 — P1-140**: yona `Markdown.render(source, project, breaks, lang)`/`render(source, project, lang)` 대응 — 렌더 캐시(성능)와 lang 오버로드(정합성 버그) 중 lang 오버로드를 이식.
  - `AutoLinkRenderer.render(body, project, lang = null)`로 `lang` 파라미터를 추가하고 `toValidUserLink(userId, lang)`에 전달 — `lang`이 주어지면(다이제스트 메일 배치 스레드처럼 HTTP 요청 컨텍스트가 없어 `LocaleContextHolder`가 수신자 언어를 알 수 없는 상황) 그 값을 그대로 쓰고, 없을 때만(일반 요청 스레드) 기존처럼 `LocaleContextHolder.getLocale()`로 대체(yona `AutoLinkRenderer.java:322-327`의 `StringUtils.isBlank(lang) ? getPureNameOnly() : getPureNameOnly(lang)` 대응).
  - `MarkdownService`/`MarkdownServiceImpl`에 `render(body, breaks, project, lang)` 4-인자 오버로드 신설, 기존 3-인자는 `lang=null`로 위임.
  - `NotificationMailDigestScheduler.sendMail()`이 이미 수신자 배치별로 계산해둔 `locale`을 `markdownService.render(...)` 호출에 명시적으로 넘기도록 수정 — 이전에는 이 값이 계산까지 되고도 markdown 렌더링에는 전달되지 않아, 다이제스트 메일의 `@멘션` 표시 이름이 수신자가 아니라 서버(스레드) 기본 로케일로 렌더링될 수 있었다.
  - **새로 발견해 [[tickets/p2-43|P2-43]]으로 분리**: `Markdown.renderWithHighlight()`의 `CacheStore.renderedMarkdown`(해시코드 키, 압축 저장, 접근 시 TTL 갱신) 렌더 캐시는 순수 성능 최적화라 새 캐싱 라이브러리(Caffeine/Guava, 현재 미도입) 선정이 필요한 별도 아키텍처 결정으로 분리.
  - 테스트: `MarkdownServiceImplSpec.kt` +1(lang="en"/"ko"로 각각 다른 멘션 표시 이름), `NotificationMailDigestSchedulerSpec.kt` 기존 "언어가 다른 수신자는 각자 다른 로케일로" 테스트에 markdownService.render가 각 배치의 언어로 호출되는지 검증 추가. 전체 통과.
