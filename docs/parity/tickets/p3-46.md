# P3-46: 클라이언트 위젯 라이브러리 현대화 (2026-09-10 사용자 제안)

## 배경

[[tickets/p3-45|P3-45]](Tailwind CSS + htmx 템플릿 리팩터링) 계획서 작성 중, yona가 현재 쓰는
클라이언트 전용 위젯 라이브러리 상당수가 오래되거나 사실상 유지보수가 멈춘 것이 확인됐다. 사용자가
이를 지적하며 최신·활발히 유지되는 라이브러리로 교체할 것을 제안했다.

P3-45는 "화면 재설계 없이 CSS/상호작용 구현 방식만 교체"하는 낮은 리스크의 작업으로 범위를
한정하면서, 클라이언트 위젯 라이브러리 교체는 **비범위로 명시적으로 제외**했다 — 위젯 하나하나가
자체 API/이벤트 모델을 가진 별도 라이브러리라 교체마다 고유한 회귀 리스크가 있고, 182개 템플릿
리팩터링에 얹으면 리스크가 배가되기 때문이다. 이 티켓은 그 제외된 범위를 별도로 추적하기 위해
신설한다.

## 착수 원칙(사용자 지시, 2026-09-10)

- **TDD 에이전트로 라이브러리별 순차 진행.** 각 라이브러리 전환은 별도 작업 단위로 다룬다.
- **기존 라이브러리와 동작이 완전히 일치해야 한다** — TEMPLATE_BACKLOG/P3-45와 동일한 정신의
  "동치성 우선" 원칙. 새 라이브러리가 제공하는 부가 기능이 있어도 켜지 않는다(예: Tom Select의
  태그 생성 기능이 Select2엔 없었다면 끈 채로 유지). 옵션/이벤트/키보드 동작까지 최대한 맞춘다.
- **여러 후보가 남아있는 결정은 착수 전 사용자 확인** — 위 표로 전부 해소됨. 작업 중 새로운
  선택지가 발견되면(예: 특정 옵션의 기본값 차이) 그때그때 확인받는다.
- **범위 밖 발견/기록용 이슈는 메인 세션(대화 에이전트)에게 전달, 직접 처리하지 않는다.** TDD
  에이전트가 라이브러리 전환 중 발견하는 관련 없는 버그/개선점은 즉시 고치지 말고 보고만 하며,
  대화 세션이 사용자에게 확인받아 별도 티켓으로 등록하거나 그 자리에서 처리 여부를 결정한다.

## 완료 로그

### 1. Pikaday → Flatpickr (2026-09-10)

TDD 에이전트로 진행. Flatpickr **4.6.13** 자체 호스팅(`static/javascripts/lib/flatpickr/`) 도입,
`yobi.ui.Calendar.js`(공개 API `getDate`/`setDate`, 마크업 계약 `data-toggle="calendar"`+
`.btn-calendar` 유지)와 `yobi.milestone.Write.js`(브리핑엔 없었으나 에이전트가 직접 발견 —
milestone create/edit는 래퍼 없이 `new Pikaday(...)`를 직접 써서 `#datepicker`에 항상 펼쳐진
인라인 캘린더로 구현돼 있었음, `{inline:true}`로 동일 아키텍처 재현) 둘 다 교체. Pikaday 파일
전체 삭제. 신규 `CalendarWidgetTemplateEquivalenceSpec`(7케이스, RED→GREEN)+기존 이슈/마일스톤
관련 스펙 전부 회귀 없음(메인 세션이 직접 재실행해 재검증).

**결정 필요 사항 해소**: Flatpickr(`allowInput:true`)는 날짜 필드에 파싱 불가능한 문자열을
타이핑하고 blur하면 필드 값을 지운다(Pikaday는 그대로 둠) — 극단적 엣지케이스이며 사용자가
현재 구현(표준적인 Flatpickr 사용) 유지를 확정.

**범위 밖 발견 2건, 사용자 확인 후 이번 커밋에 함께 포함**:
1. `yobi.issue.View.js`의 `elements.dueDate = $("#issueDueDate")`(대응 요소 자체가 없어 항상 빈
   셀렉션이고 이후 어디서도 읽지 않는 죽은 코드) 제거.
2. issue/view.html에서 마감일이 있는 상태로 페이지를 열 때마다 `yobi.ui.Calendar.js`의 초기화가
   필드 값을 화면에 동기화하려고 `setDate()`를 호출하면서 불필요하게 `change` 이벤트까지 쏴서
   `_onChangeDueDate`(마감일 자동저장 위젯)를 매번 트리거하던 기존 버그(Pikaday 시절부터 있던
   것 — 원본 `pikaday.js`의 `setDate()`가 `preventOnSelect` 인자와 무관하게 항상
   `fireEvent(field, 'change', ...)`를 호출함을 삭제 전 커밋에서 직접 확인) 수정. 초기화 시의
   "표시 동기화" 호출만 `triggerChange=false`로 바꿔 change 이벤트를 억제하고, 공개 `setDate()`
   API는 기존처럼 change를 발생시키도록 유지(다른 코드가 명시적으로 부를 경우의 계약은 보존).

**수동 브라우저 확인 필요(미착수)**: 6개 화면(issue create/edit/list/view, milestone create/edit)의
실제 캘린더 팝업/인라인 캘린더 동작, issue/view 마감일 변경 자동저장이 여전히 정상 동작하는지.
