# P3-46: 클라이언트 위젯 라이브러리 현대화 (2026-09-10 사용자 제안)

## 배경

[[tickets/p3-45|P3-45]](Tailwind CSS + htmx 템플릿 리팩터링) 계획서 작성 중, yona가 현재 쓰는
클라이언트 전용 위젯 라이브러리 상당수가 오래되거나 사실상 유지보수가 멈춘 것이 확인됐다. 사용자가
이를 지적하며 최신·활발히 유지되는 라이브러리로 교체할 것을 제안했다.

P3-45는 "화면 재설계 없이 CSS/상호작용 구현 방식만 교체"하는 낮은 리스크의 작업으로 범위를
한정하면서, 클라이언트 위젯 라이브러리 교체는 **비범위로 명시적으로 제외**했다 — 위젯 하나하나가
자체 API/이벤트 모델을 가진 별도 라이브러리라 교체마다 고유한 회귀 리스크가 있고, 182개 템플릿
리팩터링에 얹으면 리스크가 배가되기 때문이다. 이 티켓은 그 제외된 범위를 별도로 추적하기 위해
신설한다.

  대화 세션이 사용자에게 확인받아 별도 티켓으로 등록하거나 그 자리에서 처리 여부를 결정한다.

### 1. Pikaday → Flatpickr (2026-09-10)

TDD 에이전트로 진행. Flatpickr **4.6.13** 자체 호스팅(`static/javascripts/lib/flatpickr/`) 도입,
`yobi.ui.Calendar.js`(공개 API `getDate`/`setDate`, 마크업 계약 `data-toggle="calendar"`+
`.btn-calendar` 유지)와 `yobi.milestone.Write.js`(브리핑엔 없었으나 에이전트가 직접 발견 —
milestone create/edit는 래퍼 없이 `new Pikaday(...)`를 직접 써서 `#datepicker`에 항상 펼쳐진
인라인 캘린더로 구현돼 있었음, `{inline:true}`로 동일 아키텍처 재현) 둘 다 교체. Pikaday 파일
전체 삭제. 신규 `CalendarWidgetTemplateEquivalenceSpec`(7케이스, RED→GREEN)+기존 이슈/마일스톤
관련 스펙 전부 회귀 없음(메인 세션이 직접 재실행해 재검증).

**결정 필요 사항 해소**: Flatpickr(`allowInput:true`)는 날짜 필드에 파싱 불가능한 문자열을
타이핑하고 blur하면 필드 값을 지운다(Pikaday는 그대로 둠) — 극단적 엣지케이스이며 사용자가
현재 구현(표준적인 Flatpickr 사용) 유지를 확정.

**범위 밖 발견 2건, 사용자 확인 후 이번 커밋에 함께 포함**:
1. `yobi.issue.View.js`의 `elements.dueDate = $("#issueDueDate")`(대응 요소 자체가 없어 항상 빈
   셀렉션이고 이후 어디서도 읽지 않는 죽은 코드) 제거.
2. issue/view.html에서 마감일이 있는 상태로 페이지를 열 때마다 `yobi.ui.Calendar.js`의 초기화가
   필드 값을 화면에 동기화하려고 `setDate()`를 호출하면서 불필요하게 `change` 이벤트까지 쏴서
   `_onChangeDueDate`(마감일 자동저장 위젯)를 매번 트리거하던 기존 버그(Pikaday 시절부터 있던
   것 — 원본 `pikaday.js`의 `setDate()`가 `preventOnSelect` 인자와 무관하게 항상
   `fireEvent(field, 'change', ...)`를 호출함을 삭제 전 커밋에서 직접 확인) 수정. 초기화 시의
   "표시 동기화" 호출만 `triggerChange=false`로 바꿔 change 이벤트를 억제하고, 공개 `setDate()`
   API는 기존처럼 change를 발생시키도록 유지(다른 코드가 명시적으로 부를 경우의 계약은 보존).

**수동 브라우저 확인 필요(미착수)**: 6개 화면(issue create/edit/list/view, milestone create/edit)의
실제 캘린더 팝업/인라인 캘린더 동작, issue/view 마감일 변경 자동저장이 여전히 정상 동작하는지.

### 2. Jcrop → Cropper.js (2026-09-10)

TDD 에이전트로 진행. Cropper.js **1.6.3**(v1 계열 최신 안정판, `getCroppedCanvas()` 명령형 API
사용 위해 웹컴포넌트 기반으로 전면 재작성된 v2 대신 의도적으로 선택 — 재설계 금지 원칙과 부합)
자체 호스팅(`static/javascripts/lib/cropperjs/`) 도입. `yobi.user.Setting.js`의 Jcrop 관련 함수
전체를 Cropper.js API로 재작성(`aspectRatio:1`/`minCropBoxWidth,Height:32`/`ready` 콜백에서
`setCropBoxData`로 기본 선택영역[0,0,128,128]/`crop` 이벤트로 실시간 미리보기/`getCroppedCanvas
({width:128,height:128})`로 최종 렌더링). Jcrop 파일 전체 삭제. 신규
`AvatarCropWidgetTemplateEquivalenceSpec`(2케이스, RED→GREEN)+`UserViewControllerSpec`(145)+
`CalendarWidgetTemplateEquivalenceSpec`(7) 전부 회귀 없음(메인 세션이 직접 재실행해 재검증).

**결정 필요 사항 해소**: Jcrop은 크롭박스가 완전히 사라질 수 있어 그 경우 기본 영역을 복원하는
안전장치(`onRelease`)가 있었는데, Cropper.js는 최소크기(32px) 미만으로 줄어들지 않아 크롭박스가
사라지는 상태 자체가 구조적으로 불가능하다 — 별도 대응 코드 없이도 "항상 유효한 크롭 영역 존재"
보장이 성립한다는 에이전트 판단을 사용자가 그대로 승인.

**범위 밖 발견 2건**:
1. **사용자 확인 후 함께 수정**: 크롭 결과 업로드 시 `elImage.mimeType`이 표준 `Image` 객체에
   없는 속성이라 항상 `undefined`였고, `canvas.toBlob()`이 타입 인자 없이 호출되어 원본 파일
   형식과 무관하게 항상 PNG로 인코딩되던 기존 버그(Jcrop 시절부터 있던 것). `_showCropper(oRes)`
   에서 `oRes.mimeType`(업로드 응답이 실제로 제공하는 값)을 `htVar.sAvatarMimeType`에 저장해두고
   `toBlob()` 호출 시 그대로 넘기도록 수정 — 원본 형식(JPEG 등)이 보존된다.
2. **이번엔 그대로 둠(기록만)**: Cropper.js 기본 오버레이 색상(반투명 검정)이 Jcrop의
   `bgColor:"#fff"`(반투명 흰색)와 시각적으로 다름. 필요 시 `.cropper-modal` CSS 오버라이드로
   맞출 수 있음.

**수동 브라우저 확인 필요(미착수)**: 아바타 업로드→크롭 모달 동작, 크롭박스 드래그 시 미리보기
동기화, 128x128 결과가 기존과 동일 영역을 담는지(특히 원본이 128px보다 작거나 매우 클 때),
모달 취소 후 재업로드 시 Cropper 재초기화, 크롭 결과가 원본 형식(JPEG 등)으로 정상 업로드되는지.

**메인 세션이 리뷰 중 에이전트가 놓친 심각한 회귀를 직접 발견해 수정**: `common/yobi.Mention.js`
(에이전트가 Tribute로 재작성한 파일)가 **어느 템플릿에서도 `<script src>`로 로드되지 않고
있었다** — 실제 실행되는 `yobi.Mention`은 전역 레이아웃이 로드하는 구버전 번들
(`static/javascripts/yona-lib.js`)에 박혀있던 atjs 기반 사본뿐이었고, 에이전트가 편집한 소스는
브라우저에 전혀 반영되지 않는 죽은 파일이었다. atjs 삭제로 그 번들 사본이 이제 항상 크래시하게
되어, **지금까지 실제로 동작하던 `:`(이모지) 트리거까지 깨지는 회귀**였다. `yobi.Mention()`을
호출하는 6개 화면(board/milestone/issue의 create·edit, pullrequest 2개는 원래도 로드 안 하던
화면이라 제외)에 `tribute.min.js` 바로 뒤로 `<script src=".../yobi.Mention.js">`를 추가해
해결(스크립트 실행 순서상 번들의 구식 정의를 새 정의로 덮어씀). 테스트에 `assertMentionScriptLoaded`
회귀 방지 단언 추가.

**범위 밖 발견, 사용자 확인 후 함께 처리**:
1. `mentionList`/`titleHeads` 원격검색 URL이 실제 컨트롤러 매핑과 어긋나 `@`/`#`/`[` 트리거가
   전부 404였던 기존 버그 — `/api` 접두사 누락(`mentionList`, 6개 파일)과 경로 구조 자체가
   다른 문제(`titleHeads`, 3개 파일) 둘 다 수정, `MentionController.kt`/`ProjectController.kt`의
   실제 `@GetMapping` 경로와 대조해 확정.
2. `pullrequest/create.html`/`edit.html`은 애초에 atjs/Tribute 어느 쪽도 로드한 적이 없는 기존
   버그 — 이번에도 건드리지 않고 보존(에이전트와 메인 세션 둘 다 독립적으로 확인).
3. `issue/view.html`의 atjs include는 `yobi.Mention()` 호출 자체가 없는 죽은 코드였음 — 제거.

**애초에 "심각한 발견"으로 지목했다가 실제 브라우저 재현으로 반증되어 정정한 것**:
`jQuery.browser` 미로드로 파이어폭스 IME 폴리필이 크래시해 같은 스크립트 블록의 뒤이은 코드
(PR/게시글 저장 핸들러 등)가 실행되지 않을 거라 추정했으나, Playwright로 실제 확인한 결과
`jQuery.browser`는 정의되어 있어(`{chrome:true,...}`) 크래시 자체가 나지 않았다. 대신 그
과정에서 board/edit.html의 완전히 다른 실제 버그(문자열 미인용 `ReferenceError`)를 찾아
[[tickets/p3-47|P3-47]]로, 그걸 고친 뒤 드러난 CSRF 403 문제를 [[tickets/p3-48|P3-48]]로
분리 등록했다(둘 다 P3-46과 무관한 기존 버그).

### 4. ViewerJS → 순정 Viewer.js 업그레이드 (2026-09-10)

TDD 에이전트로 진행(범위 좁음 — `site/layout.html` 전역 레이아웃 한 곳뿐, 다른 파일은 안 씀).
Viewer.js를 **1.6.1 → 1.13.0**으로 업그레이드하고 jQuery 래퍼(`jquery-viewer.js`) 완전 제거,
초기화 코드를 `$(".markdown-wrap").each(...)` 순회는 유지한 채 `$that.viewer()` → `new
Viewer(this, {transition:false})`로 전환(여러 `.markdown-wrap` 컨테이너 각각에 독립 인스턴스
필요 — 이슈/PR 뷰의 본문+댓글 여러 개 등). 신규 `ViewerLightboxWidgetTemplateEquivalenceSpec`
(RED→GREEN)+`TemplateEquivalenceSpec`(jquery-viewer.js 로드 단언을 `shouldBe 0`으로 갱신)+
`IssueViewControllerSpec`/`PullRequestViewControllerSpec`/`PullRequestViewControllerMoreSpec`/
`CalendarWidgetTemplateEquivalenceSpec`/`MentionAutocompleteWidgetTemplateEquivalenceSpec`
(레이아웃 전역 스크립트 블록을 건드린 만큼 추가 확인) 전부 개별 `--tests` 실행으로 GREEN —
메인 세션이 신규 스펙 재실행으로 재검증.

**결정 필요 사항 해소**: mouseover 시 커서를 포인터로 바꾸는 핸들러가 jquery-viewer.js
래퍼 기능인지 확인 — v1.13.0 소스/CSS 전체를 뒤져봐도 그런 처리가 없음을 확인, 애초에
순정 jQuery로 직접 작성된 이 프로젝트 자체 코드였다는 결론. 그대로 보존.

**범위 밖 발견**: 없음.

**수동 브라우저 확인 필요(미착수)**: 라이트박스 열기/닫기/갤러리 넘기기, 여러
`.markdown-wrap` 컨테이너(본문+댓글)가 각각 독립적으로 동작하는지, mouseover 커서 변경.

### 5. Select2 → Tom Select (2026-09-10)

TDD 에이전트로 진행(지금까지 중 가장 넓은 범위 — 템플릿 15개, 커스텀 JS 5개). Tom Select
**2.6.2**(`tom-select.complete.min.js`, remove_button 플러그인 포함) 자체 호스팅 도입.
`yobi.ui.Select2.js`를 전면 재작성 — `data-format`별(projects/issues/user/milestone/
issuelabel/branch) 포맷터를 `render.option`/`render.item`으로, 커스텀 matcher를 `score`
콜백으로 이식. `issuelabel`(이슈 라벨 배타 카테고리 다중선택)이 가장 복잡한 부분이었는데,
select2 v3의 "선점형"(`select2-selecting`+`preventDefault`) 방식 대신 Tom Select의
`onItemAdd`에서 "추가 후 정리"(같은 `categoryId`의 기존 선택을 사후 제거) 방식으로 재현 —
`optgroup`의 `data-category-id`/`data-category-is-exclusive`가 HTML5 dataset이라 항상
문자열로만 와서 `=== "true"`로 비교해야 한다는 점까지 정확히 짚어 구현. 원격 자동완성 2건
(담당자/공유자)은 `load`/`loadThrottle`(300ms)+`valueField`로 이식. `yobi.issue.Write.js`/
`yona.TitleHeadAutoCompletion.js`/`yobi.issue.View.js`의 `.select2("val",...)` 프로그래매틱
호출부(`yobi.issue.View.js`는 브리핑에 없었으나 에이전트가 직접 발견)도 `.tomselect.setValue`/
`.getValue()`로 전환. Select2 라이브러리 파일 전체 삭제. 신규
`SelectWidgetTemplateEquivalenceSpec`(9케이스, RED→GREEN)+기존 스펙 14개(Issue/Milestone/
Project/PullRequest/Board/Organization/Code 등 핵심 컨트롤러·렌더링 스펙 + Calendar/Mention/
AvatarCrop/Viewer 위젯 스펙) 전부 개별 `--tests` 실행으로 GREEN — 메인 세션이 신규 스펙
재실행 + 핵심 로직(`onItemAdd` 배타 처리) 코드 리뷰로 재검증.

**전역 번들 중복 확인(항목3 교훈 적용)**: `yona-lib.js`/`yona-common.js`/`yona-layout.js`
3개 전부 select2/tomselect 관련 코드 0건 — 착수 전·완료 후 에이전트가 확인했고 메인 세션도
독립적으로 재확인함. 이번엔 항목3같은 번들 함정 없음.

**결정 필요 사항(에이전트가 합리적 근거로 판단, 이견 없으면 그대로 확정)**:
1. `select2-without-searchbox`(project/create의 VCS 선택 등) → Tom Select `controlInput:null`
   (입력 자체 제거)로 대응. 원본도 `display:none`이라 포커스/타이핑이 애초에 불가능했으므로
   기능적으로 동일.
2. 로케일(ko/ja) 처리는 `window.YOBI_SELECT2_I18N`(noResults/searching/tooShort)로 이식.
   `formatInputTooLong`/`formatSelectionTooBig`은 이 프로젝트 어디서도 트리거 안 되는 설정이라
   이식 안 함(허용 가능한 gap).

**범위 밖 발견(전부 기존 버그/죽은 코드, 고치지 않고 보고만 함)**:
1. `yona.issue.Sharer.js`(`#issueSharer` 담당자 공유 위젯) 전체가 어느 템플릿에서도 로드된 적
   없는 죽은 파일 — 원본 formatter도 malformed(안 닫힌 `</div>`)였음.
2. `yobi.issue.Write.js:84`, `yobi.issue.View.js`의 `data("forceChange")` 분기 — 어디서도
   set되지 않아 도달 불가능.
3. `yobi.issue.View.js`의 `labelIds`(`evt.added`/`evt.removed`) 분기 — 현재 `.issue-info`
   안에 해당 select2 필드 자체가 없어 도달 불가능.
4. `organization/issueSearch_partial.html`의 `#projects` select에 `data-format` 속성이 빠져
   있어 아바타/owner 커스텀 렌더링이 애초에 적용 안 됨(기존 불일치).
5. `user/edit_tokens_new.html`의 `#scopedProjectIds`는 `data-toggle="select2"`는 있지만 이
   템플릿이 `common/select2` fragment를 include 안 해서 select2/Tom Select 어느 쪽도 초기화된
   적 없음(순정 native select로 동작 — fragment include 누락, 이번 교체와 무관).
6. `code/view.html`/`code/history.html`의 `#branches`(순정 select)를 다루는
   `yobi.code.Browser.js`/`yobi.code.Diff.js`가 select2 전용 프로퍼티(`weEvt.val`)를 읽어
   기존부터 `undefined`로 깨져있던 것으로 보임.
7. `code/view.html`/`code/history.html`/`code/diff.html`이 select2 위젯이 전혀 없는데도
   `common/select2` fragment를 불필요하게 로드 중(리소스 낭비, 기능 문제는 아님).
8. `.select2-container.select2-drop-above`(드롭다운이 위로 펼쳐질 때 테두리 반전) 스타일은
   Tom Select에 대응 클래스가 없어 이식 안 함 — 코너 라운딩 정도의 사소한 시각 차이 가능.

**수동 브라우저 확인 필요(미착수)**: `data-format`별 드롭다운 표시/검색(특히 milestone/issues/
