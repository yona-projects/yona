# P3-46: 클라이언트 위젯 라이브러리 현대화 (2026-09-10 사용자 제안)

## 배경

[[tickets/p3-45|P3-45]](Tailwind CSS + htmx 템플릿 리팩터링) 계획서 작성 중, yona가 현재 쓰는
클라이언트 전용 위젯 라이브러리 상당수가 오래되거나 사실상 유지보수가 멈춘 것이 확인됐다. 사용자가
이를 지적하며 최신·활발히 유지되는 라이브러리로 교체할 것을 제안했다.

P3-45는 "화면 재설계 없이 CSS/상호작용 구현 방식만 교체"하는 낮은 리스크의 작업으로 범위를
한정하면서, 클라이언트 위젯 라이브러리 교체는 **비범위로 명시적으로 제외**했다 — 위젯 하나하나가
자체 API/이벤트 모델을 가진 별도 라이브러리라 교체마다 고유한 회귀 리스크가 있고, 182개 템플릿
리팩터링에 얹으면 리스크가 배가되기 때문이다. 이 티켓은 그 제외된 범위를 별도로 추적하기 위해
신설한다.

## 현재 상태(코드로 확인, 2026-09-10 기준)

| 용도 | 현재 라이브러리 | 위치 | 비고 |
|---|---|---|---|

| 날짜 선택 | Pikaday | `static/javascripts/lib/pikaday/` | 유지보수 느림 |
| 이미지 크롭(프로필 사진 등) | Jcrop | `static/javascripts/lib/jquery/jquery.Jcrop.min.js`, `static/stylesheets/jcrop/` | 원 프로젝트 사실상 중단(~2015) |
| `@` 멘션 자동완성 | atjs(`jquery.atwho.js` 등) | `static/javascripts/lib/atjs/` | jQuery 플러그인 |
| 이미지 뷰어/라이트박스 | ViewerJS | `static/javascripts/lib/viewerjs/` | jQuery 래퍼(`jquery-viewer.js`) 포함 |
| 마크다운 렌더링 | marked.js | `static/javascripts/lib/marked.js` | 버전 미상이나 `sanitize`/`sanitizer` deprecation 경고 문자열로 미루어 0.7.0 전후 구세대 API(현재 v12+와 시그니처가 크게 다름) |
| 코드 문법 강조 | highlight.js | `static/javascripts/lib/highlight/highlight.pack.js` | **v9.11.0**(2016) — 현재 v11.x는 `highlightBlock()` 등 주요 API가 폐기/변경됨 |

## 권장 교체안(모두 jQuery 불필요, 활발히 유지보수 중 — 2026-09-10 시점 판단)

| 현재 | 권장 대안 | 비고 |
|---|---|---|
| Select2 | **Tom Select** 또는 **Choices.js** | 둘 다 무의존성, API가 Select2와 개념적으로 유사해 마이그레이션 부담이 상대적으로 낮음 |
| Pikaday | **Flatpickr** | 무의존성, 매우 활발한 유지보수 |
| Jcrop | **Cropper.js** | 무의존성, 사실상 업계 표준으로 자리잡음 |
| atjs | **Tribute.js** | 무의존성, textarea/contenteditable 양쪽 지원 |
| ViewerJS | **PhotoSwipe** 또는 (동일 계열 유지 시) **Viewer.js**(fengyuanchen, jQuery 래퍼 없이 순정 버전만 사용) | 현재 쓰는 파일명(`viewer.js`)이 fengyuanchen Viewer.js와 동일 계열로 보이므로, jQuery 래퍼(`jquery-viewer.js`)만 걷어내고 순정 버전으로 올리는 것도 저비용 대안 |
| marked.js(구버전) | **marked v12+**(같은 라이브러리 메이저 업그레이드) 또는 **markdown-it** | API 변경 폭 확인 필요(치환이 아니라 버전업 우선 검토) |
| highlight.js v9 | **highlight.js 최신판**(같은 라이브러리 메이저 업그레이드) | `highlightBlock`→`highlightElement` 등 API 변경 대응 필요, 교체가 아니라 버전업 |
| "마크다운 에디터"(자체 구현) | **보수적 옵션**: textarea 유지 + atjs만 Tribute.js로 교체 + marked/highlight.js만 버전업 / **적극적 옵션**: **EasyMDE** 또는 **CodeMirror 6** 기반 재구성(툴바·탭·체크리스트 버튼을 에디터가 자체 제공 — 현재 수제 UI를 대체하는 것이라 사실상 상호작용 재설계) | 적극적 옵션을 택할 경우 P3-45의 "재설계 금지" 원칙과 별도로 사용자 승인 필요 |

## 결정 필요 사항

- 착수 순서: P3-45(CSS/htmx)와 독립적으로 언제든 착수 가능하나, 마크업이 자주 바뀌는 P3-45 작업
  기간과 겹치면 두 브랜치가 같은 템플릿을 건드려 충돌 가능성이 있음 — 순서 조율 필요(사용자 결정)
- 마크다운 에디터: 보수적 옵션(부분 교체) vs 적극적 옵션(EasyMDE/CodeMirror 6 전면 교체) 중 택일
- 위 표의 각 교체 항목별로 실제 착수 시점의 최신 버전 확정 필요(이 문서는 2026-09-10 시점 판단)
