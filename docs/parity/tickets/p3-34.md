# P3-34: SVN도 Git/Hg와 동일한 수준의 실제 서버+실제 클라이언트 HTTP interop 테스트 추가

## 배경

Git과 Mercurial은 각각 `GitSmartHttpProtocolIntegrationSpec.kt`/`HgHttpProtocolIntegrationSpec.kt`에서
`@SpringBootTest(webEnvironment = SpringBootTest.WebEnvironment.RANDOM_PORT)`로 실제 임베디드
톰캣을 띄우고, `ProcessBuilder("git"/"hg", ...)`로 **실제 CLI 바이너리**를 실행해 HTTP
clone/push 왕복을 확정적으로 검증한다.

반면 SVN 관련 테스트는 `SvnControllerOptionsIntegrationSpec.kt`/
`DeployKeySvnAuthorizationIntegrationSpec.kt` 둘뿐이고, 둘 다 `MockMvc`(가짜 서블릿 컨테이너,
실제 포트 없음) 기반이며 실제 `svn` CLI 바이너리를 실행하는 코드는 테스트 트리 전체에 한 곳도
없다. `SvnControllerOptionsIntegrationSpec`은 자체 주석에도 "OPTIONS 응답의 Allow 헤더에
PROPFIND가 있으면 DAVServlet까지 도달했다는 뜻"이라고 **간접 추론**만 검증할 뿐, 실제
`svn checkout`/`svn commit`을 돌려 end-to-end로 확정 검증한 적이 없다.

즉 SVN 저장소가 실제 svn 클라이언트로 clone/checkout/commit이 되는지는 이 코드베이스의
자동화된 테스트로는 한 번도 확정 검증된 적이 없다(Git/Hg는 있음).

## 요구사항

Git/Hg 스펙과 동일한 패턴으로 SVN interop 테스트를 신설한다:

1. `@SpringBootTest(webEnvironment = RANDOM_PORT)`로 실제 서버를 띄운다.
2. 테스트 환경에 실제 `svn` CLI가 설치돼 있는지 먼저 확인하고(`ProcessBuilder("svn", "--version")`),
   없으면 스킵한다 — Hg 스펙의 기존 관례와 동일.
3. `svn checkout http://127.0.0.1:$port/svn/{owner}/{project}`로 실제 워킹카피를 만들고,
   파일 추가 후 `svn add`/`svn commit`으로 실제 서버에 커밋한다.
4. 커밋이 실제로 반영됐는지 별도 워킹카피로 다시 checkout하거나 `svn log`로 확인한다.
5. 가능하면 DeployKey 인증 경로(`DeployKeySvnAuthorizationIntegrationSpec`가 다루는 시나리오)도
   실제 `svn` 클라이언트로 왕복하는 케이스를 함께 추가해, 그 스펙의 MockMvc 검증을 실제
   end-to-end로 보강한다(기존 MockMvc 스펙은 대체가 아니라 유지 — 더 빠른 하위 계층 검증으로 남김).

## 참고

- 실제 `svn` 바이너리는 로컬/CI 환경에 설치가 전제되어야 한다 — Hg 스펙처럼 미설치 시
  조용히 스킵하는 방어 코드가 필요하다.
- SVN은 WebDAV/DeltaV 기반이라 Git/Hg의 smart HTTP 프로토콜과 요청 흐름이 다르다
  (PROPFIND/REPORT/MKACTIVITY 등) — `DAVServlet`(Apache Jackrabbit 또는 동등 구현)이 실제로
  이 메서드들을 다 처리하는지까지 실제 클라이언트로 검증하는 게 이 티켓의 핵심 가치다.
