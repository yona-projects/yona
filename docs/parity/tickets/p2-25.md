## 완료 로그 (원문, `PARITY_BACKLOG.md`의 "완료 로그" 섹션에서 이관)

- **2026-08-21 — P2-25**: `AttachmentServiceImpl.store()`가 `Files.probeContentType(targetFile.toPath())`로 MIME 타입을 감지하던 것을, yona `FileUtil.java:113-142` `detectMediaType()`(Apache Tika로 실제 콘텐츠/매직 바이트 기반 감지, 원본 파일명은 힌트로만 사용) 대응으로 정정.
  - 물리 저장 파일은 SHA-256 해시를 파일명으로 쓰므로(확장자 없음) `Files.probeContentType()`(사실상 확장자 기반)은 사실상 항상 감지에 실패해 모든 첨부가 `application/octet-stream`으로 저장되고 있었다 — "가능성"이 아니라 사실상 상시 발생하는 버그였음을 신규 테스트로 직접 확인.
  - `build.gradle.kts`에 `org.apache.tika:tika-core:2.9.2` 추가(yona는 `tika-core 1.2`를 쓰지만 2026년 시점 최신 스택에 맞춰 현재 안정 버전으로 이식 — 프레임워크/언어 전환에 따른 버전 현대화는 기존 세션 전반의 원칙과 동일).
  - `domain/support/FileUtil.kt`(기존에 `detectCharset()` 두 오버로드가 이미 있던 객체)에 `detectMediaType(file, name)` 추가 — `Tika().detector.detect(BufferedInputStream, Metadata)`로 콘텐츠 감지 후, 텍스트 타입이면 기존 `detectCharset()`을 재사용해 `; charset=...` 파라미터를 붙이고(yona 동일 로직 재사용), `audio/ogg`+`.ogv` 확장자 조합은 yona와 동일하게 `video/ogg`로 보정.
  - `AttachmentServiceImpl.store()`가 해시 파일(`targetFile`)의 실제 바이트를 `FileUtil.detectMediaType(targetFile, name)`에 넘기도록 교체 — `name`(원본 파일명)은 힌트로만 전달되어 yona와 동일한 신호 구조.
  - 테스트: `AttachmentServiceSpec.kt` +2(PNG 매직 바이트를 확장자 없는 이름/컨테이너로 저장해도 `image/png`로 정확히 감지/한글 텍스트는 `text/plain; charset=UTF-8`로 감지). 전체 10/10 통과.
