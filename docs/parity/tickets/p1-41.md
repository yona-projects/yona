## 완료 로그 (원문, `PARITY_BACKLOG.md`의 "완료 로그" 섹션에서 이관)

- **2026-08-20 — P1-41**: 최근 방문 이슈/게시글을 실제로 조회하는 엔드포인트와, 회원 탈퇴 시 방문 이력을 정리하는 배선이 없던 문제 수정. `RecentIssueService.recordIssueVisit/recordPostingVisit/getRecentIssues`([[tickets/p1-09|P1-09]])는 이미 준비돼 있었고, 이번엔 조회 노출과 삭제 정리만 연결.
  - `web/UserController.kt`에 `GET /api/users/me/recent-issues` 신규 추가 — 로그인한 사용자의 `RecentIssueService.getRecentIssues()` 결과를 `{title, url, createdDate}` JSON 배열로 반환. yona는 이 데이터를 `usermenu` 드롭다운(`myRecentIssueList.scala.html`)에서 서버 렌더링으로 소비하지만, **범위 조정**: 이번 패스에서는 데이터를 노출하는 JSON API까지만 구현하고 드롭다운 UI 배선(레이아웃 템플릿에 프래그먼트 삽입)은 하지 않음 — 순수 프론트엔드 UI 작업이라 백엔드 동치성 확보가 우선인 이 백로그의 성격과 다소 어긋나고, `getRecentIssues()`가 이미 있었던 것처럼 엔드포인트만 있으면 프론트엔드는 필요할 때 쉽게 연결 가능해 범위를 좁혔다.
    (**정정, 2026-08-23**: 이 JSON API 경로로 UI를 연결하는 일은 실제로 일어나지 않았고, 대신
    `docs/TEMPLATE_BACKLOG.md` TASK-0225(#14)가 legacy와 더 가까운 서버 렌더링 방식
    — `UserViewController.usermenuTabContentList()`가 같은 `RecentIssueService.getRecentIssues()`를
    직접 호출해 `common/usermenu_tab_content_list.html`에 렌더링 — 으로 드롭다운을 완성했다. 이
    `GET /api/users/me/recent-issues` JSON 엔드포인트 자체는 현재 어떤 화면에서도 호출되지 않는
    미사용 상태이나, 별도 소비처가 생길 수 있어 제거하지 않고 그대로 유지)
  - `RecentIssueService`에 `deleteAll(user)` 추가(기존에 이미 있던 `RecentIssueRepository.deleteByUserId`를 그제서야 실제로 사용). `SiteService.deleteUser()`(계정 삭제/탈퇴가 실제로 일어나는 유일한 지점, 관리자용 `SiteApiController`가 호출)에서 사용자 상태를 DELETED로 바꾼 직후 `recentIssueService.deleteAll(targetUser)` 호출을 추가.
  - 테스트: `UserControllerSpec.kt` +2 tests(정상 조회/비로그인 401), `RecentIssueServiceSpec.kt` +1 test(deleteAll), 신규 `SiteServiceSpec.kt`(이 서비스에 대한 첫 유닛테스트 파일) 1 test(deleteUser가 recentIssueService.deleteAll을 호출하는지 검증). 인접 회귀: `domain/site/*`, `domain/issue/RecentIssueServiceSpec`, `web/UserControllerSpec`, `web/SiteControllerSpec`, `YonaApplicationTests` 전체 재실행 통과.
  - 검증: `./gradlew compileKotlin compileTestKotlin`, `./gradlew test --tests "com.github.yonaprojects.yona.domain.site.*" --tests "com.github.yonaprojects.yona.domain.issue.RecentIssueServiceSpec" --tests "com.github.yonaprojects.yona.web.UserControllerSpec" --tests "com.github.yonaprojects.yona.web.SiteControllerSpec" --tests "com.github.yonaprojects.yona.YonaApplicationTests"` 모두 통과.
