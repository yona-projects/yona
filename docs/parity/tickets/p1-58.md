## 완료 로그 (원문, `PARITY_BACKLOG.md`의 "완료 로그" 섹션에서 이관)

- **2026-08-20 — P1-58**: mentionList 응답의 `name`/`searchText` 필드가 `user.name`을 그대로 쓰던 것을 yona `ProjectApp.collectedUsersToMentionList()`와 동일하게 `getDisplayName()` 기반으로 수정.
  - [[tickets/p1-14|P1-14]] 당시엔 yona `User`에 `englishName`/`getDisplayName()` 자체가 없어 단순화가 불가피했지만, 이후 다른 작업(정확한 시점 불명)에서 `domain/user/User.kt`에 `englishName`/`extractDepartmentPart()`/`getDisplayName()`/`getDisplayName(forCurrentUser: User)`가 이미 이식돼 있었음에도 `MentionController.toMentionMaps()`만 옛 구현 그대로 남아있던 것을 확인.
  - `toMentionMaps(users, currentUser: User?)`로 시그니처 확장(호출부 3곳 모두 `loginUser`를 전달 — 모두 이미 스코프에 있어 새 파라미터 배선만 필요). `displayName = currentUser?.let { user.getDisplayName(it) } ?: user.getDisplayName()` — yona `user.getDisplayName()`이 `UserApp.currentUser()`(요청자)의 `lang`을 암묵적으로 참조하는 것을, yona의 명시적 파라미터 버전(`getDisplayName(forCurrentUser)`)으로 그대로 재현. 비로그인 요청(currentUser=null)은 무인자 `getDisplayName()`(항상 `name` 반환)으로 폴백 — yona의 익명 사용자(`lang` 미설정)가 사실상 영어 조건을 못 타 `name`으로 떨어지는 것과 동일한 결과.
  - `"name" to displayName`(기존 `user.name`에서 교체), `"searchText" to "${user.name}${displayName}${user.loginId}"`(yona `name+getDisplayName()+loginId` 3필드 그대로).
  - 테스트: `MentionControllerSpec.kt` +1 — 영어 사용자(`lang="en"`)가 조회할 때 `englishName`+`extractDepartmentPart()`(대괄호 부서명 포함, 예: `"Gildong Hong [개발팀]"`)가 `name`/`searchText`에 반영되는지 확인. 기존 12 tests는 name 필드를 다루지 않는 케이스들이라 회귀 없음(총 13 tests).
  - 검증: `./gradlew compileKotlin compileTestKotlin` 전체 컴파일 성공, `./gradlew test --tests "com.github.yonaprojects.yona.web.MentionControllerSpec"` 13 tests 전체 통과.
