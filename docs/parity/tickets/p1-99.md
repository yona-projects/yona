## 완료 로그 (원문, `PARITY_BACKLOG.md`의 "완료 로그" 섹션에서 이관)

- **2026-08-21 — P1-99**: 사이트 전역 "익명 접근 허용" 설정(`allowsAnonymousAccess`)을 `AccessControl.kt`에 이식.
  - 착수 전 재확인(Serena LSP): yona `AccessControl.java:21,336-337`을 다시 읽어 이 값이 DB 사이트 설정이 아니라 **conf 파일 부트타임 설정**(`play.Configuration.root().getBoolean("application.allowsAnonymousAccess", true)`, `conf/application.conf.default:21`에 명시적으로 `true`)임을 확정 — 이전 등록 문구의 "대응 사이트 설정 모델/화면 자체 없음(확인 필요)"이라는 불확실성을 해소, DB 모델이 아니라 Spring `@Value` 프로퍼티로 이식하는 게 정확한 대응임을 확정.
  - `AccessControl.kt` 생성자에 `@Value("\${yona.access.allows-anonymous-access:true}") allowsAnonymousAccess: Boolean = true` 추가, `isAnonymousNotAllowed(): Boolean = !allowsAnonymousAccess` 헬퍼 신규.
  - [[tickets/p1-85|P1-85]] 1b에서 만든 13개 `isAllowed(...)` 리소스 타입별 오버로드 + `isAllowedAttachment()` 전부(총 15곳)의 시작부에 `if (isAnonymousNotAllowed() && user == null) return false` 게이트를 동일한 위치(yona의 `isAllowed()` 최상단과 동일)에 일괄 삽입 — Serena `replace_content`(regex, `allow_multiple_occurrences`)로 공통 시작 패턴(`if (user?.isSiteManager == true) return true`)을 앵커 삼아 한 번에 적용.
  - 테스트: `AccessControlSpec.kt`에 `allowsAnonymousAccess=false`로 만든 별도 인스턴스로 3건 추가(PUBLIC 프로젝트라도 익명 READ 거부/로그인 사용자는 영향 없음/기본값(true)에서는 기존처럼 익명 READ 허용).
  - 검증: `./gradlew test --tests "...AccessControlSpec"` 전체 통과(기존 게스트/공유자 테스트 등 회귀 없음 확인).
