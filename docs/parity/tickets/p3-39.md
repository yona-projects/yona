# P3-39: legacy Open API 동시편집 충돌감지 4곳이 실제 프로토콜과 다른 필드명/검증 방식을 쓰고 있던 결함 수정

## 배경

[[tickets/p3-38|P3-38]]에서 새로 이식한 bare 경로 PATCH가 실제 v1.6 웹 UI에서도 호출되는지
확인하려고 `yona.Tasklist.js`(마크다운 체크박스 클릭 시 댓글/본문을 저장하는 실제 클라이언트
코드)를 열어봤다가, 그 AJAX 요청이 `{content, original}` 필드로 **원문 텍스트 그대로**를
보낸다는 것을 발견했다. v1.6 원본 서버(`IssueApi.java`/`BoardApi.java`)의
`isModifiedByOthers(current, fromView)`도 정확히 이 방식이다 — 클라이언트가 보낸 원문
(`original`)과 서버의 현재 값을 **각각** SHA-1 해시해서 비교한다.

그런데 yona의 legacy Open API 호환 레이어(4개 엔드포인트: 이슈 본문 수정, 게시글 본문 수정,
이슈 댓글 수정, 게시글 댓글 수정)는 전부 `content`/`sha1` 필드를 쓰고
있었고, `isModifiedByOthersLegacyChecksum(current, clientChecksum)`이라는 별도 함수로
"클라이언트가 이미 계산한 SHA-1 해시값 자체를 보낸다"고 **검증 없이 가정**하고 있었다. 실제로는
그런 클라이언트가 없다 — v1.6 자신의 웹 UI조차 원문을 그대로 보낸다. 이 잘못된 함수가 쓰이는
동안은, 실제 legacy 프로토콜을 따르는 어떤 클라이언트가 호출하든 `original` 필드가 무시되고
`sha1` 필드는 기본값 빈 문자열로 남아 **거의 항상 409(Already modified)로 거부**됐을 것이다
(내가 P3-38 실사용 검증 때 우연히 스스로 계산한 SHA-1 해시를 `sha1` 필드로 넣어 테스트했던
탓에 이 결함을 그때는 놓쳤다).

## 범위

4개 엔드포인트 전부 수정:

| 컨트롤러 | 메서드 | 대상 |
|---|---|---|
| `IssueApiController.kt` | `updateIssueContentLegacyPath` | 이슈 본문 |
| `BoardApiController.kt` | `updatePostingContentLegacyPath` | 게시글 본문 |
| `CommentController.kt` | `updateIssueCommentLegacyPath` | 이슈 댓글 |
| `CommentController.kt` | `updatePostingCommentLegacyPath` | 게시글 댓글 |

- 요청 DTO 필드명 `sha1` → `original`로 변경(`LegacyUpdateIssueContentRequest`/
  `LegacyUpdatePostingContentRequest`/`LegacyUpdateCommentRequest`).
- `isModifiedByOthersLegacyChecksum(current, clientChecksum)`(잘못된 가정으로 만들어진 함수,
  한쪽만 해시)을 완전히 삭제하고, 기존에 이미 정확하게 이식돼 있던
  `isModifiedByOthers(current, fromView)`(양쪽 다 해시, `domain/support/ChecksumUtils.kt`)로
  4곳 전부 통일.

## 완료 로그

### 2026-09-09 — 발견·구현·검증 완료

**발견**: `yona.Tasklist.js`(v1.6 원본, 마크다운 체크박스 저장 AJAX)와 `IssueApi.java`/
`BoardApi.java`의 `isModifiedByOthers()` 원본 소스를 직접 대조해 확인.

**수정**: `ChecksumUtils.kt`에서 `isModifiedByOthersLegacyChecksum` 삭제, 4개 호출부를
`isModifiedByOthers()`로 교체, 3개 DTO의 `sha1` 필드를 `original`로 리네임.

**테스트 갱신**: `CommentControllerSpec.kt`/`IssueApiControllerSpec.kt`/
`BoardApiControllerSpec.kt`의 관련 테스트가 이전에는 `sha1: sha1Hex(rawText)`(해시값)를
보냈는데, 이제 `original: rawText`(원문 그대로)를 보내도록 수정 — 이 테스트들 자체가 잘못된
프로토콜 가정 위에서 "그린"이었을 뿐, 실제 legacy 클라이언트 동작을 검증하지 못하고 있었다.

**실사용 검증(핵심)**: 실제 서버(포트 18799)에서 이슈 댓글을 생성한 뒤, **해시 계산 없이
원문 텍스트를 그대로** `original` 필드에 담아 `PATCH /admin/patchtest/issue/1/comments/{id}`
호출 → 200 성공 확인. 다른(틀린) 원문으로 재시도 → 409(Already modified) 정상 거부 확인 —
`yona.Tasklist.js`가 실제로 보내는 것과 동일한 요청 형태로 검증했다는 점이 핵심(P3-38 검증
때는 몰랐던 결함이라 스스로 계산한 해시를 보내 우회 검증했었다).

**회귀 확인**: `CommentControllerSpec`(66)/`IssueApiControllerSpec`(15)/
`BoardApiControllerSpec`(6)/`IssueControllerSpec`/`BoardControllerSpec` 전부 GREEN.
