# P1-26: PULL_REQUEST 리소스 타입은 웹훅 payload를 만들 수 없음

## 원본 표 정보

- **상태(원본 체크박스)**: `[x]`
- **yona 근거**: `Webhook.java:674-729`(PR 부분)
- **yona 대상**: `domain/webhook/WebhookServiceImpl.kt` (`buildPayload`, `getResourceType`)
- **비고(원문)**: **완료**

## 완료 로그 (원문, `PARITY_BACKLOG.md`의 "완료 로그" 섹션에서 이관)

- **2026-08-20 — P1-26**: `CodeReviewServiceImpl`/`PullRequestServiceImpl`이 발행하는 `PULL_REQUEST` 타입 `NotificationEvent`(리뷰어 참여/취소, PR 상태변경)가 `WebhookNotificationEventListener.resolveResource()`에서 지원하지 않는 타입으로 처리돼 조용히 스킵되던 문제 수정(yona `Webhook.sendRequestToPayloadUrl(EventType, User, PullRequest, ...)` 대응).
  - 커밋([[tickets/p1-25|P1-25]])과 달리 PR은 정상적인 DB 엔티티이고 `NotificationEvent.resourceId`도 PR의 실제 PK를 담고 있어(`pullRequestId.toString()`/`saved.id.toString()`), 기존 ISSUE_POST/BOARD_POST 등과 동일한 "resourceId로 재조회" 패턴이 그대로 들어맞는다. `WebhookNotificationEventListener`에 `PullRequestRepository`를 주입해 `resolveResource()`에 `ResourceType.PULL_REQUEST -> pullRequestRepository.findById(id)?.let { it.toProject to it }` 케이스만 추가하면 충분했다.
  - `WebhookServiceImpl`의 `getResourceType`/`getResourceId`/`buildTextMessage`에 `PullRequest` 케이스 추가. `buildTextMessage`의 이벤트별 문구도 yona `Webhook.buildRequestBody(EventType, ...)`의 switch(NEW_PULL_REQUEST/PULL_REQUEST_STATE_CHANGED/PULL_REQUEST_MERGED/PULL_REQUEST_COMMIT_CHANGED/PULL_REQUEST_REVIEW_STATE_CHANGED)를 참고해 누락돼 있던 3개 이벤트 타입 문구를 함께 보강.
  - 테스트: `WebhookNotificationEventListenerSpec.kt` — 기존에 "PULL_REQUEST는 조용히 스킵해야 한다"를 검증하던 테스트를 실제 발송을 검증하는 테스트로 교체하고, "대상 PR을 찾을 수 없으면 미발송" 케이스를 신규 추가 — 총 8 tests(기존 6건 중 1건 교체 + 1건 신규). `com.github.yonaprojects.yona.domain.pullrequest.*`/`YonaApplicationTests` 재실행으로 회귀 없음 확인.
  - 검증: `./gradlew test --tests "WebhookNotificationEventListenerSpec" --tests "com.github.yonaprojects.yona.domain.pullrequest.*" --tests "YonaApplicationTests"` 전체 통과, `./gradlew compileKotlin compileTestKotlin` 전체 컴파일 성공.
