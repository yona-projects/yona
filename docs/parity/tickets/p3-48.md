# P3-48: CSRF 재활성화 이후 raw `$.ajax` PUT/DELETE/PATCH 호출들이 CSRF 토큰 없이 403으로 거부되던 문제 (2026-09-10 발견·근본 수정 완료, 화면별 전수 재현은 남음)

## 배경

[[tickets/p3-47|P3-47]](board/edit 저장 버튼 `ReferenceError`)를 수정한 뒤 Playwright로
저장 버튼을 실제로 눌러 검증하던 중, `PUT /api/projects/{id}/posts/{postId}`가 **403
Forbidden**으로 거부되는 것을 확인했다 — `board/edit.html`의 저장 핸들러가 `$.ajax({method:
'PUT', data: JSON.stringify(requestData), ...})` 형태로 직접 구성한 JSON 바디를 보내는데
CSRF 토큰을 헤더/바디 어디에도 싣지 않았기 때문이다. `static/javascripts/yona-common.js`를
확인한 결과, `meta[name=csrf-token]`을 읽어 CSRF를 자동으로 채워주는 로직은 jQuery
`.ajaxForm()`/`.ajaxSubmit()` 플러그인 경로에만 있고 raw `$.ajax({...})` 호출에는 없었다.

## 근본 수정 (완료)

Spring Security 공식 문서가 권장하는 표준 패턴을 적용했다:

1. `site/layout.html::head`에 `<meta name="_csrf" th:content="${_csrf?.token}">`/
   `<meta name="_csrf_header" th:content="${_csrf?.headerName}">` 추가(모든 화면이 이 fragment를
   씀 — 한 곳에서 전역 적용). `_csrf` 요청 속성이 없을 수 있는 경로(에러 페이지 포워딩 등)를
   위해 안전 내비게이션(`?.`) 사용 — 처음엔 `${_csrf.token}`으로 했다가 전체 스위트 실행 중
   `ErrorPageTemplateRenderingSpec` 등 13개 스펙이 `SpringEL` NPE로 깨지는 걸 발견해 정정.
2. `site/layout.html::scripts` 최상단에 그 두 meta를 읽어 **모든 `$.ajax` 호출에 일괄 적용**되는
   전역 `$.ajaxSetup({beforeSend: function(xhr){ xhr.setRequestHeader(csrfHeader, csrfToken); }})`
   추가. 개별 화면을 하나씩 고치는 대신(재발 방지 안 됨) 이 방식을 택함.

## 실제 브라우저(Playwright)로 board/edit 저장을 end-to-end 재검증하며 발견한 추가 버그

CSRF 수정 후 재검증했더니 403은 사라졌지만 **400 Bad Request**가 새로 나타났다 — 원인은
`board/edit.html`의 같은 저장 핸들러가 `var body = $("#body").val();`로 본문을 읽고 있었는데,
이 화면엔 `id="body"`인 요소 자체가 없다(마크다운 에디터는
`markdownEditor('body', ...)` 프래그먼트가 `id="editor-body-<랜덤>"`로 렌더링 — `name="body"`는
맞지만 `id`는 다름). `$("#body").val()`이 항상 `undefined`를 반환해 `JSON.stringify()`가 그
키를 통째로 빼먹어 서버가 400으로 거부했다. `$('textarea[id^=editor-]').val()`(같은 파일의
멘션 대상 셀렉터와 동일 패턴)로 수정 — **이것도 CSRF와 무관한 별도의 기존 버그**(P3-46/47/48
어느 것과도 무관, 이번 검증 과정에서 우연히 발견).

세 버그(따옴표 누락[[tickets/p3-47|P3-47]] + CSRF 헤더 누락[본 티켓] + 잘못된 `#body` 셀렉터)를
모두 고친 뒤 Playwright로 로그인→프로젝트 생성→게시글 생성→수정→저장까지 **end-to-end로 실제
저장 성공(제목 변경 반영)까지 확인했다.**

## 남은 작업 — 다른 12개 파일의 화면별 재현 (미착수)

전역 `$.ajaxSetup`을 걸어뒀으므로 **이론적으로는 raw `$.ajax` PUT/DELETE/PATCH를 쓰는 나머지
화면들도 자동으로 함께 고쳐졌어야 한다**(CSRF 헤더 누락이라는 근본 원인 자체가 전역으로
해소됐으므로). 다만 실제로 하나씩 브라우저에서 재현해 확인한 것은 board/edit뿐이다. 아래
목록을 이번 세션에서 다시 뽑아뒀다(`method:`/`type:`에 `PUT`/`DELETE`/`PATCH`를 쓰는 파일,
`site/layout.html` 자기 자신과 벤더 파일 `lib/ace/worker-coffee.js` 제외):

- `organization/members.html`
- `pullrequest/edit.html`, `pullrequest/view.html`
- `board/edit.html`(재현·수정 완료), `board/view.html`
- `code/svnDiff.html`, `code/compare.html`
- `project/members.html`, `project/setting.html`
- `common/commentDeleteModal.html`
- `issue/view.html`
- `static/javascripts/common/yona.Tasklist.js`

착수 시 이 11개(board/edit 제외)를 Playwright(또는 브라우저)로 하나씩 실제 액션을 수행해
403/400 등이 완전히 사라지는지 확인할 것 — 전역 수정으로 이미 해소됐을 가능성이 높지만,
board/edit처럼 CSRF와 무관한 별도 버그가 같은 핸들러에 숨어 있을 수 있으므로 "전역 수정
했으니 끝"으로 단정하지 않는다.

## 완료 로그

### 2026-09-10

전역 `$.ajaxSetup` + meta 태그 방식으로 근본 수정 완료. `_csrf?.token` 안전 내비게이션 정정
(전체 스위트 6512건 중 13개 스펙 NPE 발견·수정). `LogoutCsrfIntegrationSpec`의 `maskCsrfToken`
헬퍼가 새 meta 태그의 동적 토큰 값도 마스킹하도록 확장(안 그러면 매 요청 다른 난수라 비교
실패). 신규 `GlobalCsrfAjaxHeaderTemplateEquivalenceSpec`(meta 태그 렌더링 + ajaxSetup 스크립트
로드 마크업 계약)로 회귀 방지. board/edit 저장을 Playwright로 실제 end-to-end 재검증(로그인→
프로젝트 생성→게시글 생성→수정→저장→제목 변경 반영 확인)해 완전히 동작함을 확인. 이 과정에서
발견한 별도 버그(`$("#body")` 잘못된 셀렉터)도 함께 수정.

전체 회귀 스위트(`./gradlew test -Dyona.it.db=h2 --rerun-tasks`, 캐시 무시 강제 재실행 —
직전 시도가 데몬 강제 종료 여파로 아무것도 재실행하지 않은 채 거짓 성공(exit 0)을 낸 것을
결과 파일 타임스탬프로 잡아내고 재실행) **6513건 전부 통과, 실패 0건, 에러 0건** 확인
(`build/test-results/test/*.xml` 418개 파일이 실행 시각 이후로 실제 갱신됐음을 직접 대조해
확인 — 단순 exit code만 보지 않음). 나머지 11개 화면의 개별 브라우저 재현은 후속 세션 과제로
남김.
