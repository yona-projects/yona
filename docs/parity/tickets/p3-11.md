# P3-11: 새 프로젝트 기본 브랜치를 "main"으로 결정론적 고정 (2026-08-31 사용자 요청, TDD로 완료)

## 원본 표 정보

- **우선순위 구분**: P3
- **상태(원본 체크박스)**: `[x]`
- **비고(원문)**: [원본에 있던 추가 열(섹션 헤더는 3열인데 이 행은 4열)]
  - (원본 열 3) yona 동치성과 무관 — legacy도 "main" 컨벤션이 없던 2013~2017년대 코드라 이 항목의 대상 자체가 아님
  
  **완료** — 기존엔 `GitRepository.create()`가 `Git.init()`을 브랜치명 지정 없이 호출해, JGit이 서버 머신의 전역 git 설정(`init.defaultBranch`)을 그대로 따르는 구조였음(`GitRepositorySpec.kt`의 `defaultBranchRef` 프로브 주석에 이미 문서화돼 있던 사실 — 이 환경은 `init.defaultBranch` 미설정이라 git 자체의 옛 기본값 "master"로 떨어짐). `GitRepository`/`BareCommit`에 `defaultBranch` 생성자 인자(기본값 "main", 하드코딩 리터럴도 "master"→"main"으로 전환)를 추가하고 `Git.init().setInitialBranch(defaultBranch)`로 결정론적으로 고정. `RepositoryService`가 `yona.git.default-branch`(env `YONA_GIT_DEFAULT_BRANCH`, 기본값 "main") 설정값을 읽어 `GitRepository`에 전달 — 사용자가 배포 환경변수로 재정의 가능. `BareCommit`도 같은 값을 따라야 함을 확인: 새 저장소(HEAD가 아직 커밋 없는 `refs/heads/main`)에 `setRefName()` 없이 커밋하는 경로(BoardViewController의 README/ISSUE_TEMPLATE 생성)가 여전히 구버전 기본값("master")으로 커밋하면 main은 계속 비어있고 별도 고아 브랜치 master만 생기는 불일치가 발생함을 확인해 함께 수정. 파라미터 순서는 신규 `defaultBranch`를 각각 `userResolver`/기존 3-인자 뒤에 이어 붙여, `GitRepository(a,b,c,userResolver)`/`BareCommit(project,user,gitBaseDir)` 형태의 기존 호출부(테스트 90여 곳 포함) 전부 무변경으로 유지. 테스트: `GitRepositorySpec.kt`+1, `BareCommitSpec.kt`+1(RED 확인 후 GREEN), 기존 하드코딩된 "refs/heads/master" 기대값 2곳(레거시 3-인자 오버로드 테스트, TREE 파일모드 테스트의 `seedInitialCommit` 시드 브랜치명)을 "main"으로 갱신. 전체 스위트(5672건) 재확인, 무관한 기존 실패 3건(`PullRequestListTemplateEquivalenceSpec` 2건, `SvnControllerOptionsIntegrationSpec` 1건 — `git stash`로 이 변경 적용 전 기준선에서도 동일하게 실패함을 직접 재현해 무관함을 확인) 제외 전부 GREEN
