## 완료 로그 (원문, `PARITY_BACKLOG.md`의 "완료 로그" 섹션에서 이관)

- **2026-08-21 — P0-22**: 이슈/마일스톤/게시글 신규 생성 시 임시 업로드 첨부파일을 소유권 검증 없이 그대로 재배선하던 보안 결함 수정.
  - Serena LSP로 yona `Attachment.java:173-185 moveOnlySelected(from, to, selectedFileIds)`를 재확인 — 선택된 첨부파일 ID 각각에 대해 `attachment.containerId==from.getId() && attachment.containerType==from.getType()`(원래 있던 곳이 맞는지)를 만족해야만(또는 사이트매니저) 옮긴다는 걸 확인. `from`은 항상 `UserApp.currentUser().asResource()`(`ResourceType.USER`+업로더 id) — 즉 임시 업로드 자체가 업로더별로 분리된 컨테이너에 저장됨.
  - yona `AttachmentServiceImpl.moveOnlySelected()`(컨테이너 일치 검사 자체는 이미 구현돼 있었음)를 Serena `find_referencing_symbols`/`search_for_pattern`으로 전수 조사한 결과 **어디서도 호출되지 않고 있었음**을 확인 — 대신 `IssueViewController.createIssue`/`MilestoneViewController.createMilestone`/`MilestoneViewController.editMilestone`/`BoardViewController.createPost` 4곳이 각자 `attachmentRepository.findById(fileId).ifPresent { attachment.containerType = ...; attachment.containerId = ...; save() }`로 검증 없이 직접 재배선하고 있어, 로그인한 임의 사용자가 다른 사람의 업로드/이미 다른 리소스에 붙은 첨부파일 ID를 추측해 자신의 새 이슈·마일스톤·게시글에 강제로 붙일 수 있는 상태였음.
  - **아키텍처 차이 반영**: yona는 임시 업로드를 `ResourceType.USER`+업로더id 컨테이너에 저장해 컨테이너 자체가 업로더별로 분리되지만, yona는 모든 임시 업로드가 `ResourceType.NOT_A_RESOURCE`+`""`라는 공용 컨테이너를 공유하고 대신 별도 `ownerLoginId` 필드로 업로더를 기록한다(`AttachmentController.uploadFile()` 기존 구현) — 따라서 yona에서는 컨테이너 일치 검사만으로는 업로더를 구분할 수 없어, `moveOnlySelected()`에 `moverLoginId: String` 파라미터를 추가하고 `attachment.ownerLoginId == moverLoginId` 검사를 컨테이너 일치 검사와 함께(AND) 요구하도록 확장(호출부가 이전까지 전무해 시그니처 변경에 따른 파급 없음).
  - 4개 호출부를 전부 안전한 `attachmentService.moveOnlySelected(fromType=NOT_A_RESOURCE, fromId="", toType=..., toId=..., selectedIds=fileIds, moverLoginId=loginUser.loginId)` 호출로 교체, `AttachmentService`를 3개 컨트롤러(IssueViewController/MilestoneViewController/BoardViewController) 생성자에 신규 주입.
  - 테스트: `AttachmentServiceSpec.kt` +3(본인 업로드 첨부만 이동/다른 사용자 업로드분은 ownerLoginId 불일치로 거부/이미 다른 컨테이너에 붙은 첨부는 from 불일치로 거부, 전부 실제 DB 대상 통합테스트), `IssueViewControllerSpec.kt`/`BoardViewControllerSpec.kt` 기존 테스트를 `moveOnlySelected` 위임 검증으로 갱신, `MilestoneViewControllerSpec.kt` +1(신규, createMilestone 경로 위임 검증).
  - 검증: 관련 스펙 전부 개별 통과 확인 후 `./gradlew test` 전체 통과(회귀 없음 확인).
