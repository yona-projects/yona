# P3-66: 이슈 공유자(Sharer) 입력이 검색형 위젯이 아니라 순수 텍스트 입력으로 퇴화

## 배경

`service/yona.issue.Sharer.js` 파일 상단(7~14행)에는 이미 다음 코멘트가 있다:

> P3-46 #5: Select2(v3) -> Tom Select 교체.
> 범위 밖 발견: yonaIssueSharerModule(...)는 어느 템플릿에서도 호출되지 않고, 이 파일 자체도
> `<script src>`로 로드된 적이 없다 — `#issueSharer`(issue/view.html) input은 현재 순수
> 텍스트 입력일 뿐이며 이 모듈은 완전한 죽은 코드다. ... 원본의 malformed 템플릿(닫히지 않은
> div, 아바타/로그인id 미표시)도 "완전히 일치" 원칙에 따라 그대로 보존했다.

이번 조사는 이 발견을 legacy/백엔드와 교차 검증해 실제 착수 난이도를 확정하기 위해 진행했다.

## legacy 상태

이슈 공유(sharer) 기능 자체는 legacy v1.6.1에는 없었다(당시 `issue/view.scala.html`에 sharer
관련 마크업 0건 — 나중에 추가된 기능). 최신 legacy(HEAD)의 `app/views/issue/view.scala.html`에는:

```scala
// 257행: hidden input(TomSelect류 위젯이 강화 대상으로 삼는 값 저장소)
<input type="hidden" class="bigdrop width100p" id="issueSharer" name="issueSharer" ...>

// 495행: 스크립트 로드
<script type="text/javascript" src="@routes.Assets.at("javascripts/service/yona.issue.Sharer.js")"></script>

// 546~551행: 초기화 호출
yonaIssueSharerModule(
    "@api.routes.IssueApi.findSharerByloginIds(project.owner, project.name, issue.getNumber)",
    "@api.routes.IssueApi.findSharableUsers(project.owner, project.name, issue.getNumber)",
    "@api.routes.IssueApi.updateSharer(project.owner, project.name, issue.getNumber)",
    "@Messages("issue.sharer")"
);
```

즉 legacy에서는 실제로 동작하는, 검색 가능한 멀티셀렉트 위젯이다(malformed 렌더링 디테일은
있지만 기능은 살아있음).

## 현재 yona 상태 (격차 확정 — 백엔드는 이미 준비돼 있음)

- `src/main/resources/templates/issue/view.html`(456행)의 `#issueSharer`는
  `type="text"`(순수 텍스트 입력)일 뿐, hidden input도 TomSelect 강화도 없다.
- **백엔드 API는 legacy와 1:1로 이미 존재한다** — `IssueShareController.kt`에
  `GET /-_-api/v1/owners/{owner}/projects/{projectName}/issues/{number}/findSharer`(94행),
  `GET .../sharableUsers`(111행), `POST .../share`(123행)가 모두 구현돼 있다(legacy
  `conf/routes`의 `findSharerByloginIds`/`findSharableUsers`/`updateSharer`와 정확히 대응).
- `service/yona.issue.Sharer.js`도 이미 TomSelect 기반으로 완전히 이식돼 있다(P3-46 #5).
- **즉 백엔드·프론트 로직 모두 준비된 상태에서, `issue/view.html`에 `<script src>` 추가 +
  `yonaIssueSharerModule(...)` 초기화 호출 + `#issueSharer`를 hidden input으로 되돌리는
  마킹 작업만 빠져있다.** 세 티켓(P3-63/64/65) 중 착수 난이도가 가장 낮다.

## 제안

이 티켓은 순수 조사 산출물이며 구현은 하지 않았다(사용자 지시로 백로그 등록만 완료). 착수 시:

1. `issue/view.html`의 `#issueSharer`를 `type="text"`에서 legacy와 동일한 hidden input +
   TomSelect 강화 대상으로 되돌린다(마크업은 `yona.issue.Sharer.js`가 이미 malformed 디테일까지
   legacy와 동치로 재현해뒀으므로, 그 결과물에 맞춰 마크업만 조정).
2. `<script src="/javascripts/service/yona.issue.Sharer.js">`를 추가하고, Thymeleaf
   `@{...}` 문법으로 `IssueShareController`의 3개 엔드포인트 URL을 만들어
   `yonaIssueSharerModule(...)`를 호출한다(P3-46 #5 당시 함께 이식된 `yona.issue.Assginee.js`
   초기화 패턴을 그대로 참고 가능 — 같은 화면에서 이미 동작 중).
3. TDD로 "이슈 상세 화면에 `yona.issue.Sharer.js` 스크립트 태그와 초기화 호출이 존재한다"는
   템플릿 렌더링 스펙을 먼저 세우고, Playwright로 실제 검색·추가·제거 동작을 1회 확인한다.

## 해결 (2026-09-12)

`issue/view.html`의 `#issueSharer`를 `type="text"`에서 legacy와 동일한
`type="hidden" class="bigdrop width100p"`로 되돌리고, `<script src="/javascripts/service/yona.issue.Sharer.js">`를
`yona.issue.Assginee.js` 바로 다음에 추가했다. 초기화 호출은 `yonaAssgineeModule(...)` 초기화와
동일한 패턴(별도 `<script th:if="${isAllowedUpdate}">` 태그로 분리 — 본문 스크립트는 raw text라
th:block 중첩이 안 되는 문제를 이미 그 방식으로 우회해뒀음)으로
`yonaIssueSharerModule(findSharerUrl, sharableUsersUrl, updateSharerUrl, message)`를
호출하도록 추가했다. 3개 URL은 Thymeleaf `@{...}`로 `IssueShareController`의 실제 엔드포인트
(`GET .../findSharer`, `GET .../sharableUsers`, `POST .../share`)를 가리킨다.

- 테스트: `src/test/kotlin/com/github/yonaprojects/yona/web/IssueSharerWidgetWiringTemplateRenderingSpec.kt`
  (신규, RED→GREEN). 기존 `SelectWidgetTemplateEquivalenceSpec.kt`의 "#issueSharer는 죽은 코드"
  전제 단언(스크립트 미로드 검증)도 이번 배선에 맞게 갱신했다(hidden input + 스크립트 로드
  검증으로 교체).
- 변경 파일: `src/main/resources/templates/issue/view.html`,
  `src/test/kotlin/com/github/yonaprojects/yona/web/SelectWidgetTemplateEquivalenceSpec.kt`
- Playwright 실측: 매니저 권한으로 이슈 상세 화면 진입 → 공유자 입력에 로그인id 일부를 타이핑해
  검색 결과가 뜨는지, 항목을 추가/제거하면 공유자 목록/카운트가 갱신되는지 확인.
