## 완료 로그 (원문, `PARITY_BACKLOG.md`의 "완료 로그" 섹션에서 이관)

- **2026-08-20 — P1-46**: git push(NEW_COMMIT) 알림 메일이 여전히 발송되지 않던 문제 수정. [[tickets/p1-25|P1-25]]에서 웹훅은 고쳤지만 `processCommitsNotification`이 만드는 `NotificationEvent`는 `receivers`가 항상 빈 채로 저장만 되고 `eventPublisher.publishEvent()`도 호출되지 않아, `NotificationMailEventListener`([[tickets/p0-01|P0-01]])가 이 이벤트를 구독할 기회 자체가 없었다.
  - `GitPostReceiveEventListener`에 `WatchService`/`ApplicationEventPublisher`를 신규 주입. `processCommitsNotification`에서 `WatchService.findActualWatchers(baseWatchers=emptySet(), resourceType=PROJECT, resourceId=project.id, projectId=project.id, eventType=NEW_COMMIT)`로 프로젝트 워처를 계산해 `receivers`에 채우고(발신자 본인은 기존 다른 리스너들과 동일한 관례로 제외), `notificationEventRepository.save()` 이후 `eventPublisher.publishEvent(notificationEvent)`를 호출.
  - 테스트: `GitPostReceiveEventListenerSpec.kt` +1 test(워처가 수신자로 계산되고 발신자 본인은 제외된 채 이벤트가 publish됨). 기존 테스트들도 `watchService.findActualWatchers(...)`가 빈 집합을 반환하도록 `beforeTest`에 기본 스텁을 추가해 회귀 없이 통과. 인접 회귀: `domain/event/*`, `domain/notification/*`, `YonaApplicationTests` 전체 재실행 통과.
  - 검증: `./gradlew compileKotlin compileTestKotlin`, `./gradlew test --tests "com.github.yonaprojects.yona.domain.event.*" --tests "com.github.yonaprojects.yona.domain.notification.*" --tests "com.github.yonaprojects.yona.YonaApplicationTests"` 모두 통과.
