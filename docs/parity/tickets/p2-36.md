## 완료 로그 (원문, `PARITY_BACKLOG.md`의 "완료 로그" 섹션에서 이관)

- **2026-08-22 — P2-36**: yona `Webhook.java`의 Posting(게시글) 이벤트 오버로드(279-317행)에만 유일하게 `DETAIL_SLACK` 전용 분기가 없어(다른 모든 리소스 타입은 `if (webhookType == DETAIL_SLACK) { attachments 생성 }` 분기를 가짐) SLACK 웹훅이어도 attachments 없이 평문 텍스트만 보내는데, yona `WebhookServiceImpl.buildPayload()`는 리소스 타입 구분 없이 `webhookType`만으로 분기해 Posting도 다른 타입과 동일하게 attachments를 붙이던 편차 수정.
  - `buildPayload()`의 `DETAIL_SLACK` 분기에 `if (resource !is Posting) { attachments 생성 }` 가드 추가 — Posting이면 다른 타입과 동일한 코드 경로(`root.put("text", textMessage)`만 있는 JSON)로 떨어진다.
  - `buildAttachmentJSON()`의 `when`에서 이제 도달 불가능해진 `is Posting -> text = resource.body ?: ""` 분기 제거(이 함수의 유일한 호출부가 Posting을 배제하므로 죽은 코드 — legacy에도 애초에 Posting용 `buildXxxDetails()`가 없어 이 분기 자체가 legacy에 없던 편법이었음).
  - 테스트(TDD, 레드 확인 후 그린): `WebhookServiceSpec.kt`에 "Posting은 SLACK 웹훅이어도 attachments 없이 텍스트만 보내야 한다" 1 test 신규(`payload`에 `attachments` 키 자체가 없음을 확인). 기존 CommitComment DETAIL_SLACK 테스트(attachments 있음을 전제)는 Posting이 아니라서 영향 없음을 재확인.
  - 검증: `./gradlew test --tests "com.github.yonaprojects.yona.domain.webhook.WebhookServiceSpec"` 전체 통과, 전체 스위트 `./gradlew test` 통과(실패 0).
