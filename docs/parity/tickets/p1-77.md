## 완료 로그 (원문, `PARITY_BACKLOG.md`의 "완료 로그" 섹션에서 이관)

- **2026-08-20 — P1-77**: 회원가입 관리자 승인 대기(signup.require.admin.confirm) 정책 이식.
  - `AuthController`에 `@Value("\${yona.signup.require-admin-confirm:false}")` 설정 추가(기존 `allowed-email-domains`와 동일한 패턴).
  - `signup()`에서 이 설정이 켜져 있으면 `user.state = UserState.LOCKED`로 생성하고 `/users/loginform?signupRequested`로, 꺼져 있으면(기본값) 기존과 동일하게 `ACTIVE`+`?signupSuccess`로 분기.
  - **로그인 시 LOCKED 계정 차단 자체는 이미 구현돼 있어 추가 작업 불필요** — `YonaAuthenticationProvider.checkAccountState()`([[tickets/p0-13|P0-13]])가 `signup.require.admin.confirm` 설정과 무관하게 LOCKED 계정을 항상 `LockedException`으로 차단하고 있음을 확인. yona는 이 설정이 켜졌을 때만 LOCKED를 로그인 시점에 별도 체크하는 구조(`isUsingSignUpConfirm()` 가드)지만, yona는 이미 더 넓게(설정과 무관하게 항상) 차단하고 있어 관찰 가능한 동작은 상위 호환으로 동일 — 이 부분은 정말 빠진 게 가입 시점의 초기 상태 결정뿐이었다.
  - 테스트: `AuthControllerSpec.kt` +2(설정 켜져 있으면 LOCKED로 생성+승인 대기 리다이렉트/기본값이면 ACTIVE로 생성+기존과 동일). 기존 `AuthController(...)` 생성자 호출 2곳에 세 번째 인자 추가.
  - 검증: `./gradlew compileKotlin compileTestKotlin`, `AuthControllerSpec` 11 tests 전체 통과.
