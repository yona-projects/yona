# P3-25: hg4j `Wire1CommandsCoverageTest`의 기존 flaky 실패(빈 저장소 changegroup) 근본 수정

## 배경

`Wire1CommandsCoverageTest.changegroupOnAnEmptyRepositoryReturnsAnEmptyStream`이 여러 세션에
걸쳐 hg4j 전체 테스트 스위트 실행 시 계속 실패해왔다(P3-12/P3-19 세션 모두에서 관찰,
이번 세션 변경들과는 무관함을 `git stash`로 베이스라인에서도 동일 재현되는 것으로 확인
완료). "실사용에 영향 없다"고 판단해 계속 보류해왔으나, 사용자 지시로 근본 원인을 찾아
정확히 고친다.

## 범위

1. 실패 원인을 정확히 진단한다 — 테스트 이름대로 "빈 저장소에서 changegroup 명령이 빈
   스트림을 반환해야 하는데" 실제로는 무엇을 반환하는지, 어느 assertion이 왜 실패하는지
   직접 실행해서 확인(`./gradlew test --tests "*Wire1CommandsCoverageTest*" -x
   jacocoTestReport`).
2. 진짜 버그(assertion이 맞고 프로덕션 코드가 틀림)인지, 테스트 자체의 결함(assertion이
   틀렸거나 flaky한 전제 — 예를 들어 이번 세션에서 고친 `HgLocalClient.getBundle()`의
   빈 저장소 처리 방식이 바뀌면서 이 테스트의 기대값이 낡았을 가능성도 확인)인지 판별한다.
3. 근본 원인에 맞게 프로덕션 코드 또는 테스트(기대값이 실제로 낡았다면 테스트 쪽)를 고친다 —
   "그냥 assertion을 실제 출력에 맞춰 바꾼다"는 식으로 얼버무리지 말고, 왜 그 값이 나오는
   게 옳은지 근거를 남길 것(다른 관련 테스트들 — 이번 세션에서 추가한
   `HgHttpWireServerEmptyRepoRealHgInteropTest` 등 — 과 일치하는 결론이어야 한다. 만약
   불일치하면 그 자체가 추가로 파고들 신호다).
4. hg4j 전체 스위트를 재실행해 이 수정이 다른 테스트를 깨지 않는지 확인.

## 완료 기준

- `Wire1CommandsCoverageTest` 포함 hg4j 전체 스위트가 GREEN(현재 알려진 유일한 실패였던
  이 테스트까지 포함해 0 failures).

## 완료 로그

(2026-09-09) 착수 및 완료. 커밋: `hg4j@5f9b640`, `origin/main`에 push 완료.

**근본 원인**: 진짜 프로덕션 버그가 아니라 테스트 자체의 낡은 기대값이었다. 이 테스트는
원래 `HgLocalClient.getBundle()`이 빈 저장소에서 `new byte[0]`을 그대로 반환하던 버그
(이번 세션 초반에 이미 발견·수정 완료, `llm-wiki/known-bugs-registry.md` 참고)를
검증하던 것이었는데, 그 버그가 고쳐진 뒤 실제 응답이 "올바르게 형식을 갖춘 빈
changegroup"(터미네이터 청크만 있는 유효한 cg1 스트림)으로 바뀌면서 `assertEquals(0,
r.getPayload().length)`이 더 이상 맞지 않게 됐다. `HgHttpWireServerEmptyRepoRealHgInteropTest`
(실제 hg CLI 기반)가 이미 같은 결론(빈 저장소 clone/pull이 실제로는 정상 동작)을 검증하고
있어 일치를 확인했다.

**수정**: 테스트명을 `changegroupOnAnEmptyRepositoryReturnsAWellFormedEmptyStream`으로
바꾸고, `ChangegroupParser.parseBundle()`로 실제 페이로드를 파싱해 changelog/manifest/
file 엔트리가 전부 0개인 "올바르게 파싱되는 빈 changegroup"인지 검증하도록 수정
(`HgLocalClientCoverageTest`가 `HgLocalClient.getBundle()`의 동일 케이스를 검증하는
방식과 동일). 근거를 테스트 코드 자체의 javadoc 주석에 상세히 남겼다.

**테스트 결과**: `./gradlew test -x jacocoTestReport`(전체 스위트, 2309개) →
`BUILD SUCCESSFUL`, 0 failures/errors — 지금까지 알려진 유일한 실패였던 이 테스트까지
포함해 전부 GREEN.
