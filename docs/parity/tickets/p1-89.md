## 완료 로그 (원문, `PARITY_BACKLOG.md`의 "완료 로그" 섹션에서 이관)

- **2026-08-20 — P1-89**: `WatchController`의 4개 감시(watch)/알림토글 엔드포인트(`checkWatchPermission`/`watchProject`/`unwatchProject`/`toggleProjectNotification`)가 전부 WATCH 연산에 READ 규칙(`accessControl.isAllowedToReadProject`, `!isGuest` 요구)을 잘못 재사용하던 회귀 버그 수정. legacy WATCH 규칙(`AccessControl.java:293-296`, `isPublic() && !isAnonymous() || isMemberOf || isAdmin || isAllowedIfGroupMember`)은 게스트는 허용하고 순수 익명만 배제하는데, READ 규칙을 재사용하면서 게스트 계정의 PUBLIC 프로젝트 감시 등록/해제까지 부당하게 차단하고 있었다.
  - 4개 호출부 전부 `accessControl.isAllowedToReadProject(user, project)` → `accessControl.isAllowed(user, project, Operation.WATCH)`([[tickets/p1-85|P1-85]] 1b 신규 오버로드)로 교체. `WatchController`는 이미 `getLoginUser()`에서 미인증 시 401을 먼저 던지므로 `user`는 항상 non-null이라 순수 익명 차단은 이미 보장돼 있었고, 이번 수정으로 게스트만 부당하게 막던 부분이 바로잡혔다.
  - 테스트: `WatchControllerSpec.kt`의 기존 스텁 6곳을 `isAllowedToReadProject` → `isAllowed(user, project, Operation.WATCH)`로 갱신(교체 전 스텁 불일치로 MockKException 발생 확인 후 수정 — 사실상 회귀 검증 역할을 했다). WATCH의 게스트 허용 자체는 `AccessControlSpec.kt`([[tickets/p1-85|P1-85]] 1b)에서 이미 전담 검증 중이라 중복 테스트는 추가하지 않음.
  - 검증: `./gradlew test --tests "WatchControllerSpec"` 10 tests 전체 통과, `./gradlew compileKotlin compileTestKotlin` 전체 컴파일 성공.
