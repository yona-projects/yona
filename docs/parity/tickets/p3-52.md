# P3-52: legacy가 로드하던 일부 스크립트가 포팅본에 로드되지 않아 생긴 기능 격차 묶음
(script src 존재 여부 전수 대조 결과)

## 배경

이번 세션의 Twirl-vs-Thymeleaf 렌더링 감사(카테고리 C)에서, `origin/v1.6`의 242개 legacy
뷰가 로드하는 `<script src="@routes.Assets.at("javascripts/...")">` 목록과 현재 포팅본의
`<script src="/javascripts/...">` 목록을 1차 자산 파일(third-party 라이브러리 제외) 기준으로
전수 대조했다. 대부분(예: `yobi.CodeCommentBlock.js`/`yobi.CodeCommentBox.js`/
`yobi.Interval.js`/`yona.Sha1.js`/`yona.SubComment.js`/`yona.CommentAttachmentsUpdate.js`
[[tickets/p3-50|P3-50으로 이미 분리]]/`yona.issue.Sharer.js`[이미 알려진 죽은 코드])는
현재 페이지가 다른 방식으로 이미 기능을 재구현했거나 원래도 죽은 코드였던 걸로 확인됐다 —
**아래 항목만 실제 기능 격차로 남는다.**

## 발견된 실제 격차

1. **`common/yona.ReceiverList.js` 미로드** — 이슈/게시글 댓글 작성 중 "누구에게 알림이
   갈지" 미리보기 목록을 디바운스 AJAX로 실시간 갱신하는 기능. legacy `issue/view.scala.html`이
   로드하지만 현재 `issue/view.html`에 대응 기능이 없다.
2. **`service/yona.detectChange.js` 미로드** — 이슈 상세 화면에서 주기적으로 폴링해 본문/댓글
   수가 바뀌었는지 감지하고 사용자에게 알려주는(새로고침 유도) 기능. legacy `issue/view.scala.html`
   전용, 현재 포팅본에 폴링 로직 자체가 없다. 보안과 무관한 경미한 UX 기능.
3. **`common/yobi.CommentForm.js` 미로드** — 댓글 작성 폼 공용 가드: 빈 값 제출 방지,
   Ctrl+Shift+Enter 단축 제출, 페이지 이탈 시 작성 중인 내용 경고(beforeunload), 그리고
   **localStorage 기반 임시 저장(초안 자동저장/복구)**. `common/commentForm.html`(광범위하게
   include되는 공용 프래그먼트)에 대응 기능이 없다 — 사용자가 댓글을 쓰다가 실수로 페이지를
   벗어나면 작성 중이던 내용이 경고 없이 그냥 사라진다.
4. **PR 코드 리뷰 화면의 "새 인라인 댓글 작성 UI" 자체가 없어 보임** — `yobi.CodeCommentBox.js`/
   `yobi.CodeCommentBlock.js`가 담당하던 "diff 줄 클릭 → 그 줄에 댓글 작성 폼 즉시 삽입" UX가
   `code/diff.html`에는 인라인 vanilla JS(`.add-comment-btn-cell`)로 재구현돼 있지만,
   **`pullrequest/*.html`(PR 코드 리뷰 diff 화면)에는 같은 패턴이 보이지 않는다** — 기존
   리뷰 스레드는 서버사이드 렌더링으로 잘 보이는데(`partial_diff_comment_on_line.html`),
   새 리뷰 스레드를 "시작"하는 클릭 UI가 확인되지 않았다. **이 항목은 스캔 단계에서 코드
   재구현 여부를 100% 확인하지 못했다 — 착수 전 재확인 필요**(가장 우선순위 높게 재조사할
   항목, PR 코드 리뷰라는 핵심 기능이라 실재한다면 영향이 크다).

## 제안하는 다음 단계

우선순위 제안: 4번(PR 인라인 코드 리뷰 댓글 작성 UI 실재 여부)을 가장 먼저 재확인 — 실제
사용자 시나리오로 PR diff 화면에서 특정 줄에 댓글을 달아보는 실사용 검증부터. 실재하는
기능 격차로 확인되면 이 항목만 별도 상위 우선순위 티켓으로 분리해야 할 만큼 크다. 1~3번은
각각 독립적인 프론트엔드 작업(디바운스 AJAX 미리보기 / 폴링 / localStorage 초안 자동저장)이라
TDD로 각각 테스트를 먼저 작성한 뒤 순서대로 진행.

### 항목4 조사 결론 (착수 전 재확인 대상이었음)

### 항목3 구현 (`common/yobi.CommentForm.js` 대응 — 빈값 제출 방지/단축 제출/이탈 경고/임시저장)

**설계 결정(코디네이터 확인 완료, 옵션 A 채택)**: `yobi.CommentForm.js`를 그대로
`<script src>`로 로드하지 않았다 — 그 파일의 `onSubmitCommentForm`은 `event.preventDefault()`
후 300ms 뒤 실제 네이티브 `form.submit()`을 다시 스케줄링하는데, `#comment-form`은 이미
P3-48/50에서 검증된 AJAX 제출 핸들러(`$(document).on('submit', '#comment-form', ...)`)로
전환돼 있어 그 흐름과 공존시키면 이중 제출(AJAX 요청 하나 + 300ms 뒤 진짜 페이지 이동 하나)이
난다. 대신 이미 검증된 AJAX 핸들러 쪽에 4가지 기능을 직접 재구현했다. `yobi.CommentForm.js`
파일 자체는 삭제하지 않고 계속 미참조 상태로 남겨둔다(코디네이터 결정 — 다른 정리는 별도
티켓에서 다룸).

- `src/main/resources/templates/issue/view.html`, `board/view.html` (`#comment-form` 둘 다):
  - 빈 값 제출 방지: 제출 시 `contents.trim()`이 비어있으면 `$yobi.notify('post.comment.empty'
    root 값, 3000)`을 띄우고 AJAX 자체를 보내지 않음.
  - Ctrl(⌘)+Shift+Enter 단축 제출.
  - beforeunload 이탈 경고: 내용이 비어있지 않고 아직 제출 중이 아니면
    `common.comment.beforeunload.confirm` 메시지로 경고.
  - localStorage 임시저장: 이미 다른 모든 작성 화면(이슈/게시글/마일스톤/PR 본문 등)에서 실제로
    쓰이고 있는 전역 `temporarySaveHandler`/`removeCurrentPageTemprarySavedContent`
    (`service/yona.temporarySaveHandler.js`, yona-lib.js 번들 사본으로 이미 로드돼 활성 상태)를
    그대로 재사용 — 새 코드를 만들지 않고 기존 검증된 메커니즘에 얹었다.
  - **EasyMDE/CodeMirror 재배선 함정(재발견, P3-50과 동일 패턴)**: `markdownEditor` fragment는
    textarea를 EasyMDE(CodeMirror)로 감싸 실제 화면에 보이는 입력 표면이 원본 textarea가 아닌
    별도 DOM이 된다. Ctrl+Shift+Enter를 원본(숨겨진) textarea에 `keydown`으로 직접 바인딩하면
    실제 타이핑 중에는 절대 발생하지 않는다(Playwright로 실제 타이핑 재현 중 발견 — 최초 구현은
    MockMvc 템플릿 검증만 GREEN이고 실브라우저에서는 단축키가 전혀 동작하지 않았음). 수정:
    `document` 레벨에서 keydown을 캡처해 `document.activeElement`가 그 `#comment-form` 안에
    있을 때만(=CodeMirror를 포함한 폼 내부 어디를 포커스하고 있어도) 반응하도록 재배선했다.
    이 패턴은 P3-46 3단계(멘션-CodeMirror 연동)에도 재사용 가능하다는 메모를 남긴다.
  - **인라인 `<script>` 수동 따옴표 버그(발견 즉시 수정)**: 이 두 파일의 스크립트 블록은
    `th:inline="javascript"`가 없어(파일 관례상 필요한 곳만 직접 따옴표로 감싸는 방식)
    `return [[#{...}]];`처럼 따옴표 없이 메시지 키를 인라인하면 그 문구가 그대로(따옴표 없이)
    JS에 삽입돼 `Unexpected identifier` 구문 오류가 났다 — Playwright의 `pageerror` 리스너로
    실제 재현해서 발견했고(MockMvc는 JS를 실행하지 않아 이 클래스의 버그를 못 잡음),
    `'[[#{...}]]'`처럼 직접 따옴표로 감싸 수정했다.
