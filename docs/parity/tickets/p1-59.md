## 완료 로그 (원문, `PARITY_BACKLOG.md`의 "완료 로그" 섹션에서 이관)

- **2026-08-20 — P1-59**: 메일 답장으로 만든 코드리뷰/커밋 댓글의 첨부파일·cid 인라인 이미지가 저장/치환되지 않던 결손 수정. yona `saveReviewComment()`는 `saveAttachments(content.attachments, comment.asResource())` — 첨부는 스레드가 아니라 새로 생성된 댓글 자신(`ReviewComment.asResource()` == `REVIEW_COMMENT`+comment.id)에 붙는다.
  - `attachAttachments()`의 `when (outcome)`에 `ReviewCommentCreated -> ResourceType.REVIEW_COMMENT to outcome.commentId.toString()`, `CommitCommentCreated -> ResourceType.COMMIT_COMMENT to outcome.commentId.toString()` 케이스 추가(스레드 id가 아니라 새로 생성된 댓글 자신의 id를 리소스 id로 사용 — yona `comment.asResource()`와 동일한 지점). yona는 커밋 댓글에 별도 `CommitComment` 엔티티가 있어([[tickets/p0-16|P0-16]], yona에는 없는 구조) `COMMIT_COMMENT`로 매핑했는데, 이는 이미 `computeMessageId`([[tickets/p1-27|P1-27]]/[[tickets/p1-51|P1-51]])와 watcher 조회([[tickets/p1-50|P1-50]])가 써온 것과 동일한 기존 관례.
  - `postprocessHtmlBody()`에 두 케이스 추가 — `ReviewCommentRepository`(신규 주입)/`CommitCommentRepository`(기존)로 방금 생성된 댓글을 다시 조회해 `contents`의 `cid:` 참조를 치환 후 저장. `IssueCreated`/`IssueCommentCreated`/`PostingCommentCreated`와 동일한 패턴(변경 없으면 저장 안 함).
  - 테스트: `IncomingMailProcessingServiceSpec.kt` +3(코드리뷰 스레드 답장 첨부가 스레드가 아니라 새 리뷰 댓글에 연결/커밋 댓글 답장 첨부가 새 커밋 댓글에 연결/코드리뷰 스레드 답장의 HTML cid 참조가 치환돼 리뷰 댓글이 갱신) — 총 25 tests. 먼저 `when` 분기에 새 case를 추가하기 전 컴파일이 되던 상태(구현 전)에서 `attachmentService.store`가 호출되지 않음을 확인 후 구현.
  - 검증: `./gradlew compileKotlin compileTestKotlin` 전체 컴파일 성공, `./gradlew test --tests "com.github.yonaprojects.yona.domain.mail.IncomingMailProcessingServiceSpec"` 25 tests 전체 통과.
