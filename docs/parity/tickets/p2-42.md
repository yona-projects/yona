# P2-42: **(2026-08-21 [[tickets/p1-139|P1-139]] 구현 중 발견)** yona `partial_readme.scala.html:38-42`는 `!project.menuSetting.code && projectReadmePosting != null`(코드브라우저 비활성 프로젝트는 게시판 README 글의 body를 README로 사용)와 그 외(git 파일 README)를 분기하는데, yona `ProjectViewController.getReadmeContent()`는 git 저장소 파일(`README.md`)만 읽고 `Posting(readme=true)` 기반 README는 전혀 읽지 않음 — 코드브라우저를 끈 프로젝트에서 게시판으로 작성한 README가 프로젝트 홈에 노출되지 않는다

## 완료 로그 (원문, `PARITY_BACKLOG.md`의 "완료 로그" 섹션에서 이관)

- **2026-08-22 — P2-42**: 코드브라우저 메뉴를 끈(`!project.menuSetting.code`) 프로젝트에서 게시판으로 작성한 README 글(`Posting(readme=true)`)이 프로젝트 홈에 전혀 노출되지 않던 문제 수정 — yona `partial_readme.scala.html:38-42`의 분기(`!project.menuSetting.code && projectReadmePosting != null`이면 `Markdown.render(projectReadmePosting.body, project)`, 아니면 기존처럼 `Markdown.renderFileInReadme(project.readme, project)`)를 그대로 이식.
  - `ProjectViewController.projectHome()`의 `readmeHtml` 계산 로직에서, `!project.isCodeEnabled`(legacy `!menuSetting.code` 대응)일 때 `postingRepository.findByProjectAndReadme(project, true).firstOrNull()`(legacy `Posting.findREADMEPosting()`의 `finder...findUnique()`를 리스트+`firstOrNull()`로 아키텍처 번역 — Ebean의 "단일 결과 아니면 예외"라는 방어적 동작까지는 재현하지 않되 정상 케이스의 실질 동작은 동일함)로 README 글을 찾고, 있으면 `markdownService.render(posting.body, breaks=true, project)`(legacy `Markdown.render(body, project)`의 2-arg 오버로드 기본값 `breaks=true`와 동일)로 렌더링. 없으면(또는 코드브라우저가 켜져 있으면) 기존 git 파일 기반 `getReadmeContent()` + `renderFileInReadme()` 경로 그대로 유지.
  - `readmeFileName`(헤더에 표시되는 파일명, git 파일 존재 여부로 README 섹션 자체를 보여줄지 게이트하는 역할)은 legacy와 동일하게 손대지 않음 — legacy도 `project.getReadmeFileName()`을 헤더에 그대로 쓰고, `projectReadmePosting`은 본문(body) 렌더링 소스만 바꾼다.
  - 테스트(TDD, 레드 확인 후 그린): `ProjectViewControllerSpec.kt`에 2 tests 신규 — 코드브라우저 꺼진 프로젝트 + README 글 있음 → `markdownService.render(posting.body, ...)`로 렌더링되고 `renderFileInReadme`는 호출 안 됨 / 코드브라우저 꺼졌지만 README 글이 없음 → 기존처럼 git 파일(`renderFileInReadme`) 경로 유지. 기존 "코드브라우저 켜진 프로젝트" 테스트([[tickets/p1-139|P1-139]])는 `isCodeEnabled` 기본값(true)이라 영향 없음을 재확인.
  - 검증: `./gradlew test --tests "com.github.yonaprojects.yona.web.ProjectViewControllerSpec"` 전체 통과, 전체 스위트 `./gradlew test` 통과(실패 0).
