## 완료 로그 (원문, `PARITY_BACKLOG.md`의 "완료 로그" 섹션에서 이관)

- **2026-08-22 — P2-31**: `SearchType.getValue()`가 인식 불가한 값을 `SearchType.NA`로 폴백시키는데, yona `SearchApp.java`의 `searchInAll()`(56-58행)/`searchInAGroup()`(134-136행)/`searchInAProject()`(209-211행)는 이 경우 `badRequest()`를 반환하는 반면 yona `SearchController.kt`의 대응 핸들러들은 가드 없이 그대로 `searchService`에 넘겨 조용히 빈 결과 200을 반환하던 문제를 수정.
  - `searchInAll`/`searchInAGroup`에는 `searchType == SearchType.NA`, `searchInAProject`에는 legacy 원문 그대로 `searchType == SearchType.NA || searchType == SearchType.PROJECT`(프로젝트 범위 검색에서 "프로젝트를 찾는다"는 검색 타입 자체가 무의미) 가드를 `SearchType.getValue()` 호출 직후에 추가, `ResponseStatusException(HttpStatus.BAD_REQUEST)`를 던짐.
  - `searchInAGroup`은 legacy 조건의 나머지 절(`organization == null`)이 yona에서는 이미 그 앞의 `organizationRepository.findByName(...).orElseThrow{404}`로 처리되므로 중복 구현하지 않음(순서상 404가 우선하도록 가드를 그 아래에 배치). `searchInAProject`도 동일하게 기존 `projectRepository.findByOwnerAndNameOrPreviousPlace(...).orElseThrow{404}` 다음에 배치해 "프로젝트가 실제로 없을 때는 404가 우선"하는 순서를 보존.
  - 테스트(TDD, 레드 확인 후 그린): `SearchControllerSpec.kt`에 4 tests 신규 — `searchInAll`/`searchInAGroup`(canonical, `/organizations/...` alias 없이 대표 경로만) NA 폴백 400 각 1개, `searchInAProject`의 NA 폴백 400 1개 + `searchType=project` 명시 400 1개.
  - 검증: `./gradlew test --tests "com.github.yonaprojects.yona.web.SearchControllerSpec"` 전체 통과, `./gradlew compileKotlin compileTestKotlin` 전체 컴파일 성공, 전체 스위트 `./gradlew test` 통과(실패 0).
