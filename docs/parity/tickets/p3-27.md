# P3-27: Mercurial 프로젝트의 Pull Request 병합이 동작하지 않음(JGit 하드코딩)

## 배경

P3-21/P3-22 실사용 검증 중 발견. `PullRequestServiceImpl`의 `attemptMerge`/`previewMerge`/
`merge`/`updateMerge`가 전부 `FileRepositoryBuilder().setGitDir(...)`로 JGit 저장소를 직접
여는 방식으로 하드코딩돼 있어, Mercurial 프로젝트에서는 PR 병합/충돌 계산이 동작하지 않는다.

- PR **생성**은 실패가 조용히 삼켜져 겉보기엔 성공한 것처럼 보인다.
- 관련 PR 재검사(`RelatedPullRequestMergeEvent`, push 시 자동 트리거 — P3-22에서 배선 완료)는
  실제로는 `NoRemoteRepositoryException`으로 실패한다(catch돼 로그만 남고 크래시하지 않음).

이건 P3-20~26과 달리 국소적인 버그 수정이 아니라 **PR diff/merge/conflict 계산 전체를
Mercurial 대응으로 새로 설계·구현해야 하는 대규모 작업**이다(hg4j 쪽에 병합/3-way-merge에
해당하는 API가 있는지부터 확인 필요) — 그래서 P3-20~26과 함께 처리하지 않고 별도 티켓으로
분리했다. 착수 여부는 사용자 확인 필요.

## 범위 (착수 시 확정 필요)

1. `PullRequestServiceImpl`에서 JGit에 하드코딩된 지점을 전수 조사(`FileRepositoryBuilder`
   검색).
2. hg4j에 3-way merge/병합 커밋 생성에 대응하는 API가 있는지 확인(`MergeCommand`류가
   있는지, 있다면 어느 수준까지 지원하는지).
3. 없다면 hg4j에도 신규 구현이 필요할 수 있음 — 규모가 크므로 별도 설계 논의 필요.
4. diff 계산 자체는 이미 P3-12(2026-09-09)에서 `HgRepository.getDiff()`로 해결됐으므로,
   남은 건 병합 커밋 생성/충돌 감지/미리보기 로직.
