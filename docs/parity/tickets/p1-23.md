## 완료 로그 (원문, `PARITY_BACKLOG.md`의 "완료 로그" 섹션에서 이관)

- **2026-08-20 — P1-23**: `SvnAuthorizationFilter`가 yona `SvnApp`의 `AccessControl.isAllowed()` 위임 규칙 대비 두 가지가 축소돼 있던 문제 수정.
  - **PROTECTED 프로젝트 인증 누락**: 기존엔 `requiresAuth`가 `projectScope == PRIVATE`일 때만 참이라, PROTECTED(비공개 그룹 전용) 프로젝트가 PUBLIC과 똑같이 인증 없이 SVN으로 열람 가능했다. yona READ 규칙(`project.isPublic() && !user.isGuest || user.isMemberOf(project) || ... || isAllowedIfGroupMember(...)`)상 PROTECTED는 공개 프로젝트가 아니므로 멤버(또는 조직 그룹멤버)만 읽을 수 있어야 한다. `requiresAuth` 조건을 `projectScope != PUBLIC`으로 바꿔 PROTECTED도 PRIVATE와 동일하게 인증+멤버십을 요구하도록 수정. 조직 그룹멤버 우회(`isAllowedIfGroupMember`)는 이 저장소의 기존 관례(멘션 자동완성 [[tickets/p1-14|P1-14]] 등)대로 미구현.
  - **게스트 계정 차단 누락**: yona는 PUBLIC 프로젝트라도 `!user.isGuest`를 요구해 게스트 계정은 공개 저장소조차 SVN으로 못 읽지만, yona는 이 검사 자체가 없어 게스트 계정도 공개 프로젝트를 자유롭게 읽을 수 있었다. `UserRepository`를 주입해 `isGuestUser()` 헬퍼를 추가하고, "인증 불필요" 경로(PUBLIC 읽기)에서도 실제로 인증된 사용자가 있다면 게스트 여부를 확인해 게스트면 403으로 거부(완전한 익명 요청은 영향 없음, yona도 익명과 게스트를 별개로 다룸).
  - **범위를 벗어나 식별한 것([[tickets/p1-45|P1-45]]로 분리)**: `GitAuthorizationFilter`도 완전히 동일한 구조적 결함(PROTECTED 미인증 허용, 게스트 미차단)을 갖고 있으나, 이번 백로그 항목이 감사 리포트상 SVN(`SvnApp.java`)만 명시적으로 지목하고 있어 이번 패스에서는 손대지 않고 별도 항목으로 분리해 기록했다.
  - 테스트: `SvnAuthorizationFilterSpec.kt`(신규, 이전에 이 필터에 대한 테스트가 전혀 없었음 — `GitAuthorizationFilterSpec.kt`와 동일한 mockk 기반 패턴 채용) 11 tests(404, PUBLIC 읽기/쓰기, PRIVATE 읽기 비인증/비멤버/멤버, PROTECTED 읽기 비인증/비멤버/멤버, PUBLIC+게스트 거부, PUBLIC+비게스트 통과). `YonaApplicationTests`/`GitAuthorizationFilter*` 재실행으로 회귀 없음 확인(Git 쪽은 이번에 손대지 않음).
  - 검증: `./gradlew test --tests "SvnAuthorizationFilterSpec" --tests "com.github.yonaprojects.yona.config.git.*" --tests "YonaApplicationTests"` 전체 통과, `./gradlew compileKotlin compileTestKotlin` 전체 컴파일 성공.
