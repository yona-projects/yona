## 완료 로그 (원문, `PARITY_BACKLOG.md`의 "완료 로그" 섹션에서 이관)

- **2026-08-20 — P1-61**: 수신 HTML 메일 본문 처리에 yona `postprocessForHTML()`의 `HtmlCompressor` 압축 단계 추가.
  - `build.gradle.kts`에 `com.googlecode.htmlcompressor:htmlcompressor:1.4`(yona가 실제 쓰는 버전, `build.sbt` 대조로 확인) 추가.
  - **트리거 조건도 함께 정정**: 기존엔 `message.isHtml && cidAttachments.isNotEmpty()`일 때만 `postprocessHtmlBody()`를 호출해, 첨부(따라서 cid 치환 대상)가 전혀 없는 HTML 메일은 압축 자체가 시도되지 않았다 — yona `postprocessForHTML()`은 HTML 메일이면 cid 치환 결과와 무관하게 항상 압축을 수행한다(`saveComment`/`saveIssue`/`saveReviewComment` 3곳 모두 `if (ContentType.match(HTML))`만 조건). 트리거를 `message.isHtml`로만 완화하고, 대신 신규 `postprocessForHtml(html, cidAttachments): String?`가 "cid 치환 결과(없으면 원본) → HtmlCompressor 압축 → 원본과 완전히 같으면 null" 순서로 판단해 불필요한 저장을 계속 막는다(원본과 yona처럼 항상 저장하는 대신, 이 저장소가 [[tickets/p1-47|P1-47]]부터 유지해온 "변경 없으면 저장 안 함" 최적화는 그대로 보존 — 순수 효율화라 사용자가 체감할 동작 차이는 없음).
  - `IncomingMailProcessingService`에 `private val htmlCompressor = HtmlCompressor()`(yona `new HtmlCompressor()`의 기본 옵션 그대로) 필드 추가, `postprocessHtmlBody()`의 5개 리소스 타입(Issue/IssueComment/PostingComment/ReviewComment/CommitComment) 분기 전부가 `replaceCidWithAttachments()` 직접 호출 대신 `postprocessForHtml()`을 거치도록 통일.
  - 테스트: `IncomingMailProcessingServiceSpec.kt` +1(첨부가 전혀 없어도 태그 사이 개행이 압축돼 저장됨, `<p>제목</p>\n<p>본문</p>` → `<p>제목</p> <p>본문</p>` — 실제 `HtmlCompressor` 라이브러리로 직접 검증한 출력값). 기존 "cid 매칭 안 되면 저장 안 함" 테스트는 트리거 조건 완화로 `issueRepository.findById`가 이제 호출되므로 스텁 추가(이미 완전히 압축된 한 줄짜리 본문이라 결과는 여전히 미저장) — 총 29 tests.
  - 검증: `./gradlew compileKotlin compileTestKotlin` 전체 컴파일 성공, `./gradlew test --tests "com.github.yonaprojects.yona.domain.mail.IncomingMailProcessingServiceSpec"` 29 tests 전체 통과.
