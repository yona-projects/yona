## 완료 로그 (원문, `PARITY_BACKLOG.md`의 "완료 로그" 섹션에서 이관)

- **2026-08-20 — P1-21**: `WatchServiceImpl.findActualWatchers()`가 `allowedWatchersOnly` 파라미터(인터페이스 기본값 `true`, 이슈/게시글/댓글 생성 시 모든 알림 발행 경로가 이 기본값으로 호출)를 받기만 하고 실제로는 전혀 사용하지 않아, 비공개 프로젝트에 대한 읽기 권한이 없는 사용자도(예: 프로젝트에서 이미 제외됐지만 과거에 감시 등록만 남아있는 사용자) 여전히 알림 수신자에 포함되던 문제 수정(yona `Watch.findActualWatchers()`의 `AccessControl.isAllowed(watcher, resource, Operation.READ)` 필터 대응).
  - `WatchServiceImpl`에 `ProjectRepository`/`ProjectUserRepository`를 주입해 `hasReadPermission(user, projectId)` 헬퍼 추가: 사이트 관리자는 항상 통과, 프로젝트에 속하지 않은 전역 리소스(`projectId == null`)는 yona `isGlobalResourceAllowed`와 동일하게 항상 통과, 공개 프로젝트는 항상 통과, 비공개 프로젝트는 실제 프로젝트 멤버인지(`ProjectUserRepository.existsByProjectIdAndUserId`)로 판단. `allowedWatchersOnly=true`일 때만 이 필터를 적용.
  - **기존 테스트 조정(의도적, 버그를 검증하던 테스트를 실제 동작에 맞게 수정)**: `WatchServiceSpec.kt`의 기존 3개 시나리오는 PRIVATE 기본 프로젝트에서 실제 멤버십 없이 감시만 등록한 user2/user3가 알림을 받는 것을 정상으로 검증하고 있었는데, 이는 정확히 이번에 고친 버그(권한 없는 감시자도 알림을 받음)에 의존한 테스트였다. 이 스펙들은 "감시 매커니즘 자체"(watch/unwatch, 프로젝트 감시자 합류, receivers 계산)를 검증하는 게 목적이라 접근 제어와는 무관하므로, 공유 `project`를 PUBLIC으로 바꿔 권한 필터의 영향을 받지 않게 했다(PUBLIC 프로젝트는 필터를 항상 통과하므로 테스트 의도와 결과 모두 그대로 유지). 권한 필터 자체는 신규 `describe("allowedWatchersOnly 권한 필터링")` 블록에서 별도 PRIVATE 프로젝트로 명시적으로 검증.
  - 테스트: `WatchServiceSpec.kt` +2(비공개 프로젝트에서 비멤버 감시자 제외 확인, `allowedWatchersOnly=false`면 필터를 건너뛰고 전원 포함 확인) — 기존 3건(PUBLIC 프로젝트로 조정) 포함 총 5 tests. `IssueServiceSpec`/`CommentServiceSpec`/`PostingServiceSpec`/`PullRequestServiceSpec` 등 알림 발행 경로 전체와 `WatchControllerSpec`/`YonaApplicationTests` 재실행으로 회귀 없음 확인.
  - 검증: `./gradlew test --tests "WatchServiceSpec" --tests "IssueServiceSpec" --tests "CommentServiceSpec" --tests "PostingServiceSpec" --tests "com.github.yonaprojects.yona.domain.pullrequest.*" --tests "WatchControllerSpec" --tests "YonaApplicationTests"` 전체 통과, `./gradlew compileKotlin compileTestKotlin` 전체 컴파일 성공.
