# P3-58: 조직(organization) 범위 검색 결과 화면에 조직 헤더/내비게이션 메뉴가 빠져 있음

## 배경

legacy `app/views/search/result.scala.html`(33~38행)은 검색 범위가 특정 프로젝트도 아니고
조직(그룹)일 때 `organizationLayout` 데코레이터 안에서 다른 모든 조직 화면과 동일하게
`@organization.header(group)` + `@organization.menu(group)`을 호출해 조직 로고/브레드크럼/
가입요청 드롭다운과 홈·이슈·게시판·PR 탭 내비게이션을 그대로 노출한다(`project == null &&
group != null`일 때).

## 현재 yona 상태 (격차 확정)

yona의 대응 화면 `src/main/resources/templates/search/list.html`(16~22행)은 조직 스코프일
때 `organization/header`/`organization/menu` fragment를 전혀 쓰지 않고, 조직명(링크)+설명만
보여주는 즉석 `<div class="org-header">` 블록으로 대체돼 있다(`grep -n "organization"
search/list.html` 결과 0건 — fragment 재사용 자체가 없음).

결과적으로 조직 범위 검색 결과 화면에서:
- 조직 탐색 메뉴(홈/이슈/게시판/PR 탭, 관리자 설정 톱니)가 전부 사라짐
- 헤더의 로고/브레드크럼/가입요청 드롭다운도 없음
- 검색 결과에서 조직의 다른 화면(이슈 목록, 게시판 등)으로 돌아갈 내비게이션 경로가 없음

`docs/TEMPLATE_BACKLOG.md` #224~233은 `search/result.scala.html` 하위 8개 파샬(검색창/
카테고리탭/결과 dispatch/타입별 목록)을 매우 꼼꼼히 줄 단위로 대조해 다수 버그를 잡았지만,
감사 범위가 그 8개 파샬에 한정돼 있었고 **최상위 `result.scala.html` 자체의 조직 스코프
분기(`organization.header`/`organization.menu` 호출)는 다뤄지지 않았다**.

`error/forbidden_organization.scala.html`(→ yona `error/forbidden_organization.html`, TEMPLATE_BACKLOG
#49)의 동일 호출은 이미 정상 이식돼 있음을 확인했다(16/23행에서 `organization/header ::
header`, `organization/menu :: menu` fragment를 그대로 재사용) — 이쪽은 격차 아님, 참고용
비교 기준으로만 기록.

## 제안

- `search/list.html`의 조직 스코프 분기(`group != null && project == null` 등 legacy 조건에
  대응하는 부분)에서 즉석 `<div class="org-header">` 블록을 제거하고,
  `organization/header :: header(${group})` + `organization/menu :: menu(${group}, ...)`
  fragment 호출로 교체한다(project/organization 헤더-메뉴 조합을 쓰는 다른 화면들과 동일
  패턴).
- 활성 메뉴 계산(`menu` fragment의 activeMenu 파라미터)이 검색 화면에서 어떤 값을 받아야
  하는지 legacy 조건을 재확인할 것(예: 특정 탭도 아니고 검색 결과 화면이므로 전부 비활성일
  수 있음 — `error/forbidden_organization.html`이 이미 처리한 방식을 참고).
- 우선순위는 낮을 수 있음(조직 범위 검색은 부가 기능) — 다만 요청받은 "발견한 격차는 지금
  등록" 원칙에 따라 등록.

본 티켓은 순수 조사 산출물이며 구현은 하지 않았다.

## 완료 로그 (2026-09-12)

TDD로 구현 완료. 신규 회귀 스펙
`src/test/kotlin/com/github/yonaprojects/yona/web/OrganizationSearchHeaderTemplateRenderingSpec.kt`
(3개 케이스)를 먼저 추가해 RED(3/3 실패)를 확인한 뒤 구현했다.

- `search/list.html`의 즉석 `.org-header` 블록(조직명 링크 + 설명만 보여주던 div)을
  `organization/header :: header(${org})` + `organization/menu :: menu(${org}, 'none')`
  fragment 호출로 교체(`error/forbidden_organization.html`과 동일 패턴). 검색 화면은
  홈/이슈/게시판/PR 어느 탭에도 속하지 않으므로 activeMenu는 상수 `'none'`으로 고정(모든 탭
  비활성 — ticket 제안대로).

RED 재현 시 발견: 새로 만든 통합 스펙이 처음엔 302로 실패했는데 실제로는 `.org-header` 부재가
아니라 `BootstrapSetupInterceptor`(DB에 회원이 0명이면 모든 요청을 `/bootstrap-setup`으로
리다이렉트)에 걸린 것이었다 — 조직만 만들고 User를 하나도 안 만들어서 발생한 테스트 설정
문제였다(운영 코드 버그 아님). 최소 User 1명을 시드하도록 스펙을 수정해 해결.

**Playwright 실측 검증(1회)**: 기존 dev 서버(재사용)에 실제 조직을 하나 생성하고, 로그인 세션으로
`/org/{org}/search?keyword=test`에 접속해 `.org-header`가 사라졌음(count 0), 조직 로고 이미지가
`.project-header-outer` 안에 렌더링됨, `.project-menu-outer`에 홈/이슈/게시판/코드 주고받기/
(관리자이므로) 프로젝트 설정 링크가 모두 렌더링됨을 확인했다.

회귀 테스트: `OrganizationSearchHeaderTemplateRenderingSpec`(신규, 3/3 GREEN),
`SearchControllerSpec`(기존, GREEN).
