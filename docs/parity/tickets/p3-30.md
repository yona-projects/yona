# P3-30: `IssueController`/`IssueApiController`/`BoardController`/`CommentController`/`MilestoneController`(24개 엔드포인트)에도 P3-26/28과 동일한 순환참조/비밀번호 노출

## 배경

P3-26(`pushedBranches`)/P3-28(`PullRequestController`)에서 고친 "raw 엔티티를 그대로
직렬화하면 `User.projectUsers`↔`ProjectUser.user` 양방향 관계가 순환 직렬화되며
`User.password`/`passwordSalt`까지 노출된다"는 정확히 같은 문제가 이슈/게시글/댓글/
마일스톤 관련 컨트롤러에도 광범위하게 남아있음을 확인했다.

`grep -rln "): ResponseEntity<Issue>\|): ResponseEntity<Posting>\|): ResponseEntity<Milestone>\|
): ResponseEntity<Comment>\|..."` 로 전수 검색한 결과:

| 파일 | raw 엔티티 반환 엔드포인트 수 |
|---|---|
| `IssueController.kt` | 8 |
| `IssueApiController.kt`(legacy Open API, P2-55/56) | 5 |
| `BoardController.kt` | 4 |
| `CommentController.kt` | 4 |
| `MilestoneController.kt` | 3 |

실제 재현: `GET /-_-api/v1/owners/{owner}/projects/{projectName}/issues/{number}`
(`IssueApiController.getIssueLegacyPath()`)를 실제 앱으로 호출 — 응답 60690바이트,
`password` 해시값이 그대로 노출됨을 확인.

`RestApiResponseDto.kt`에 이미 `Issue.toResponse(): IssueResponse`/
`IssueComment.toResponse(): IssueCommentResponse`가 존재한다(다른 v1 API 컨트롤러가 이미
쓰고 있는 것으로 보임) — `IssueController`/`IssueApiController`가 이걸 안 쓰고 있었을
뿐이다. `Posting`/`Milestone`/`Comment`(리뷰 댓글이 아닌 게시글/이슈 공용 댓글)용 DTO는
아직 없어 신규 작성이 필요하다.

## 범위

1. `IssueController.kt`/`IssueApiController.kt`의 raw `Issue`/`List<Issue>` 반환 13곳을
   기존 `Issue.toResponse()`로 교체(legacy 쪽은 필드명 계약이 다를 수 있으니 응답 스키마가
   실제로 legacy 계약과 맞는지 재확인 — 다르면 legacy 전용 DTO를 새로 만들 것, 기존
   `IssueResponse`를 함부로 변형해 다른 v1 API 소비자를 깨지 않을 것).
2. `BoardController.kt`의 `Posting` 4곳 — `PostingResponse` DTO 신설.
3. `CommentController.kt`의 `Comment`/`IssueComment`/`PostingComment` 4곳 — 관련 DTO 신설
   (이미 있는 `IssueCommentResponse`를 재사용할 수 있는 부분은 재사용).
4. `MilestoneController.kt`의 `Milestone` 3곳 — `MilestoneResponse` DTO 신설.
5. 각 컨트롤러를 호출하는 다른 어댑터(v1 REST API, MCP 도구 등 — PR 때
   `PullRequestApiController`/`PullRequestMcpTools`에서 발견한 것과 동일한 이중 변환
   패턴이 있는지)도 함께 확인·정리.
6. 컴파일 확인 → 관련 테스트 전체 재실행 → 실제 앱 기동으로 재검증(이슈/게시글/댓글/
   마일스톤 각각 최소 1개 엔드포인트를 실제로 호출해 `password` 문자열이 응답에 없는지
   확인).

## 완료 기준

- 위 5개 파일의 어떤 엔드포인트도 raw 엔티티를 직접 반환하지 않는다.
- 실제 이슈/게시글/댓글/마일스톤 API 응답에 비밀번호 해시가 노출되지 않는다(실사용 검증).
- 기존 테스트 전부 GREEN.
