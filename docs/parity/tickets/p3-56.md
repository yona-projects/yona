# P3-56: SVN 커밋 상세 화면(`code/svnDiff.html`)의 댓글 기능이 legacy 대비 크게 축소된 즉석
구현으로 대체돼 있음(마크다운 에디터/파일첨부/멘션/권한기반삭제/삭제확인모달/마크다운 렌더링
전부 없음)

## 배경

legacy `app/views/code/svnDiff.scala.html`(SVN 프로젝트의 커밋 상세 화면, Git 쪽
`code/diff.scala.html`의 SVN 대응판)은 댓글 섹션을 Git 쪽과 완전히 동일한 컴포넌트들로
구성한다:

```scala
// legacy-yona/app/views/code/svnDiff.scala.html:100-138
@** Comment **@
<div class="board-comment-wrap">
    @if(comments.size > 0) {
    <ul class="comments">
        @for(comment <- comments){
        <li id="comment-@comment.id" ... class="comment">
            <div class="comment-avatar">
                <a href="@routes.UserApp.userInfo(comment.authorLoginId)" class="avatar-wrap" ...>
                    <img src="@User.findByLoginId(comment.authorLoginId).avatarUrl" width="32" height="32" ...>
                </a>
            </div>
            <div class="media-body">
                <div class="meta-info">
                    ...
                    @if(isAllowed(UserApp.currentUser(), comment.asResource(), Operation.DELETE)){
                    <span class="edit pull-right">
                        <button class="btn-transparent pull-right close" data-toggle="comment-delete"
                                data-request-uri="@routes.CodeHistoryApp.deleteComment(...)" ...><i class="yobicon-trash"></i></button>
                    </span>
                    }
                </div>
                <div class="comment-body markdown-wrap" data-via-email="@OriginalEmail.exists(comment.asResource)">@Html(Markdown.render(comment.contents, comment.asResource().getProject()))</div>
                <div class="attachments" data-attachments="@toJson(AttachmentApp.getFileList(ResourceType.COMMIT_COMMENT.toString(), comment.id.toString()))"></div>
            </div>
        </li>
        }
    </ul>
    }
    @common.commentForm(commit.asResource(project), ResourceType.COMMIT_COMMENT, routes.CodeHistoryApp.newComment(project.owner, project.name, commit.getId).toString())
</div>
@** // Comment **@
...
@common.markdown(project)
@common.commentDeleteModal("#code-browse-wrap")
```

즉 legacy에서는 Git이든 SVN이든 커밋 댓글(`ResourceType.COMMIT_COMMENT`)이 동일한 기능
수준(마크다운 편집기, 파일첨부, `@`/`:`/`#` 멘션, 프로젝트 매니저 권한까지 포함한 삭제 권한
체크, 삭제 전 확인 모달, 서버측 마크다운 렌더링, 첨부파일 목록)을 갖는다.

## 현재 yona 상태

`docs/TEMPLATE_BACKLOG.md` #161(`code/svnDiff.scala.html` → `code/svnDiff.html`)은
"완료(TASK-0243)... GNB/프로젝트헤더/메뉴, site/layout::scripts 누락 복구, 브랜치 드롭다운(#39)
추가... 감시(watch) 버튼 URL 배선과 목록 링크 복구"라고 기록돼 있으나, **댓글 기능 자체는
전혀 검토 대상이 아니었다**. `common/commentForm.scala.html`(#24)과
`common/commentDeleteModal.scala.html`(#26) 문서 행에도 `code/svnDiff.scala.html`이 호출부로
전혀 언급돼 있지 않다(실제 legacy grep 결과엔 있음).

실제 `src/main/resources/templates/code/svnDiff.html`(52-138행)의 댓글 섹션은 legacy
구조를 재사용하지 않고 완전히 새로 즉석 작성된 축소판이다:

```html
<!-- SVN Comments List -->
<div class="board-comment-wrap" style="margin-top: 30px;">
  <ul class="comments" ... th:if="${comments != null && !comments.isEmpty()}">
    <li th:each="comment : ${comments}" ...>
      <div class="comment-avatar" ...><img src="/images/default-avatar-32.png" ...></div>
      <div class="media-body">
        <div class="meta-info">
          <strong th:text="${comment.author?.loginId}">작성자</strong>
          ...
          <span class="edit pull-right" th:if="${currentUser != null && comment.author?.id == currentUser.id}">
            <button type="button" class="btn-transparent btn-comment-delete" th:data-comment-id="${comment.id}" ...>
          </span>
        </div>
        <div class="comment-body markdown-wrap" ... th:text="${comment.contents}">댓글 내용</div>
      </div>
    </li>
  </ul>

  <!-- SVN Comment Form -->
  <div class="write-comment-form" th:if="${currentUser != null}" ...>
    <form th:action="@{/{owner}/{projectName}/commit/{commitId}/comments(...)}" method="post">
      <textarea name="contents" placeholder="이 SVN 커밋에 댓글을 남기세요..." ... required></textarea>
      <button type="submit" class="ybtn ybtn-success">댓글 등록</button>
    </form>
  </div>
</div>
```

삭제는 인라인 스크립트의 `confirm()` + `fetch(".../comments/COMMIT_COMMENT/"+id, {method:"DELETE"})`로
처리된다(공용 `commentDeleteModal` 미사용).

## 확인된 격차 (legacy 대비)

1. **마크다운 에디터 없음** — `<textarea>` 그대로. Git 쪽 `code/diff.html`은 같은 종류의 댓글
   폼에 `site/layout :: markdownEditor(...)` 프래그먼트(`<yona-markdown-editor>`, 툴바+미리보기+
   멘션)를 쓰는데(`code/diff.html:161`), svnDiff는 이 프래그먼트를 전혀 쓰지 않는다.
2. **파일 첨부(attachment) 기능 전체 없음** — 작성 폼에 `common/uploadForm`류 업로더가 없고,
   댓글 목록에도 `.attachments` 영역/데이터가 없다(legacy 132행 `AttachmentApp.getFileList(...)`
   대응 없음).
3. **`@`/`:`/`#` 멘션 자동완성 없음** — legacy는 `yobi.Mention({target:'textarea[id^=editor-]', url: ...mentionListAtCommitDiff...})`로 배선(legacy svnDiff.scala.html 하단 스크립트). yona엔 없음.
4. **삭제 권한이 축소됨** — legacy는 `isAllowed(currentUser, comment.asResource(), Operation.DELETE)`(프로젝트
   매니저/관리자도 삭제 가능한 표준 접근제어)를 쓰는데, yona는 `comment.author?.id == currentUser.id`
   (작성자 본인만) 하드코딩 — 매니저가 부적절한 SVN 커밋 댓글을 못 지운다.
5. **삭제 확인 모달 없음** — 공용 `common/commentDeleteModal.html`(#26, git/view·git/viewChanges·
   issue/view·code/diff·board/view가 전부 쓰는 표준 컴포넌트) 대신 브라우저 기본 `confirm()`.
6. **댓글 본문이 마크다운 렌더링되지 않음** — `th:text="${comment.contents}"`로 원문 그대로
   출력(이스케이프됨). legacy는 `Markdown.render(comment.contents, project)`로 서버측 렌더링.
   마크다운 문법을 쓴 SVN 커밋 댓글은 전부 깨져 보인다.
7. **작성자 아바타/프로필 링크 없음** — 기본 아바타 이미지 고정, `UserApp.userInfo` 링크 없음.
8. **`data-via-email` 속성 없음**(다른 댓글 화면들과 달리 이메일 출처 표시 불가 — 경미).
9. **마크다운 문법 도움말 트리거 없음** — legacy는 댓글 섹션 바로 다음에
   `@common.markdown(project)`(TEMPLATE_BACKLOG #19, 마크다운 문법 안내 모달 트리거)를
   호출하는데 yona `code/svnDiff.html`엔 이 트리거 자체가 없다(에디터가 없으니 당연한
   동반 누락 — 1번 항목과 함께 해결됨).

## 참고: 동일 이슈가 아닌 것

- Git 쪽 `code/diff.html`은 `common/commentForm.html`을 문자 그대로 재사용하진 않지만(P3-55에서
  PR Changes 탭용으로 신설된 파일), `NonRangedCodeCommentThread` 아키텍처 기반으로
  `markdownEditor` 프래그먼트 + 스레드 렌더링을 정확히 쓰고 있어 기능적으로 동등하다 — 이
  티켓의 대상이 아니다.
- `git/view.scala.html`(단일 파일 브라우징 화면)의 `commentDeleteModal` 호출부는 별도 확인
  필요(다른 조사에서 다룸 — 이 티켓과 독립적으로 처리).

## 제안

`code/svnDiff.html`의 댓글 섹션을 legacy 구조에 맞춰 다시 작성한다:
- `site/layout :: markdownEditor('contents', '', 'commit-comment-body')` 프래그먼트로 교체
  (code/diff.html과 동일 패턴).
- 첨부파일 업로드/표시를 `common/uploadForm` 프래그먼트 + 댓글별 첨부파일 모델로 연결(#25/#23
  커밋 댓글용 첨부파일 인프라가 이미 있는지 확인 후 재사용 — `CommitCommentAttachment` 등
  백엔드 존재 여부 먼저 `docs/parity/index.md` 확인).
- 멘션 자동완성 배선(`yona-markdown-editor`가 이미 내장 멘션 기능을 가지고 있다면 별도 JS
  불필요 — 다른 화면과 동일 방식으로 통일).
- 삭제 버튼 노출 조건을 `templateHelper.isAllowedDelete(currentUser, comment)`류(다른 댓글
  화면이 쓰는 권한 체크 방식)로 교체(작성자 본인 제한 제거, 매니저도 허용).
- `common/commentDeleteModal.html` 프래그먼트로 교체(다른 댓글 화면과 통일된 삭제 UX).
- 댓글 본문을 `templateHelper.renderMarkdown(comment.contents, project)`(또는 동일 계열 헬퍼 —
  다른 화면에서 실제 쓰는 이름 확인 후 사용)로 렌더링.
- 아바타/프로필 링크 추가.

작업 착수 시 TDD로 "SVN 커밋 댓글 폼에 CM6 에디터가 있어야 한다" / "매니저는 타인의 SVN 커밋
댓글을 삭제할 수 있어야 한다" 등 회귀 스펙을 먼저 세울 것. 본 티켓은 순수 조사 산출물이며
구현은 하지 않았다.
