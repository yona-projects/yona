# P3-12: Mercurial(hg4j) 저장소 지원 추가 (2026-08-31 사용자 제안, 계획서만 작성 — 코드 0줄)

- **우선순위 구분**: P3
- **상태(원본 체크박스)**: `[ ]`
- **비고(원문)**: [원본에 있던 추가 열(섹션 헤더는 3열인데 이 행은 4열)]
  - (원본 열 3) yona 동치성과 무관 — legacy는 GIT/SUBVERSION 두 VCS만 지원, Mercurial 관련 코드 0건(전수 확인)
  
  계획서: [`docs/yona-wiki/plans/p3-12-mercurial-hg4j.md`](yona-wiki/plans/p3-12-mercurial-hg4j.md). 사용자가 지정한 라이브러리는 Maven Central의 구버전 TMate `org.tmatesoft.hg4j`가 아니라 **자체 개발 중인 [`github.com/search5/hg4j`](https://github.com/search5/hg4j)**이며, **인터페이스를 JGit과 동일하게 맞출 예정**이라고 확인됨 — 그렇다면 `domain/vcs/GitRepository.kt`의 구현 패턴을 hg4j API로 옮겨 적는 방식으로 `HgRepository : PlayRepository`를 구현 가능할 것으로 기대(실제 API 확정 전까지는 가정). `RepositoryService.getRepository()`의 GIT/SVN 이분기에 세 번째 분기 추가, 프로젝트 생성 폼에 VCS 옵션 추가, `GitAuthorizationFilter`/`SvnAuthorizationFilter`와 대칭인 `HgAuthorizationFilter` 신설까지가 yona 쪽 통합 범위. **가장 큰 미확정 사항**: `search5/hg4j`가 JGit의 `GitServlet`에 해당하는 프로토콜 서빙 컴포넌트(smart HTTP)까지 제공하는지, 아니면 저장소 읽기/쓰기 API만 제공하고 Mercurial wire protocol 자체는 yona가 직접 구현해야 하는지 — hg4j 저장소 진행 상황을 먼저 확인해야 착수 가능(사실상의 외부 블로커)
