## 완료 로그 (원문, `PARITY_BACKLOG.md`의 "완료 로그" 섹션에서 이관)

- **2026-08-22 — P2-44**: PR/리뷰스레드 삭제 시 REVIEW_COMMENT·COMMIT_COMMENT·웹훅 관련 첨부파일이 정리되지 않는 문제로 등록됐던 항목을 재조사한 결과, **legacy 자체가 이 세 리소스 타입(REVIEW_COMMENT, COMMIT_COMMENT, WEBHOOK)에 대한 Attachment 정리 로직을 어디에도(프로젝트 삭제 cascade든, 개별 댓글/웹훅 삭제 경로든) 구현하지 않았음을 확인** — legacy 전역에서 `Attachment.deleteAll(...)` 호출은 `Comment.delete()`(ISSUE_COMMENT/NONISSUE_COMMENT)와 `AbstractPosting.delete()`(ISSUE_POST/BOARD_POST) 단 두 곳뿐이고, `ReviewComment`/`CommitComment`/`Webhook`은 애초에 `delete()`를 오버라이드하지 않아(또는 `CommitComment`처럼 `Comment`가 아닌 `Model`을 직접 상속해) Ebean 기본 삭제만 일어난다. yona `ProjectServiceImpl.deleteProject()`/`CodeReviewServiceImpl.deleteReviewComment/deleteCommitComment`/`WebhookServiceImpl.deleteWebhook`도 동일하게 attachmentService 호출이 없어 **legacy와 정확히 같은 범위의 기존 결함을 재현하고 있는 상태**임을 확인. legacy에 없는 정리 로직을 새로 만드는 것은 "레거시에 없는 동작 추가"에 해당해 포팅 원칙에 위배되므로, 코드 변경 없이 검증만 하고 종결.
  - 검증: 코드 변경 없음(조사만 수행), 기존 전체 스위트 상태 유지.
