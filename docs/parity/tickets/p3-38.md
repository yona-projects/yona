# P3-38: v1.6 원본이 `-_-api/v1` 밖에도 이중 매핑해둔 댓글 수정 경로(PATCH) 2개 누락 발견·이식

## 배경

[[tickets/p3-37|P3-37]] 작업 중 사용자가 "레거시에도 `-_-api/v1`이 아닌 API 컨트롤러 경로가
있는지"를 물어 v1.6(원본 legacy) `conf/routes` 전체를 `controllers.api.*` 기준으로 재검색했다.
거의 전부 `-_-api/v1` 하위였지만, 정확히 2개 예외가 있었다:

```
PATCH  /:user/:project/post/:number/comment/:commentId       controllers.api.BoardApi.updatePostingComment(...)
PATCH  /:user/:project/issue/:number/comments/:commentId     controllers.api.IssueApi.updateIssueComment(...)
```

v1.6 원본 자체가 같은 컨트롤러 메서드를 **두 경로로 이중 매핑**해뒀다 — 공식
`-_-api/v1/.../comments/:commentId`(PUT)와, 웹 UI 자체 AJAX용으로 보이는 bare 경로
`/:owner/:project/.../comments/:commentId`(PATCH, `-_-api` 접두어 없음). yona `CommentController.kt`는
전자(PUT, `-_-api/v1` 경로)만 이식돼 있었고 후자(PATCH, bare 경로)는 빠져 있었다 — 기능
자체는 다른 경로로 커버되니 완전한 누락은 아니지만, 이 정확한 경로/메서드 조합으로 호출하는
legacy 클라이언트가 있었다면 여전히 404가 났을 것이다.

## 범위

`CommentController.kt`의 `updateIssueCommentLegacyPath()`/`updatePostingCommentLegacyPath()`
두 메서드에 원본 bare 경로를 PATCH 메서드로 추가 매핑(기존 `-_-api/v1` PUT 경로는 유지) —
`@RequestMapping(value = [...], method = [PUT, PATCH])`로 두 경로 모두에 PUT/PATCH 둘 다
허용(v1.6이 경로별로 메서드를 엄격히 나눴던 것보다 관대하지만, 아무것도 제거하지 않는 상위
호환이라 문제 없음):

| 기능 | 기존(유지) | 신규 추가(원본 bare 경로) |
|---|---|---|
| `IssueApi.updateIssueComment` | `PUT /-_-api/v1/owners/{owner}/projects/{projectName}/issues/{number}/comments/{commentId}` | `PATCH /{owner}/{projectName}/issue/{number}/comments/{commentId}` |
| `BoardApi.updatePostingComment` | `PUT /-_-api/v1/owners/{owner}/projects/{projectName}/posts/{number}/comments/{commentId}` | `PATCH /{owner}/{projectName}/post/{number}/comment/{commentId}` |

(주의: "issue"/"comments"는 복수, "post"/"comment"는 단수 — v1.6 원본 그대로, 임의로 통일하지 않음)

## 완료 로그

### 2026-09-09 — 발견·구현·검증 완료

**RED**: `CommentControllerSpec.kt`에 bare 경로 PATCH 호출 테스트 2건 추가(수정 전에는 매핑
없어 404).

**GREEN**: 위 범위 그대로 `CommentController.kt`에 `@RequestMapping` 다중 경로/메서드 매핑
추가. `CommentControllerSpec.kt`(66건, 신규 2건 포함) 전부 GREEN. 회귀 확인을 위해
`IssueControllerSpec`/`BoardControllerSpec`/`IssueViewControllerSpec`/`BoardViewControllerSpec`도
재실행, 전부 GREEN(경로 충돌 없음).

**실사용 검증**: 실제 서버(H2 격리 인스턴스, 포트 18699) 기동 시 모호한 매핑(Ambiguous
mapping) 예외 없이 정상 부팅됨을 먼저 확인. 실제로 이슈 생성 → 댓글 생성(`-_-api/v1` POST) →
**v1.6 원본 그대로의 bare 경로(`PATCH /admin/patchtest/issue/1/comments/1`)로 댓글 수정** →
200 성공 + 수정된 내용 반영까지 end-to-end로 확인(sha1 체크섬 불일치 시 409 거부되는 동시편집
충돌 감지도 실제로 재현해 정상 동작 확인). 게시글 댓글 쪽은 완전히 동일한 코드 패턴이라
실사용 검증은 생략하고 단위 테스트로만 커버(게시글 생성 API 경로를 못 찾아 시간 관계상
중단 — 필요시 재확인).
