# P3-73: 코드리뷰 댓글 팝업(`review-form`)에서 타이핑이 불가능함 — CodeMirror 뷰가 destroy된 채 복구되지 않음

## 배경

`code/diff.html`/`pullrequest/view.html`에서 diff 줄 옆 "+" 아이콘(`.add-comment-btn-cell`)을
클릭하면 `common/reviewForm.html`(`id="review-form"`)이 해당 줄 위치로 옮겨져 뜨는데,
실제로 열어보면 툴바(B/I/H 등)만 보이고 **그 아래 텍스트를 입력할 수 있는 영역 자체가
없다.** 사용자가 스크린샷을 보고 "글자를 입력할 수 있는 칸이 안 보인다"고 지적해 발견했다.

## 근본 원인

`common/yona.CodeCommentBox.js`의 `_placeReviewForm()`이 팝업을 새 위치로 옮길 때마다
조건 없이 `welWriteCommentForm.appendChild(htElement.welCommentWrap)`을 호출했다.
`Node.appendChild()`는 대상 노드를 다른 부모로 옮길 때 내부적으로 **disconnect 후
reconnect**를 일으키는데, `review-form` 안의 `<yona-markdown-editor>`(lib/, 미수정)
커스텀 엘리먼트는 `connectedCallback`에 `if(this.shadowRoot) return;`(중복 초기화 방지
가드)이 있어서, 이 스퓨리어스 disconnect가 기존 CodeMirror 뷰를 destroy한 뒤 그 가드
때문에 다시 만들어지지 않는다.

Shadow DOM을 직접 조사해 실측 확인: 클릭 전에는 `.editor-wrapper` 안에
`<div class="cm-editor">...`가 정상적으로 있다가, 클릭(=팝업 이동) 후에는
`<div class="editor-wrapper"></div>`로 완전히 비어버린다.

## 정확히 같은 버그가 예전에 한 번 발견·수정됐다가 유실된 이력

`docs/parity/tickets/p3-55.md`의 "1차 시도" 완료 로그에 동일한 버그와 수정이 이미
기록돼 있다: `Node.appendChild()`가 "이미 같은 부모의 마지막 자식"이어도 disconnect
후 reconnect로 처리돼 CM6 뷰가 destroy된 채 재마운트되지 않는 문제를 발견해
`_returnToInitialParent()`를 실제로 이동이 필요할 때만 동작하도록 고쳤었다. 그런데
이 1차 시도 자체가 나중에 롤백되면서(review-form 대신 `commentForm`을 만드는 방향으로
전환) 그 수정도 함께 사라졌고, 이후 "4단계 복원"(`0cf998fd0`)이 `_placeReviewForm()`을
처음부터 다시 구현하면서 이 가드를 다시 빠뜨렸다.

다만 이번 케이스는 1차 시도 때와 달리 "이미 같은 부모"인 경우만이 아니라 **완전히
새로운 위치로 처음 옮기는 경우("정말 필요한" 이동)에도 동일하게 CM6가 destroy된다** —
`_getReviewFormPlace()`가 새 줄 댓글일 때마다 매번 새 `<tr>`을 만들어 반환하므로,
"이미 그 자리에 있으면 건너뛴다" 가드만으로는 이 경우를 막을 수 없다. 그래서 이번
수정은 그 가드에 더해, 실제로 이동이 일어난 뒤에는 `<yona-markdown-editor>` 자체를
`cloneNode(true)`로 완전히 새 인스턴스로 교체해 `connectedCallback`이 빈 `shadowRoot`를
보고 CM6를 다시 만들도록 했다(`common/yona.ui.Toast.js`/`yona.ui.Dialog.js`가 이미 쓰는
cloneNode 기반 재사용 관례와 동일한 기법 — 벤더 파일은 수정하지 않음).

## 수정 내용

`common/yona.CodeCommentBox.js`:
- `_placeReviewForm()`: "이미 같은 부모면 appendChild 생략"(P3-55 1차 시도의 가드 재도입)
  + 실제로 옮겨진 경우에만 `_remountEditor()` 호출.
- `_hide()`: 초기 위치로 되돌릴 때도 동일하게 "실제로 이동이 필요할 때만" 가드 적용.
- `_remountEditor()`(신규): `<yona-markdown-editor>`를 `cloneNode(true)` 후
  `replaceWith()`로 교체 — light DOM 자식(`<textarea>`와 속성)은 그대로 복사되고
  imperative shadow DOM은 복사되지 않으므로, 새 인스턴스가 연결되면 `connectedCallback`이
  정상적으로 CM6를 새로 만든다. `htElement.welCommentTextarea` 참조도 새 텍스트영역으로
  갱신.

## 검증

- Playwright로 실제 브라우저에서: diff 줄의 add-comment-btn-cell 클릭 → 팝업 오픈 →
  `.cm-editor`가 실제 크기(798×300)로 렌더링됨 확인 → `.cm-content`에 실제 키보드
  타이핑으로 한글 텍스트 입력 성공 확인 → 폼 제출 → 서버 응답에 입력한 텍스트가 실제로
  반영됨 확인(`/pullRequest/1/changes#comment-1`로 정상 이동) → 같은 세션에서 **다른
  줄**에 다시 댓글 버튼을 클릭해도(반복 사용) 동일하게 정상 동작함을 확인(remount가
  반복 사용을 깨지 않음).
- `PullRequestInlineReviewCommentWiringTemplateRenderingSpec`(2), `CodeSwallowedStyleRenderingSpec`(6),
  `PullRequestViewControllerSpec`(93) — 전부 GREEN, XML 타임스탬프로 재실행 확인. 순수
  클라이언트 JS 수정이라 서버/템플릿 계약에는 영향 없음.

## 후속 개선(같은 세션, 사용자 요청)

수정된 팝업을 실제로 써보며 사용자가 추가로 지적한 3가지를 같은 라운드에서 함께 반영했다:

1. **취소 버튼이 없고 X 아이콘만 있음** — `common/reviewForm.html`의 제출 버튼
   ("댓글 등록") 옆에 `button.cancel` 메시지 키를 쓰는 명시적 "Cancel" 버튼을 추가했다.
   기존 X 아이콘과 동일한 `data-toggle="close"`를 그대로 붙여 별도 JS 배선 없이
   `_hide()`에 연결된다.
2. **취소/확인 시 에디터를 명시적으로 종료 후 재생성해야 함(GitHub 등의 통상적 동작)** —
   `_hide()`가 매번 무조건 `_remountEditor()`를 호출하도록 바꿨다. 실측으로는 기존
   구현도(새 줄마다 `_getReviewFormPlace()`가 항상 새 `<tr>`을 만드는 우연 덕에) 결과적으로
   깨끗한 상태였지만, 그건 우연에 기대는 것이었고 이번 변경으로 "닫히는 시점에 항상
   리셋"을 명시적으로 보장한다(제출/확인은 실제 `<form>` POST로 페이지 전체가
   새로고침되므로 별도 처리가 필요 없음 - 실측 확인).
3. **code diff 팝업의 CodeMirror 높이가 조절돼야 함** — 두 부분으로 나눠 해결했다:
   - **기본 높이를 5줄 정도로 축소**: 벤더가 노출하는 CSS 변수
     `--yona-md-min-height`(기본 300px)를 `.review-form` 컨텍스트에서만 실측 기반
     `100px`(13px 폰트 기준 줄 높이 18.19px×5 + `.cm-content` 상하 padding 4px×2 ≈ 99px)로
     오버라이드했다 — 일반 댓글 상자(하단 상시 노출)는 기존 300px 그대로 유지.
   - **사용자가 드래그로 리사이즈 가능**: `<yona-markdown-editor>`가 에디터 컨테이너를
     CSS Shadow Part `"editor"`로 노출해둔 것을 확인해(벤더 소스
     `setAttribute("part","editor")`), `.review-form yona-markdown-editor::part(editor)`에
     `resize:vertical; overflow:auto;`를 줘서 네이티브 리사이즈 핸들을 노출했다. 다만
     `.editor-wrapper`(그 part)를 늘려도 실제 CodeMirror 뷰(`.cm-editor`, `min-height`
     고정이라 부모 크기 변화를 스스로 알지 못함)는 따라 커지지 않는 것을 실측으로
     발견해, `ResizeObserver`로 `.editor-wrapper` 크기 변화를 감지해 `.cm-editor`의
     `min-height`를 JS로 직접 동기화하는 `_makeEditorResizable()`을 추가했다(`part`로
     노출 안 된 `.cm-editor`는 외부 CSS로 직접 겨냥할 수 없어 JS 경로가 필요했다 -
     shadowRoot가 open이라 접근 가능). `ResizeObserver.observe()`가 최초 1회는 "관찰 시작
     시점의 현재 크기"로 즉시 콜백을 실행하는 스펙 동작이 있어, 이걸 그대로 반영하면
     아직 사용자가 리사이즈하지 않았는데도 그 순간의 자연 높이(실측 164px)가 인라인
     `min-height`로 고정돼 위 5줄 축소가 무력화되는 문제를 발견해, 최초 콜백은 건너뛰고
     실제 크기 "변화"부터만 동기화하도록 고쳤다.

### 후속 개선 검증

- Playwright로 (a) 기본 오픈 시 높이 100px·인라인 style 없음(순수 CSS 기본값) 확인,
  (b) "Cancel"/"Add a comment" 버튼 둘 다 렌더링 확인, (c) 리사이즈 핸들을 실제
  마우스 드래그로 조작해 `.cm-editor`가 함께 커짐(100→292px 등, 여러 시나리오) 확인 +
  늘어난 공간에 15줄 타이핑이 실제로 다 들어감 확인(콘솔 경고/에러 0건, ResizeObserver
  루프 없음), (d) 타이핑 후 Cancel 클릭 → 팝업 닫힘 → 다른 줄에서 재오픈 시 높이가 다시
  기본 100px로 돌아가고 잔존 텍스트 없음(리사이즈했던 크기가 다음 오픈에 새지 않음) 확인.
- `PullRequestInlineReviewCommentWiringTemplateRenderingSpec`(2)/
  `CodeSwallowedStyleRenderingSpec`(6)/`PullRequestViewControllerSpec`(93)/
  `TemplateEquivalenceSpec`(87) 재확인 — 전부 GREEN.
