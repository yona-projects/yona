## 완료 로그 (원문, `PARITY_BACKLOG.md`의 "완료 로그" 섹션에서 이관)

- **2026-08-21 — P1-139**: 코드브라우저/README에 `.md` 마크다운 렌더링 자체가 없던 것(`markdownService` 호출 0건)을 yona `Markdown.java:346-356` `renderFileInCodeBrowser()`/`renderFileInReadme()` 대응으로 이식.
  - `MarkdownService`/`MarkdownServiceImpl`에 두 메서드 신설: 렌더링 전에 소스 안의 상대경로 링크(`![text](./path)`, `[text](./path)`)를 프로젝트 기본 브랜치 기준 절대경로로 먼저 치환한 뒤(`renderFileInCodeBrowser`는 이미지 링크만 `/owner/project/files/branch/...`로, `renderFileInReadme`는 이미지는 files로 + 일반 링크는 `/owner/project/code/branch/...`로) 기존 `render()` 파이프라인에 위임 — yona `replaceImageLinkPath()`/`replaceContentsLinkToCodeBrowerPath()`의 정규식을 Kotlin `Regex`로 그대로 이식(단, `.*`greedy 매칭은 `[^)]*`로 — 여러 링크가 한 줄에 있을 때 오동작하는 원본의 취약한 그리디 매칭을 재현할 가치가 없어 실질적으로 의도된 단일-링크 매칭으로 정리). 기본 브랜치 조회를 위해 `RepositoryService`를 새로 주입.
  - `CodeViewController.codeBrowserWithBranch()`: yona `partial_view_file.scala.html:109-114` `isMarkdownExtension(path)` 분기 대응 — 조회한 파일이 `.md`/`.markdown`/`.mdown`/`.mkdn`/`.mkd`/`.mdwn` 확장자면 `renderFileInCodeBrowser()`로 렌더링해 `markdownHtml` 모델 속성에 담고, `code/view.html` 템플릿에 마크다운 전용 분기(`markdown-wrap codebrowser-markdown`)를 추가해 기존 `<pre>` 코드블록 대신 렌더링된 HTML을 보여주도록 수정.
  - `ProjectViewController`의 README 렌더링(`readmeHtml`)도 일반 `render()` 대신 `renderFileInReadme()`를 쓰도록 정정(상대링크 치환이 빠져 있었음).
  - **새로 발견해 [[tickets/p2-42|P2-42]]로 등록**: yona는 코드브라우저가 꺼진 프로젝트의 README를 게시판 포스팅(`Posting(readme=true)`)에서 읽어오는 별도 경로가 있는데(`partial_readme.scala.html:38-42`), yona `getReadmeContent()`는 git 파일(`README.md`)만 읽어 이 경로가 아예 없음 — 이번 티켓 범위 밖이라 백로그에만 등록.
  - 테스트: `MarkdownServiceImplSpec.kt` +3(이미지 링크 치환/절대·외부 링크 보존/README 링크 이원 치환), `CodeViewControllerSpec.kt` +2(.md 파일이면 markdownHtml 채움/그 외는 안 채움), `ProjectViewControllerSpec.kt` +1(README가 renderFileInReadme로 렌더링되는지, 일반 render()는 호출되지 않는지). 전체 통과.
