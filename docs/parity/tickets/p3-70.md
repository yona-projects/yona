# P3-70: 잔여 jQuery 의존성 전면 vanilla JS 전환

## 배경

`docs/parity/index.md`/개별 티켓들에 기록된 기존 "jQuery 의존성 점진적 축소" 캠페인(tab/
affix→position:sticky/pjax/tmpl 카테고리, `.modal()`→네이티브 `<dialog>`, `$.ajax/get/post`
→`fetch` 등 다수 라운드, 커밋 이력 다수)이 이미 자체 작성 JS 77개 중 44개를 vanilla로
전환했다. 사용자 요청으로 나머지 33개 + 템플릿 인라인 스크립트 79개 + jQuery 코어 자체까지
전부 제거하는 전면 계획을 세운다.

## 원칙(사용자 확정)

1. **`static/javascripts/lib/` 아래 벤더 라이브러리 파일은 절대 수정하지 않는다** —
   jQuery 기반이든(`jquery.validate.js`/`jquery.form.js`/`bootstrap.js` 등) 이미 vanilla든
   (`tribute.min.js` 등) 전부 손대지 않는다. 전환 대상은 오직 우리 자체 코드
   (`common/service/template`의 JS 파일 + 템플릿 인라인 `<script>`)뿐이다.
2. 벤더 플러그인 사용을 대체할 때는 네이티브 브라우저 API(HTML5 validation, `fetch`,
   Clipboard API, `<dialog>` 등)로 바꾸거나 직접 vanilla 코드를 새로 작성한다. 그 결과
   더 이상 아무도 호출하지 않게 된 벤더 파일은 **`<script src>` 참조만 제거**하고 파일
   자체는 삭제 여부를 별도 판단(이 티켓 범위 밖일 수 있음).
3. 기존 캠페인과 동일한 "완전 동치" 원칙 — 새 기능 추가 금지, 옵션/이벤트/키보드 동작까지
   최대한 동일하게.
4. **각 라운드 전환 후 반드시 Playwright로 실제 브라우저 동작을 사전 검증한다**(사용자
   명시 지시) — 코디네이터가 diff 검토 + 스펙 재실행에 더해 실브라우저 확인까지 마친 뒤에만
   커밋한다.
5. 사용자 승인(2026-09-14)으로 라운드 1부터 10까지 사용자 재확인 없이 연속 진행한다 — 매
   라운드 완료 시 이 티켓에 완료 로그를 남기고 곧바로 다음 라운드 TDD 에이전트를 실행한다.

**템플릿 인라인 스크립트 전환** (9개 파일을 로드/초기화하는 템플릿 중 실제로 관련 jQuery가
있던 곳만, `grep -rl`로 로더 템플릿을 먼저 확인 후 진행):

- `templates/milestone/create.html`, `templates/milestone/edit.html`: `$(document).ready(...)` →
  `document.addEventListener("DOMContentLoaded", ...)`, `$("#dueDate")`/`$("#datepicker")` →

  안전).
- `templates/project/delete.html`: `$(document).ready(...)` → `DOMContentLoaded` 래퍼만 전환

  `DOMContentLoaded`, `$("#milestoneOption .yobicon-refresh")`/`$("#issueDueDate")` →

  `querySelectorAll(...).forEach(el => el.click())`(Subtask.js와 직결), `$('#button-save')
  .on('click', ...)` + `$this.prop('disabled', ...)` → `addEventListener` + `.disabled` 직접

  무관한 다른 기능 코드는 손대지 않았다(요청 원칙 그대로). 세부:
  - `$('#changes')` → `document.getElementById('changes')`.
  - **함정 발견·회피**: `$changesRoot.data('canReviewComment')`는 jQuery가 문자열
    `"true"`/`"false"`를 boolean으로 자동 변환하지만, 네이티브 `dataset.canReviewComment`는
    항상 문자열이라 `data-can-review-comment="false"`도 truthy가 되어 게이트가 깨진다 —
    `=== 'true'`로 명시 비교해 회피(코드에 주석으로 남김).

    `mouseenter`+`mouseleave` 두 리스너/`style.color` 직접 대입.
  - `$changesRoot.on('click', 'tr[data-line] .add-comment-btn-cell', fn)` 위임 바인딩 →
    `changesRoot.addEventListener('click', ...)` + `e.target.closest(...)` +
    `changesRoot.contains(...)` 가드(이미 vanilla로 전환된 `code/diff.html`의 동일 패턴을
    그대로 재사용).
  - `code/diff.html`에 이미 있는 100% vanilla 버전(같은 기능, 다른 스코프)과 대조하며
    포팅해 두 화면의 동작을 동일하게 맞췄다.

   전환과 무관한 기존 버그라 고치지 않았다.
2. **`common/yona.Subtask.js`의 하위이슈 폼 토글이 실제로 열리지 않는다(Playwright로 실측
   재현)** — CSS는 `.subtask-wrap { display:none; } .subtask-wrap.show { display:block; }`로
   `.show` 클래스 토글을 전제하는데, JS는 `subtaskWrap.style.display = willShow ? "" : "none"`로
   **인라인 스타일만** 토글한다. `""`는 클래스 규칙(`display:none`)으로 되돌아갈 뿐이라 클릭해도
   계속 `display:none`으로 남는다 — `.subtask-message`를 실제로 클릭해
   `getComputedStyle(...).display`가 클릭 전후 모두 `"none"`임을 확인했다. 이 파일은 이번
   라운드에서 변경하지 않았고(이미 vanilla 상태였음), 언제 이렇게 됐는지는 조사하지 않았다 —
   jQuery 문법 문제가 아니라 로직 버그라 이 티켓 범위 밖으로 판단해 기록만 남긴다.
3. issue 뷰 페이지(`/issue/{n}`)에서 담당자 Tom Select 렌더링 시
   `tom-select.complete.min.js:127`에서 `Cannot read properties of null (reading
   'setAttribute')` 콘솔 에러가 발생한다(Playwright 실측, issue.Write.js로 이슈를 생성/수정한
   직후 뷰 페이지로 리다이렉트될 때마다 재현). `yona.issue.Assginee.js`(round4 이후 대상,
   이번 라운드 파일 아님) 쪽 문제로 보이며 이번 변경과 무관하다.

- `$(document).ready`/`$(function(){})` → `DOMContentLoaded`. 위임 바인딩(`.on(evt, sel, fn)`)
  → `addEventListener` + `e.target.closest(sel)` + `container.contains(...)` 가드 +

  전부 부르고, 아무도 preventDefault를 안 하면 네이티브 `elem.submit()`으로 폴백한다.

  네이티브 `form.submit()`으로 그냥 바꾸면 각각 pjax 우회/AJAX 우회/400 Bad Request로
  깨진다 — `_triggerSubmit`/`_triggerFormSubmit` 헬퍼(진짜 `dispatchEvent(Event("submit",
  {bubbles:true, cancelable:true}))` 발생 후 `preventDefault` 안 됐으면 네이티브
  `.submit()` 폴백)로 동일한 흐름을 재현했다. **`issue.LabelEditor.js`에서는 최초 구현 시
  이 변환을 놓쳐 실제 회귀가 났던 것을 Playwright로 발견해 수정했다(아래 "발견한 실제

  `Event.currentTarget`은 항상 리스너를 붙인 컨테이너 자신이다(달라짐) — 핸들러가
  `evt.currentTarget`을 쓰던 곳(`issue.LabelEditor.js`의 `_onClickBtnEditCategory`/
  `_onClickBtnEditLabel`)은 `fn.call(matchedEl, e)`로 호출해 `this`로 대체했다.

  `target`도 델리게이션과 무관하게 항상 실제 클릭 지점이라 동일).

  동일하게 라운드9까지 유지.

**전환 패턴(라운드1~5 관례 재사용)**: `$(document).ready`/`$(function(){})` → `DOMContentLoaded`,
`$(selector)` → `getElementById`/`querySelectorAll`(+ `_delegate` 관용구: `addEventListener` +
`e.target.closest(sel)` + `container.contains(matched)` 가드 + `fn.call(matchedEl, e)`),
`.data()` → `dataset`(boolean/JSON 성격은 명시 변환), `$.ajax`/`$.post`/`$.get` → `fetch`
(폼 인코딩은 수동 직렬화, 에러 메시지는 `response.json()` 우선 시도 후 `response.text()`
폴백), `.show()`/`.hide()`는 경쟁하는 CSS class 규칙이 있는 대상마다 매번 확인해 명시적
`"block"`/`"none"` 값을 사용(round5 확립 함정 회피).

**신규로 확립하거나 재확인한 함정**:
1. **jQuery `$.contains(container, el)`은 `container === el`이면 `false`를 반환하는 "진짜
   후손" 검사**인데, 네이티브 `Node.prototype.contains()`는 자기 자신도 `true`로 본다 —
   `board/view.html`/`issue/view.html`의 Ctrl+Shift+Enter 제출 가드에서 `elCommentForm !==
   document.activeElement && elCommentForm.contains(document.activeElement)`로 자기 자신
   케이스를 별도 제외해 동치를 재현했다.
2. **`$form.data(k, v)` 셋터는 DOM 속성이 아니라 jQuery 내부 캐시에만 저장**된다(라운드4
   확립 함정 재확인) — `board/view.html`/`issue/view.html`의 댓글 제출 중(`onsubmit`) 플래그를
   `dataset`로 옮기지 않고 `yona.CommentForm.js`(이미 vanilla)의 `bOnSubmit` 클로저 변수
   관례를 그대로 재사용했다.
3. **`code/view.html`의 폴더 트리 `depth` 캐시**(`.data("depth", n)`)도 서버 렌더링 마크업엔
   전혀 존재하지 않는 순수 JS 내부값이라 `dataset` 대신 커스텀 expando(`el.__depth`)로
   대체 — `.closest(".list-wrap")`이 `null`을 반환할 수 있는 지점(최상위 폴더)에 null 가드를
   추가해 `nParentDepth = (elParentListWrap && elParentListWrap.__depth) || 0`으로 재현했다.
4. **jQuery `.toggle()`(인자 없음)은 호출 시점의 실제 가시성을 보고 방향을 정한다** —
   `code/view.html`의 `onHashChange`가 이미 로드된 폴더를 다시 접었다 펼 때 이 패턴을 쓰는데,
   경쟁하는 CSS 클래스 규칙이 없는 순수 인라인 스타일 대상이라
   `getComputedStyle(el).display === "none" ? "block" : "none"`로 정확히 재현했다.
5. **`common/yona.ReceiverList.js`(댓글창 알림수신자 미리보기)가 이번 라운드/10라운드 계획
   어디에도 명시되지 않은 채 여전히 jQuery API(`.on`/`.closest`/`.find`/`.val`/`.html`)에
   의존한다(범위 밖 발견, 아래 참고)** — `issue/view.html`에서 이 함수를 호출하는 지점 하나만
   `findNotiReceiversHandler($(elCommentTextarea), url)`로 jQuery 래핑을 유지하고, 그 외
   `#comment-form` 로직 전체는 vanilla로 전환했다.
6. **`.affix()`/`.popover()`/`.tooltip()`/`.modal()`/`.placeholder()`/`.requestAs()`/`$.tmpl()`/
   `$.ajaxSend()`/`$.ajaxComplete()`는 전부 코어/플러그인 API라 syntax 치환만으로 vanilla화할
   수 없다** — 라운드1 이후 확립된 "필요한 만큼만 jQuery 유지 + 근거 주석" 원칙을 그대로
   적용해 위 "확정 제외" 목록에 정리한 지점들만 남겼다.
