# P3-70: 잔여 jQuery 의존성 전면 vanilla JS 전환

## 배경

`docs/parity/index.md`/개별 티켓들에 기록된 기존 "jQuery 의존성 점진적 축소" 캠페인(tab/
affix→position:sticky/pjax/tmpl 카테고리, `.modal()`→네이티브 `<dialog>`, `$.ajax/get/post`
→`fetch` 등 다수 라운드, 커밋 이력 다수)이 이미 자체 작성 JS 77개 중 44개를 vanilla로
전환했다. 사용자 요청으로 나머지 33개 + 템플릿 인라인 스크립트 79개 + jQuery 코어 자체까지
전부 제거하는 전면 계획을 세운다.

## 원칙(사용자 확정)

1. **`static/javascripts/lib/` 아래 벤더 라이브러리 파일은 절대 수정하지 않는다** —
   jQuery 기반이든(`jquery.validate.js`/`jquery.form.js`/`bootstrap.js` 등) 이미 vanilla든
   (`tribute.min.js` 등) 전부 손대지 않는다. 전환 대상은 오직 우리 자체 코드
   (`common/service/template`의 JS 파일 + 템플릿 인라인 `<script>`)뿐이다.
2. 벤더 플러그인 사용을 대체할 때는 네이티브 브라우저 API(HTML5 validation, `fetch`,
   Clipboard API, `<dialog>` 등)로 바꾸거나 직접 vanilla 코드를 새로 작성한다. 그 결과
   더 이상 아무도 호출하지 않게 된 벤더 파일은 **`<script src>` 참조만 제거**하고 파일
   자체는 삭제 여부를 별도 판단(이 티켓 범위 밖일 수 있음).
3. 기존 캠페인과 동일한 "완전 동치" 원칙 — 새 기능 추가 금지, 옵션/이벤트/키보드 동작까지
   최대한 동일하게.
4. **각 라운드 전환 후 반드시 Playwright로 실제 브라우저 동작을 사전 검증한다**(사용자
   명시 지시) — 코디네이터가 diff 검토 + 스펙 재실행에 더해 실브라우저 확인까지 마친 뒤에만
   커밋한다.
5. 사용자 승인(2026-09-14)으로 라운드 1부터 10까지 사용자 재확인 없이 연속 진행한다 — 매
   라운드 완료 시 이 티켓에 완료 로그를 남기고 곧바로 다음 라운드 TDD 에이전트를 실행한다.
