## 완료 로그 (원문, `PARITY_BACKLOG.md`의 "완료 로그" 섹션에서 이관)

- **2026-08-20 — P1-76**: 프로젝트 이전/개명 후 예전 owner/name(git remote 등)으로도 계속 조회되는 "이전 위치 폴백" 메커니즘을 이식.
  - `Project.kt`에 `previousOwnerLoginId`/`previousName`/`previousNameChangedTime` 필드 3개 추가(yona `Project.java:131-133` 대응).
  - `ProjectRepository.kt`에 `findFirstByPreviousOwnerLoginIdIgnoreCaseAndPreviousNameIgnoreCaseOrderByPreviousNameChangedTimeDesc()`(yona `findByPreviousPlaceOf()`의 대소문자 무시+최신순 정렬 대응) + Kotlin 인터페이스 default 메서드 `findByOwnerAndNameOrPreviousPlace()`(현재 위치로 못 찾으면 예전 위치로 폴백) 신규.
  - `ProjectServiceImpl.acceptTransfer()`에 `recordRenameOrTransferHistoryIfLastChangePassed24HoursFrom()` 신규 호출 추가(yona 동명 메서드 대응) — 마지막 기록으로부터 24시간이 안 지났으면 예전 위치 포인터를 갱신하지 않는 게이트까지 그대로 재현(짧은 시간 내 연쇄 이전 시 "예전 위치"가 계속 최신으로만 밀리는 것 방지).
  - `ProjectServiceImpl.findByOwnerAndName()`(SVN/Git 인가 필터가 공유하는 서비스 메서드)과 `GitServletConfig.resolveProject()`(git 프로토콜 clone/push URL 파싱)를 새 폴백 메서드를 쓰도록 교체.
  - **발견 후 별도 등록, 이후 완료**: yona는 이 폴백이 `Project.findByOwnerAndProjectName()`이라는 단일 조회 헬퍼를 통해 전체 앱(웹 라우트 포함)에 자동으로 적용되는데, yona는 `ProjectRepository.findByOwnerAndName()`을 서비스 계층을 거치지 않고 28개 컨트롤러 파일이 각자 직접 호출하는 구조라 이 배선을 한 곳으로 모을 수 없었다. 이번엔 백로그가 직접 지목한 증거(git 프로토콜)와 그 서비스 메서드를 공유하는 SVN/Git 인가 필터까지만 배선했고, 나머지 웹 컨트롤러 28곳의 개별 배선은 이번 범위에서 하지 않아 **[[tickets/p1-100|P1-100]]으로 별도 등록** — 이후 26개 파일 전수 배선까지 완료됨(`[x]`, 아래 [[tickets/p1-100|P1-100]] 완료 로그 참고).
