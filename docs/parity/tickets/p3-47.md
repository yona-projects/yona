# P3-47: `board/edit.html` 인라인 스크립트의 따옴표 없는 문자열 대입 (2026-09-10 발견·재현·수정 완료)

## 배경

[[tickets/p3-46|P3-46]](클라이언트 위젯 라이브러리 현대화) 3번 항목(atjs→Tribute.js) 리뷰 중
`jQuery.browser.mozilla` 참조가 크래시를 일으켜 저장 버튼 핸들러가 아예 등록되지 않을 것이라는
가설을 세웠으나, **Playwright(Chromium)로 실제 재현한 결과 이 가설은 틀렸다** — `jQuery.browser`는
실제로는 정의되어 있고(`{chrome:true, version:"...", ...}`) `.mozilla`는 그냥 falsy일 뿐
크래시가 나지 않는다.

**대신 완전히 다른, 확정적인 버그를 실제 브라우저에서 재현했다.** `board/edit.html`의 인라인
`<script>`가

```js
var owner = [[${project.owner}]];
var projectName = [[${project.name}]];
```

로 되어 있었는데, `project.owner`/`project.name`은 **문자열**인데도 따옴표 없이 대입돼 있었다
(바로 위 `var projectId = [[${project.id}]];`는 숫자라 따옴표 없이도 맞음 — 문자열 두 줄만
빠짐). 렌더링된 실제 HTML을 확인하니 `var owner = admin;`처럼 나가 `ReferenceError: admin is
not defined`가 발생했고, 이 코드는 `$("#post-form").submit(function(e){ e.preventDefault();
... })` 핸들러 안 `e.preventDefault()` 바로 다음 줄이라 — 네이티브 제출은 막혔는데 AJAX 저장
로직은 예외로 중단되어 저장 버튼이 완전히 무반응이었다. Playwright로 로그인→프로젝트 생성→
게시글 생성→수정→저장까지 end-to-end 재현해 확인.

## 전수 검색으로 찾은 "같은 패턴"이 실제로는 대부분 오탐이었음 (중요한 정정)

처음엔 같은 패턴(`var x = [[${project.owner}]];`, 따옴표 없음)을 `grep`으로 5개 파일에서 더
찾아 총 6개 파일을 한꺼번에 고쳤으나, **`board/edit.html`을 제외한 5개(`pullrequest/edit.html`,
`board/list.html`, `milestone/list.html`, `milestone/view.html`, `issue/partial_massupdate.html`)는
전부 오탐이었다** — 이 5개 파일은 해당 `<script>` 태그에 `th:inline="javascript"`가 이미
붙어있어서, Thymeleaf가 `[[${...}]]`를 JS 문자열로 안전하게 따옴표/이스케이프 처리해 자동
렌더링한다(`var owner = "admin";`처럼 정상 출력됨 — 크래시 없음). `board/edit.html`만 그
`<script>` 태그에 `th:inline="javascript"`가 없어서(일반 HTML 텍스트 치환으로 처리되어
따옴표가 안 붙음) 유일하게 실제로 깨져 있었다. 5개 파일에 적용했던 변경은 전부
`git checkout`으로 원복했다(동작 차이는 없었을 것이나 불필요한 변경이라 되돌림).

**교훈**: `[[${...}]]`가 `var x = ...`에 따옴표 없이 쓰인 걸 봤다고 바로 버그로 단정하면 안
된다 — 그 `<script>` 태그(또는 상위)에 `th:inline="javascript"`가 있는지 반드시 함께 확인해야
한다.

## 수정 내용

`board/edit.html` 95-96행을, 이 저장소에 이미 존재하는 올바른 관용구(`code/nohead.html`,
`code/nohead_svn.html`이 쓰는 패턴)로 맞췄다:

```js
// 수정 전
var owner = [[${project.owner}]];
var projectName = [[${project.name}]];

// 수정 후
var owner = /*[[${project.owner}]]*/ '';
var projectName = /*[[${project.name}]]*/ '';
```

Playwright로 재검증한 결과 **`ReferenceError: admin is not defined`는 더 이상 발생하지 않는다**
(수정 확인됨).

## 남은 문제 — 같은 화면에 별도의 CSRF 버그가 있어 저장은 여전히 실패함

위 수정 후에도 board/edit 저장 버튼을 실제로 눌러보면 **여전히 저장되지 않는다** — 이번엔
`ReferenceError`가 아니라 `PUT /api/projects/{id}/posts/{postId}`가 **403 Forbidden**으로
거부된다(`$.ajax`가 CSRF 토큰을 헤더에 안 실어 보냄). 이건 완전히 별도의 원인이고 범위도 훨씬
넓어 **[[tickets/p3-48|P3-48]]로 분리**했다 — 자세한 내용은 그 티켓 참고.

**즉 이 티켓(P3-47)이 고친 건 "저장 버튼을 눌렀을 때 JS가 크래시하던 것"이고, "저장이 실제로
반영되는 것"은 P3-48이 끝나야 완성된다.**
