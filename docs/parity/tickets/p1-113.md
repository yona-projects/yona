# P1-113: **(2026-08-21 백엔드 전수 감사에서 발견 — 게시판 도메인)** 공개 프로젝트 비멤버의 게시글 작성 권한이 yona보다 과도하게 제한(회귀) — 근본 원인은 Board만의 실수가 아니라, yona `IssueViewController.createIssueForm`에 이미 존재하는 정답 패턴(`accessControl.isProjectResourceCreatable(user, project, ResourceType.ISSUE_POST)`)을 `BoardViewController.createPost`/`createPostForm`이 재사용하지 않고 `existsByProjectIdAndUserId(...) || isAllowedIfGroupMember(...)`라는 별도의 좁은 검사만 쓰는 것. 동일한 `checkWritePermission` 패턴이 `PullRequestController`/`ReviewApiController`에도 복제돼 있었으나 재확인 결과 그쪽은 [[tickets/p1-78|P1-78]](ACCEPT 권한) 규칙을 정확히 재현한 것이라 회귀가 아니었음(별도 확인 완료).

## 완료 로그 (원문, `PARITY_BACKLOG.md`의 "완료 로그" 섹션에서 이관)

- **2026-08-21 — P1-113**: `BoardController.createPosting()`/`BoardViewController.createPost()`/`createPostForm()`의 게시글 작성 권한을 yona 수준으로 확장(회귀 수정).
  - Serena LSP로 yona `BoardApp.java:119,211 @IsCreatable(ResourceType.BOARD_POST)`를 재확인 — `AccessControl.isProjectResourceCreatable()`는 사이트매니저/조직관리자/프로젝트멤버/그룹멤버 우회에 더해, **공개 프로젝트라면 비멤버 로그인 사용자도 BOARD_POST를 포함한 여러 리소스 타입을 생성할 수 있다**는 걸 확인. yona의 세 지점(`checkWritePermission`/`createPost`/`createPostForm`)은 모두 `existsByProjectIdAndUserId(...) || isAllowedIfGroupMember(...)`라는 멤버십 전용 좁은 검사만 써서 공개 프로젝트 비멤버를 부당하게 차단하고 있었음.
  - `BoardController.checkWritePermission()`(→`createPosting()`에서만 쓰임, UPDATE/DELETE는 별도의 더 엄격한 규칙이라 영향 없음), `BoardViewController.createPost()`/`createPostForm()`의 좁은 검사를 `accessControl.isProjectResourceCreatable(user, project, ResourceType.BOARD_POST)`로 교체. `createPostForm()`의 `isAllowedToNotice`(BOARD_NOTICE 권한)는 원래도 멤버십 전용이 legacy와 일치해 그대로 둠.
  - 이미 정확했던 `PullRequestController`/`ReviewApiController`의 동일 패턴은([[tickets/p1-78|P1-78]] ACCEPT 규칙 재현) 이번 수정 대상에서 제외 — 재확인 완료.
  - 테스트: `BoardControllerSpec.kt` +1(공개 프로젝트 비멤버 작성 성공), `BoardViewControllerSpec.kt` +1(공개 프로젝트 비멤버 `createPost` 성공) — 이 과정에서 기존 [[tickets/p1-109|P1-109]]/[[tickets/p1-110|P1-110]]/[[tickets/p0-22|P0-22]] 테스트가 `user.isMemberOf(project)`(엔티티 관계) 기반 검사로 바뀌며 함께 깨져, 해당 테스트들에 로컬 `memberUser`(projectUsers에 실제 멤버십 추가)를 붙여 회귀 원인을 제거.
  - 검증: `./gradlew test --tests "...BoardControllerSpec" --tests "...BoardViewControllerSpec"` 전체 통과. 전체 `./gradlew test`는 사용자 요청에 따라 5건 단위로 실행하기로 해 이번 항목 단독으로는 생략, [[tickets/p1-114|P1-114]] 완료 후 함께 확인 예정.
