## 완료 로그 (원문, `PARITY_BACKLOG.md`의 "완료 로그" 섹션에서 이관)

- **2026-08-22 — P2-33**: 본문에 순수 이슈 URL(`https://호스트/owner/project/issue/5` 형태, 링크 텍스트 없이 URL 그대로)을 쓰면 자동으로 `#5.이슈제목` + 상태뱃지로 치환하고 READ 권한이 없으면 원래 링크 그대로 두는 legacy `Markdown.java transformIssueLink()`/`extractIssueLink()`가 yona에 전혀 없던 것을 신규 이식(대응 코드 자체가 없었음, 의역이 아니라 순수 신규 구현).
  - `MarkdownServiceImpl` 생성자에 `ProjectRepository`, `IssueRepository`, `UserRepository`, `AccessControl`, `MessageSource`를 추가로 주입(이슈 조회 + 권한 판단 + i18n 상태 라벨에 필요).
  - `transformIssueLink(source)`: Jsoup으로 `href` 속성이 있는 요소를 순회하며, `href`가 `/`로 시작하거나 호스트가 `hostname`으로 시작하고(내부 링크) `linkText == href`(commonmark `AutolinkExtension`이 만든, 텍스트 없이 URL 그대로인 순수 자동링크만 대상 — `[텍스트](url)`처럼 별도 텍스트가 있는 링크는 legacy와 동일하게 제외)인 첫 번째 링크에 대해 `rel`에 `noreferrer`를 추가하고 `extractIssueLink()`를 호출, 성공하면 순회 중단(legacy가 첫 번째 매치만 처리하고 break하는 것과 동일).
  - `extractIssueLink(el, uri)`: 경로에서 `/issue/\d+` 패턴을 찾아 owner/projectName/number를 파싱 → `projectRepository.findByOwnerAndName`/`issueRepository.findByProjectAndNumber`로 조회 실패 시 조용히 원래 링크 유지(치환 없음) → `accessControl.isAllowed(currentUser, project, issue, Operation.READ)`가 거짓이면 마찬가지로 원래 링크 유지(권한 없는 사용자에게 이슈 제목이 노출되는 정보 누출 방지, legacy 원문 그대로) → 허용되면 링크 텍스트를 `#번호.제목`(+ URL fragment가 있으면 `#fragment` 추가)으로 교체하고 `issueLink` 클래스, `issue-state` + 상태값 클래스가 붙은 `span`(메시지소스로 i18n된 상태 라벨, 키 없으면 상태값 그대로 폴백)을 덧붙임. 숫자 파싱 실패 등 런타임 예외는 legacy처럼 로그만 남기고 원래 링크를 그대로 둠.
  - `resolveCurrentUser()`: `SecurityContextHolder`에서 인증 정보를 읽어 `UserRepository.findByLoginId`로 조회(이 세션에서 이미 여러 파일에 정착된 Spring Security 표준 패턴 재사용, `UserApp.currentUser()`의 yona 대응).
  - **아키텍처적으로 이식하지 않은 부분(의도적 축약이 아님, 근거 명시)**: `AutoLinkRenderer.kt`가 이미 갖고 있는 `#5` 형태 텍스트기반 이슈뱃지 자동링크 인프라와 상당 부분 겹치지만 병합하지 않음 — legacy 자체가 `transformIssueLink`(이미 렌더된 HTML의 DOM을 순회하며 순수 URL 링크를 찾는 방식)와 shortcode 기반 자동링커(텍스트 노드에서 `#5` 정규식을 스캔하는 방식)를 서로 다른 두 메커니즘으로 분리해 두고 있어, yona에서도 legacy의 실제 코드 구조를 그대로 반영(중복은 "동일한 데이터가 우연히 겹치는 것"이지 아키텍처적 단순화 기회가 아니라고 판단).
  - 테스트(TDD, 레드 확인 후 그린): `MarkdownServiceImplSpec.kt`에 `describe("MarkdownServiceImpl 순수 이슈URL 자동 링크화 (P2-33)")` 신규 4 tests(같은 호스트의 순수 이슈 URL이 `#5.버그 수정` + `issueLink` 클래스 + `issue-state` 뱃지로 치환/READ 권한 없는 이슈는 원래 링크 그대로 유지/`[텍스트](url)`처럼 별도 텍스트가 있는 링크는 `linkText != href`라 치환 안 됨/같은 호스트라도 이슈 경로가 아닌 URL은 치환 안 됨). 초기에 권한거부 테스트 URL을 `/issue/5-noaccess`로 잘못 만들어 `toLong()`이 `NumberFormatException`으로 실패해 권한체크 코드 경로 자체를 타지 않고 우연히 통과하던 버그를 발견해, 별도의 `privateIssue`/`/issue/6` 픽스처로 교체.
  - 검증: `./gradlew test --tests "com.github.yonaprojects.yona.domain.support.MarkdownServiceImplSpec"` 전체 통과, `./gradlew test`(전체 스위트) 통과(실패 0, 2m 3s).
