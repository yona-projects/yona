## 완료 로그 (원문, `PARITY_BACKLOG.md`의 "완료 로그" 섹션에서 이관)

- **2026-08-20 — P1-90**: `CommentServiceImpl.hasPermission()`이 이슈/게시글 댓글 UPDATE·DELETE를 "작성자 또는 프로젝트 매니저"로만 제한하던 과잉 제한 버그 수정 — legacy는 `isMemberOf(project)`만 있으면 일반 멤버 전원에게 허용한다(`AccessControl.java:280-282`).
  - `CommentServiceImpl`에 `AccessControl` 주입(기존 `ProjectUserRepository`는 이 클래스에서 `hasPermission()` 외 다른 용도가 없어 제거), 4개 호출부(`updateIssueComment`/`deleteIssueComment`/`updatePostingComment`/`deletePostingComment`)를 [[tickets/p1-85|P1-85]] 1b에서 추가한 리소스 타입별 오버로드(`isAllowed(author, comment.issue.project, comment, Operation.UPDATE/DELETE)`, `isAllowed(author, comment.posting.project, comment, Operation.UPDATE/DELETE)`)로 교체하고 기존 `hasPermission()` 사설 헬퍼는 삭제(작성자 우회 포함 모든 판정을 중앙 함수가 대체).
  - **테스트 작성 중 발견한 결함**: 새로 추가한 "비작성자·비매니저 프로젝트 멤버도 수정/삭제 가능" 테스트가 처음엔 `Permission denied`로 실패했다 — `AccessControl.isMemberOf()`가 DB 조회가 아니라 `User.projectUsers` 엔티티 컬렉션을 직접 읽는데, `projectUserRepository.save(ProjectUser(...))`만으로는 이미 메모리에 들고 있던 `otherMember` 인스턴스의 `projectUsers`가 갱신되지 않기 때문(재조회 전까지 지연 컬렉션이 새 행을 반영하지 않음) — `otherMember.projectUsers.add(projectUser)`로 양쪽에 반영해 해결(로직 결함이 아니라 테스트 fixture 결함이었음).
  - 테스트: `CommentServiceSpec.kt` +3(작성자·매니저가 아닌 프로젝트 멤버의 이슈 댓글 수정 허용/프로젝트 비멤버의 이슈 댓글 수정 거부/작성자·매니저가 아닌 프로젝트 멤버의 게시글 댓글 삭제 허용) — 기존 2건 포함 총 5 tests.
  - 검증: `./gradlew test --tests "com.github.yonaprojects.yona.domain.comment.CommentServiceSpec"` 5 tests 전체 통과, `./gradlew compileKotlin compileTestKotlin` 전체 컴파일 성공, 전체 스위트 `./gradlew test` 935 tests 전체 통과(실패 0).
