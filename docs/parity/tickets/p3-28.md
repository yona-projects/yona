# P3-28: `PullRequestController`의 8개 엔드포인트가 순환 참조로 부풀고 비밀번호 해시까지 노출됨

## 배경

P3-26(`pushedBranches` API)과 정확히 같은 근본원인의 문제가 `PullRequestController.kt`에도
광범위하게 남아있었다. 코드 내 기존 주석에 이미 "버그8"이라는 이름으로 알려진 문제였고
`mergePullRequest`/`changeState`는 이미 `.toResponse()`로 방어돼 있었지만, 나머지 8개
엔드포인트는 방어되지 않은 채 남아있었다: `getPullRequest`, `createPullRequest`,
`updatePullRequest`, `deleteFromBranch`, `restoreFromBranch`, `setAssignee`,
`removeAssignee`, `addLabel`, `removeLabel`.

실제 앱을 기동해 `POST /api/projects/1/pullrequests`(PR 생성 — `pullrequest/create.html`의
JS가 직접 호출하는 바로 그 엔드포인트)를 호출해 재현: 응답 60451바이트, `User.password`/
`passwordSalt` 해시값이 그대로 노출됨을 확인.

## 완료 로그

**(2026-09-09) 발견 즉시 수정.**

- `PullRequestController.kt`: 위 8개 메서드의 반환 타입을 `ResponseEntity<PullRequest>` →
  `ResponseEntity<Any>`로 바꾸고 본문을 전부 `.toResponse()`(`RestApiResponseDto.kt`의 기존
  `PullRequestResponse` DTO, `mergePullRequest`/`changeState`가 이미 쓰던 것과 동일)로 감쌌다.
- `PullRequestApiController.kt`: 위 8개를 호출하며 `.mapBody { it.toResponse() }`로 이중
  변환하던 7곳(`create`/`get`/`setAssignee`/`removeAssignee`/`addLabel`/`removeLabel`/
  `update`)에서 `mapBody` 호출 제거 — 이미 DTO로 변환된 값을 그대로 전달(`merge`/`close`/
  `reopen`이 이미 쓰던 패턴과 동일하게 통일).
- `PullRequestMcpTools.kt`(P3-07 MCP 서버): `get_pull_request`/`create_pull_request`가
  `.unwrapForMcp().toResponse()`로 이중 변환하던 것도 동일하게 `.toResponse()` 제거.
- 컴파일 확인 후 `PullRequestControllerSpec`/`PullRequestApiControllerSpec`/
  `DirectPullRequestControllerCoverageSpec`/`PullRequestMcpToolsSpec` 전부 재실행 GREEN.
- 실사용 재검증: 실제 앱 기동 후 PR 생성/조회/담당자 지정을 실제로 호출 — 응답이 `id`/
  `number`/`title`/`toProject`(id/owner/name만)/`contributor`(id/loginId/name만) 등 최소
  필드만 담은 깔끔한 JSON으로 확인, `password` 문자열 재검색 결과 0건.

## 완료 기준

- `PullRequestController`/`PullRequestApiController`의 어떤 엔드포인트도 raw 엔티티를
  직접 반환하지 않는다(전부 DTO 변환).
- 실제 PR 생성/조회 응답에 비밀번호 해시가 노출되지 않는다(실사용 검증 완료).
