## 완료 로그 (원문, `PARITY_BACKLOG.md`의 "완료 로그" 섹션에서 이관)

- **2026-08-20 — P1-22**: 사용자가 특정 프로젝트의 특정 이벤트 타입 알림을 끌 수 있는 `UserProjectNotification`(뮤트 토글) 엔티티·리포지토리·설정 API(`WatchController`)는 이미 yona에 있었지만, 실제 알림 수신자를 계산하는 어느 코드에서도 이 설정을 조회하지 않아 뮤트를 꺼도 계속 알림이 오던 문제 수정(yona `NotificationEvent.filterReceivers()`의 `UserProjectNotification.isEnabledNotiType()` 대응).
  - yona `filterReceivers()`를 그대로 옮기는 대신, 이 저장소의 모든 알림 발행 경로가 공통으로 거치는 `WatchService.findActualWatchers()`에 통합했다 — `IssueServiceImpl`/`CommentServiceImpl`/`PostingServiceImpl` 개별 수정 없이 한 곳에서 일관되게 적용되도록 하기 위함(단, 호출부는 실제 `eventType`을 넘겨줘야 하므로 `IssueServiceImpl`/`CommentServiceImpl`/`PostingServiceImpl`/`PullRequestServiceImpl`/`CodeReviewServiceImpl`/`GitPostReceiveEventListener`의 `findActualWatchers()` 호출부 다수에 `eventType = notificationEvent.eventType` 인자를 추가했다).
  - `WatchService.findActualWatchers()`에 `eventType: EventType? = null` 파라미터 추가(뒤에 추가해 기존 호출부 호환 유지, 다만 뮤트 필터가 실제로 동작하려면 값을 넘겨야 함). `WatchServiceImpl`은 감시자 집합을 "프로젝트 감시로만 포함된 사용자"(baseWatcher도 아니고 리소스를 직접 감시하지도 않음)와 그 외로 구분해, 전자에게만 `UserProjectNotificationRepository.findByUserAndProjectAndNotificationType()` 설정을 확인 — 설정이 없으면 yona `isNotifiedByDefault()`와 동일하게 `NEW_COMMENT`만 기본 OFF, 나머지는 기본 ON.
  - 테스트: `WatchServiceSpec.kt` +4(이벤트타입별 뮤트 시 제외, 뮤트 설정 없으면 기본 수신, `NEW_COMMENT`는 프로젝트 감시만으로는 기본 미수신, 리소스를 직접 감시 중이면 뮤트와 무관하게 항상 포함) — 기존 5건 포함 총 9 tests. `IssueServiceSpec`/`CommentServiceSpec`/`PostingServiceSpec`/`WatchControllerSpec`/`YonaApplicationTests` 재실행으로 회귀 없음 확인(기존 시나리오들은 뮤트 설정을 두지 않아 항상 기본값 경로를 타므로 영향 없음).
  - 검증: `./gradlew test --tests "WatchServiceSpec" --tests "IssueServiceSpec" --tests "CommentServiceSpec" --tests "PostingServiceSpec" --tests "WatchControllerSpec" --tests "YonaApplicationTests"` 전체 통과, `./gradlew compileKotlin compileTestKotlin` 전체 컴파일 성공.
