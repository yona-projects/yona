## 완료 로그 (원문, `PARITY_BACKLOG.md`의 "완료 로그" 섹션에서 이관)

- **2026-08-22 — P2-35**: `AutoLinkRenderer.toValidSHALink()`(commit SHA 텍스트 자동 링크화)가 yona `utils/AutoLinkRenderer.java:275` `!project.isCodeAvailable() || !project.isGit()`와 달리 `vcs=="GIT"` 여부만 검사하고 `isCodeAvailable()`(legacy `menuSetting == null || menuSetting.code`, yona `project.isCodeEnabled`) 검사가 빠져 있던 문제 수정 — 코드브라우저 메뉴를 끈 GIT 프로젝트에서도 게시글/댓글/커밋메시지 등에 쓰인 커밋 SHA가 (존재하지 않는 코드브라우저 URL을 가리키는) 링크로 잘못 변환되고 있었다.
  - `toValidSHALink(prefix, project, sha)` 최상단 vcs 검사 조건에 `!project.isCodeEnabled ||`를 추가 — `isCodeEnabled=false`면 저장소 조회(`repositoryService.getRepository`) 자체를 시도하지 않고 즉시 빈 링크 반환(legacy도 `isCodeAvailable()` 실패 시 저장소 접근 이전에 조기 반환).
  - 이 클래스에 대응하는 전용 테스트 파일이 이전에 없어(간접적으로 `MarkdownServiceImplSpec.kt`에서만 실인스턴스로 쓰임) `AutoLinkRendererSpec.kt`를 신규 작성.
  - 테스트(TDD, 레드 확인 후 그린): `AutoLinkRendererSpec.kt` 신규 2 tests — `isCodeEnabled=true`인 GIT 프로젝트는 SHA가 커밋 링크로 변환됨(기존 동작 보존 확인) / `isCodeEnabled=false`면 GIT이어도 SHA가 링크로 바뀌지 않고 `repositoryService.getRepository`가 아예 호출되지 않음. 신규 spec의 mock 인스턴스가 top-level에서 재사용되는데 `beforeTest`에 `clearMocks`가 없어 첫 테스트의 호출 이력이 두 번째 테스트의 `verify(exactly=0)`을 오염시키던 문제를 `beforeTest { clearMocks(...) }` 추가로 수정(이 세션에서 이미 여러 번 확인된 "top-level mock은 clearMocks 없이 호출 이력이 테스트 간 누적된다" 패턴의 재발).
  - 검증: `./gradlew test --tests "com.github.yonaprojects.yona.domain.support.AutoLinkRendererSpec"` 전체 통과, 전체 스위트 `./gradlew test` 통과(실패 0).
