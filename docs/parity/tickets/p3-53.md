# P3-53: P3-46 8-1/8-2단계(EasyMDE 셸 교체·미리보기 연동)에서 남겨진 죽은 코드·미정리 항목 묶음

## 배경

P3-46(클라이언트 위젯 라이브러리 현대화) 8단계 중 1단계(EasyMDE 셸 교체)와 2단계(미리보기
서버 연동)를 진행하며 "범위 밖 발견"으로 티켓 완료 로그에 기록만 해두고 별도 백로그로
승격하지 않았던 항목들이다. 사용자가 "8-1에서만 8개 정도 나왔던 것 같은데 왜 간추리냐"고
지적해, [[tickets/p3-46|P3-46]] 완료 로그에 흩어져 있던 항목을 하나도 누락 없이 재정리해
공식 백로그 항목으로 등록한다.

## 세부 항목 (총 8개)

1. **`yona.CommentAttachmentsUpdate.js`가 애초에 어느 템플릿·번들에서도 로드된 적 없음** —
   8-1단계 에이전트가 "드래그앤드롭 파일첨부가 깨질 수 있다"는 위험을 짚으며 근거로 든 파일.
   1차 결론은 "이 파일 자체가 죽은 코드라 EasyMDE와 무관"이었음. → 실제로는 [[tickets/p3-49]]에서
   "댓글 **수정** 폼 전용 파일이며 `<script src>`로 로드된 적이 없다"는 진짜 원인으로 재규명되어
   **해소됨(완료)**.
2. **`yona.SubComment.js`도 어느 템플릿·번들에서도 로드된 적 없음** — 1번과 같은 문맥에서 함께
   지목된 죽은 코드. 이 파일 자체의 기능(대댓글 관련 추정)이 실제로 필요한지, 완전히 죽은
   기능인지는 **별도로 확인된 적이 없다 — 미착수**.
3. **`issue/view.html`의 `<script>` 안 `<th:block th:if>` 중첩으로 `yobi.issue.View` 모듈
   자체가 파싱 실패해 안 뜨는 버그** — 사용자가 "실제로 드롭까지 해봤냐"고 재확인시켜
   Playwright로 실제 재현해 드러난 진짜 원인 중 하나. → [[tickets/p3-49]]에서 **수정 완료**.
4. **`yona.CommentAttachmentsUpdate.js`가 포팅은 됐지만 `<script src>`로 로드된 적이 없는
   버그**(1번과 동일 파일, "죽은 코드"가 아니라 "로드 누락"이라는 별개 원인으로 재규명) —
   → [[tickets/p3-49]]/[[tickets/p3-50]]으로 분리. **완전히 해소됨(완료)** — P3-50(커밋
   `9eaa92498`, 2026-09-11)에서 `issue/view.html`/`board/view.html` 양쪽에 실제 로드
   완료, 게다가 그 과정에서 훨씬 심각한 자매 버그(`yobi.Files.js`/`yobi.Attachments.js`도
   동일하게 미로드돼 있어 첨부파일 링크 삽입이 저장 시점에 통째로 사라지는 데이터손실급
   결함)까지 발견·수정.
5. **`PullRequestListTemplateEquivalenceSpec`의 select2.js 스크립트 존재 단언(214번째 줄)이
   stale함** — 항목5(Select2→Tom Select 전환)에서 이미 제거된 리소스를 여전히 기대하는
   기존 단언. 발견 당시엔 `git stash` 대조로 확인만 하고 손대지 않았으나, **P3-51(커밋
   `4dc86ba74`, 2026-09-11) 재검토 중 함께 해소됨(완료)**.
6. **`.nav-tabs.small` CSS 규칙(`yobi.css`)이 구 탭 UI 제거로 고아가 됨** — 동작에는 영향
   없어 그대로 방치됨. **미착수**.
7. **`.markdown-preview` div의 `editorMode` 클래스 분기** — 8-1단계에서 실사용처를 못 찾아
   일단 제거했으나 100% 확신하지 못해 "2단계에서 재확인 필요"로 남겼던 항목. → 8-2단계에서
   `yobi.css`/전체 JS 재grep으로 재확인해 이 분기를 읽는 규칙이 정말 없음을 확정.
   **완전히 해소됨(완료)**.
8. **8-1단계의 "드래그앤드롭 문제 없음" 최초 결론 자체가 틀렸었다는 메타적 교훈** — 1차
   조사(소스 grep만)로는 "EasyMDE 탓 아니고 문제 없다"고 결론 냈으나, 사용자가 실제 브라우저
   재현을 요구해서야 진짜 회귀(3·4번)가 드러났다. 향후 유사한 "코드 안 읽었지만 문제
   없어 보인다"류 결론은 실제 브라우저 재현 없이는 확정하지 말 것 — **별도 코드 변경 대상이
   아니라 작업 방식에 대한 기록**.
