  **완료** — 46곳의 네이티브 쿼리(전부 순수 ANSI SQL)가 H2에서도 수정 없이 통과함을 15개 이상의 실제 DB 통합테스트 스펙(IssueServiceSpec/PostingServiceSpec/각종 RepositorySpec 등)으로 확인. **TDD로 진짜 버그 하나 발견·수정**: `DataBackupServiceImpl`([[tickets/p0-07|P0-07]]/[[tickets/p2-07|P2-07]], 사이트 백업/복원)이 `Dialect.OTHER`(알 수 없는 DB는 auto-increment/시퀀스 재설정을 건너뜀)로 처리되던 걸 `Dialect.H2`로 명시 추가하는 과정에서, 복원 직후 신규 저장 시 PK 충돌이 실제로 재현됨(`DataBackupServiceH2IntegrationSpec.kt`로 고정) — H2 identity 컬럼은 MariaDB의 AUTO_INCREMENT와 달리 명시적 INSERT 값을 보고 스스로 전진하지 않음(PostgreSQL의 SERIAL과 동일한 함정, 실측 확인). `SET REFERENTIAL_INTEGRITY {TRUE|FALSE}`(FK 토글)와 `ALTER TABLE ... ALTER COLUMN id RESTART WITH n`(시퀀스 복원, 둘 다 H2 고유 구문 실측 확인)으로 해결. 이 과정에서 `hasIdColumn()`이 컬럼명 패턴 `"id"`를 그대로 JDBC 메타데이터 조회에 넘기던 게 H2가 unquoted 컬럼명을 대문자(`ID`)로 저장하는 것과 안 맞아 오탐하던 기존 잠재 버그도 함께 발견해 대소문자 무관 비교로 수정(MariaDB/PostgreSQL 회귀 없음, 전체 스위트 재확인). **알려진 한계(문서화)**: H2의 identity "다음 값"을 직접 조회하는 표준 SQL이 없어(`INFORMATION_SCHEMA.SEQUENCES`에 노출 안 됨, 실측 확인) `MAX(id)+1`로 근사 — MariaDB/PostgreSQL과 달리 export 이전에 이미 삭제된 행으로 생긴 시퀀스 갭까지는 보존하지 못함.
