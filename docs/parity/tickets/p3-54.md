# P3-54: `site/postList.html`/`site/issueList.html`이 작성자가 탈퇴(또는 authorLoginId가
null)한 게시글/이슈를 목록에 렌더링할 때 500 에러

## 배경

`site/postList.html`/`site/issueList.html`이 각각 다음과 같이 게시글/이슈 작성자를
조회한다:

```html
th:with="user=${userRepository.findByLoginId(post.authorLoginId).orElse(null)}"
th:with="user=${userRepository.findByLoginId(issue.authorLoginId).orElse(null)}"
```

`UserRepository.findByLoginId(loginId: String)`는 파라미터 타입이 non-null(Kotlin)이라
Spring Data의 null 안전성 검사기(`NullnessMethodInvocationValidator`)가 호출 자체를
`IllegalArgumentException("Parameter loginId ... must not be null")`으로 막는다.
`.orElse(null)`은 "조회했지만 못 찾았을 때"만 처리할 뿐, "애초에 null을 넘겨 호출이 실패하는
경우"는 막지 못한다. `post.authorLoginId`/`issue.authorLoginId`가 null인 레코드(작성자
탈퇴 등으로 발생 가능)가 하나라도 있으면 사이트 관리자 게시글/이슈 목록
(`/sites/postList`, `/sites/issueList`) 전체가 `TemplateProcessingException`으로 500
에러가 난다.

## 발견 경위

이 두 건은 이미 `docs/TWIRL_THYMELEAF_RENDERING_AUDIT_2026-09-11.md`(2026-09-11) 시점에
baseline 실패 3건 중 2건(`SiteAdminTemplateEquivalenceSpec`)으로 기록돼 있던 것으로,
이번 P3-48/50/51/52 작업과 무관한 기존 결함이다. 작업 완료 후 마지막 전체 회귀 스위트
(6,594건 중 실패 2건, 에러 0건)를 코디네이터가 재확인하며 재차 확인했다 — 4개 티켓의
변경분과는 파일이 전혀 겹치지 않음을 `git diff`로 직접 검증.

참고로 담당 TDD 에이전트가 이 감사 도중 자체적으로 RED→GREEN 수정(널 가드 삼항연산자
추가 + 전용 회귀 테스트 2건)까지 만들어뒀으나, **사용자 지시로 이번 라운드에서는 채택하지
않고 되돌렸다** — 백로그 등록만 하고 별도 라운드에서 착수하기로 결정.

## 제안하는 다음 단계

`th:with="user=${post.authorLoginId != null ? userRepository.findByLoginId(post.authorLoginId).orElse(null) : null}"`
식의 널 가드 추가(또는 `UserRepository`에 null-safe 오버로드 신설)로 간단히 해결 가능할
것으로 보인다 — 착수 시 TDD로 `authorLoginId`가 null인 게시글/이슈 픽스처를 만들어 RED를
먼저 확인한 뒤 진행할 것.
