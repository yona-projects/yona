# P3-65: 첨부된 동영상이 Video.js 스킨 없이 브라우저 기본 컨트롤로만 재생됨

## 배경

`lib/videojs`(Video.js 플레이어)는 legacy v1.6.1에는 존재하지 않았다(파일 자체가
`git ls-tree v1.6.1`에서 0건) — legacy 커밋 `052174d25`(2020-06-14, "dependency: Introduce
video-js player")로 나중에 추가된 기능이다. 최신 legacy(HEAD)의 `app/views/issue/view.scala.html`
(488·492행)에서 지금도 로드·사용 중이다. legacy의 markdown sanitizer
(`app/utils/Markdown.java`의 `sanitizerPolicy`)도 `<video>`/`<source>` 태그와
`data-setup`/`controls`/`autoplay` 등 속성을 명시적으로 허용목록에 두고 있다.

## 현재 yona 상태 (격차 확정 — 예상보다 가벼움)

**좋은 소식**: yona의 markdown sanitizer(`MarkdownServiceImpl.kt` 55~71행)는 이미 legacy와
거의 동일하게 `<video>`/`<source>` 태그와 관련 속성을 허용목록에 포함하고 있고,
`common/yobi.Attachments.js`(`_getLinkText()`, 468~489행)도 동영상 첨부 시 legacy와 동일한
마크업을 이미 생성한다:

```js
$(`<video class="video-js" data-setup='{}'>`)
    .attr('controls', true)
    .append($('<source>').attr('src', sFilePath).attr('type', sMimeType))
```

즉 동영상 첨부 → 마크다운 삽입 → 서버 렌더링(sanitize 통과) 파이프라인은 legacy와 동치로
이미 동작한다. `class="video-js"`/`data-setup='{}'`는 Video.js가 있을 때만 인식하는
속성이라, Video.js 라이브러리(`lib/videojs/video.min.js`, `video-js.min.css`)가 로드되지
않은 지금 yona에서는 이 속성들이 그냥 무시되고, **브라우저 기본 HTML5 `<video controls>`
플레이어로 정상 재생된다**(`controls` 속성과 실제 `<source src="...">`가 있으므로 재생 자체는
문제없음).

**실제 격차는 순수 시각적 스킨 차이뿐이다**: legacy는 Video.js의 커스텀 UI(브라우저 간 통일된
컨트롤 디자인)로 보이는 반면, yona는 각 브라우저의 기본 video 컨트롤 UI로 보인다. 콘텐츠
손실이나 재생 불가 같은 기능적 문제는 없다.

## 영향도

기능 손실 없음 — 순수 시각적 일관성 문제. 우선순위는 낮게 보는 것이 합리적이다.

## 제안

이 티켓은 순수 조사 산출물이며 구현은 하지 않았다(사용자 지시로 백로그 등록만 완료). 착수 시:

1. `issue/view.html`(legacy와 동일하게 이슈 상세 화면 한정 — legacy도 board 쪽엔 videojs를
   로드하지 않음)에 `lib/videojs/video-js.min.css`+`video.min.js`를 로드한다 — 마크업은 이미
   Video.js 호환 형태로 생성되고 있으므로 라이브러리 스크립트/스타일 추가만으로 자동
   활성화될 것으로 예상된다(Video.js는 `class="video-js"` 요소를 자동 스캔해 초기화).
2. Playwright로 "동영상을 첨부하면 Video.js 플레이어 UI로 렌더링된다"만 1회 확인하면 충분하다.

## 해결 (2026-09-12)

`issue/view.html`(이슈 상세 화면 한정)에 `lib/videojs/video-js.min.css`(`<link>`)와
`video.min.js`(`<script>`)를 로드했다. 별도 초기화 스크립트는 추가하지 않았다 — 제안대로
`common/yobi.Attachments.js`가 이미 생성하는 `class="video-js" data-setup='{}'` 마크업을
Video.js가 스스로 스캔해 활성화한다.

- 테스트: `src/test/kotlin/com/github/yonaprojects/yona/web/AttachmentVideoJsSkinTemplateRenderingSpec.kt`
  (신규, RED→GREEN)
- 변경 파일: `src/main/resources/templates/issue/view.html`
- Playwright 실측: 이슈 상세 화면에 동영상을 첨부한 뒤 본문에서 Video.js 커스텀 컨트롤 UI로
  렌더링됨을 확인(브라우저 기본 `<video controls>` UI가 아님).
