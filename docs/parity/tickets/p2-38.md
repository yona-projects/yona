## 완료 로그 (원문, `PARITY_BACKLOG.md`의 "완료 로그" 섹션에서 이관)

- **2026-08-22 — P2-38**: 사용자 프로필의 이슈/PR 목록이 `daysAgo` 파라미터로 최근 N일 필터링되지 않고 항상 전체 기간을 반환하던 문제 수정 — yona `UserApp.java:754-759`의 `Issue.findRecentlyIssuesByDaysAgo(user, daysAgo)`/`PullRequest.findOpendPullRequestsByDaysAgo(user, daysAgo)`를 그대로 이식.
  - `IssueRepository`에 `findRecentlyByUser(userId, since)` 신규(`@Query`, LEFT JOIN으로 담당자 명시 — legacy가 `authorId` 또는 `assignee.user.id`인 이슈를 OR로 묶는 것과 동일, `searchIssues()`가 이미 쓰던 LEFT JOIN 패턴 재사용), `updatedDate >= since` 조건 + `ORDER BY updatedDate DESC, state ASC`(legacy `order("updatedDate desc, state asc")` 그대로).
  - `PullRequestRepository`에 `findByContributorAndUpdatedGreaterThanEqualOrderByUpdatedDescStateAsc` 신규 — legacy 메서드명(`findOpendPullRequestsByDaysAgo`)과 달리 실제로는 state 필터가 없는(오타성 네이밍이지만 원문 그대로) legacy 쿼리를 그대로 재현.
  - `UserViewController.userProfile()`에서 `daysAgo` 파라미터(기존엔 model에 표시만 되고 쿼리에 미반영)로 `since = now - daysAgo일`을 계산해 위 두 함수에 전달. legacy `UserApp.java:740-743`의 "daysAgo가 음수면 1로 보정" 가드도 함께 이식(`effectiveDaysAgo`), model에 노출하는 `daysAgo` 값도 보정된 값으로 갱신(legacy도 보정된 지역변수를 그대로 뷰에 넘김).
  - 테스트(TDD, 레드 확인 후 그린): `UserViewControllerSpec.kt`의 기존 3개 테스트(`findByAuthorId`/`findByContributor` 스텁 사용)를 새 리포지토리 메서드 스텁으로 갱신(회귀 아님, 메서드 교체에 따른 스텁 갱신). 신규 2 tests — `daysAgo=7`이 `findRecentlyByUser`의 `since` 인자(캡처해 `Instant.now()-7일` 범위 안인지 검증)와 model의 `daysAgo` 속성에 반영됨 / `daysAgo=-5`는 1로 보정됨.
  - 검증: `./gradlew test --tests "com.github.yonaprojects.yona.web.UserViewControllerSpec"` 전체 통과, 전체 스위트 `./gradlew test` 통과(실패 0).
