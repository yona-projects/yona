legacy Yona의 `docs/technical/name-validation.md`를 옮김. 이름 검증 규칙을 새로 만들거나
바꿀 사람을 위한 설계 참고 문서다 — 특정 프레임워크에 종속된 내용이 아니라, yona에도 여전히
유효한 설계 지침이다(단, 실제 정규식/제약이 코드에 이 문서와 정확히 일치하게 구현되어
있는지는 검증하지 않았다 — 실제 검증 로직은 `domain/*/EmailDomainValidator.kt` 등 관련 클래스

## URL 경로 세그먼트로 쓰일 이름을 고려할 때

프로젝트 이름이나 사용자 이름처럼 URL 경로 세그먼트로 쓰일 이름은, percent-encoding을 피하기
위해 아래처럼 영숫자와 `- . _ ~`로만 구성하는 것을 권장한다.

```
name  = ALPHA / DIGIT / "-" / "." / "_" / "~"
```

`/`나 `?` 같은 예약 문자가 포함된 이름은 URL에 쓰일 때 항상 percent-encoding된다. 예를 들어
이름이 "요비"인 프로젝트의 URL은 아래처럼 인코딩된다.

```
http://www.foo.com/bar/%EC%9A%94%EB%B9%84
```

percent-encoding된 URL은 보기에 안 좋을 뿐 아니라 버그를 유발하기도 쉽다.

첨부파일 이름은 통제하기 어려우므로 어떤 문자든 허용한다.

## 파일/디렉터리 이름으로 쓰일 이름을 고려할 때

아래와 같은 이름은 파일/디렉터리 이름으로도 쓰인다.

- 프로젝트 이름
- 사용자 이름

### 길이 제한

ext 파일시스템은 255바이트, NTFS는 255 UTF-16 문자로 파일명 길이가 제한된다.

### 허용되지 않는 문자

ext 파일시스템에서는 `\0 /`, Windows에서는 `\ / : * ? " < > |`를 파일명에 쓸 수 없다.

### 대소문자 구분

표시할 때는 대소문자를 구분해서 보여주되, 비교할 때는 대소문자를 구분하지 않는 것이 안전하다.

이름 중복을 막기 위해 비교할 때는 일부 파일시스템(예: HFS+)에서 올바르게 동작하도록 대소문자를
구분하지 않아야 한다. 하지만 사용자에게 보여줄 때는 대소문자를 그대로 보여줘야 사용자 요구를
충족한다 — 즉 이름을 저장할 때도 대소문자를 구분하지 않는 방식으로 저장해야 한다는 뜻이다.

### 예외

MS-DOS/Windows 3.1/Windows 95에서 쓰이던 8.3 형식(예: "FILENAME.TXT")의 짧은 파일명은
지원하지 않는다. Oracle JRE의 [Certified System Configurations](http://www.oracle.com/technetwork/java/javase/config-417990.html) 밖의
환경에서 올바르게 동작함을 보장하지 않는다.

### 참고 사항

아래와 같은 이름의 파일은:

- `.`으로 시작하면 숨김 파일로 인식될 수 있다.
- `-`으로 시작하면 셸 명령어 옵션으로 오인될 수 있다.
- `.`이면 현재 디렉터리를 가리키는 기호로 오인될 수 있다.
- `..`이면 상위 디렉터리를 가리키는 기호로 오인될 수 있다.

## 이메일 주소의 local part로 쓰일 이름을 고려할 때

RFC 5322에 따르면 메일 주소는 아래와 같이 local-part와 domain으로 구성된다.

```
addr-spec       =   local-part "@" domain
```

`dot-atom-text` 규칙에 따르면 local-part는 `.`으로 시작하거나 끝날 수 없다. 즉
`foo.bar@mail.com`은 허용되지만 `.foo@mail.com`이나 `foo.@mail.com`은 허용되지 않는다.

## 다른 서비스와의 호환성을 고려할 때

yona로/에서 데이터를 가져오거나 내보내기 쉽도록, 명명 규칙을 Github 같은 다른 서비스와
최대한 호환되게 만드는 것이 좋다.

### Github

Github의 사용자명 검증 규칙은 단순하다 — 대시와 영숫자를 쓸 수 있지만 대시로 시작할 수는
없다.

저장소 이름에 대한 검증 규칙은 공식 문서에 없지만, 여러 번 시도해서 확인한 바로는 다음과
같다. 영숫자와 `- _ .`를 허용하고, 그 외 문자는 자동으로 `-`로 바뀐다. `.`, `...`, `.git`
같은 문자열은 예약되어 있어 저장소 이름으로 쓸 수 없다.

## Basic 인증을 고려할 때

로그인 ID처럼 Basic 인증 스킴의 userid로 쓰일 이름에는 `:` 문자를 포함하면 **안 된다**.
Basic 인증 스킴은 `:`를 자격증명에서 userid와 password를 나누는 구분자로 쓰기 때문에,
userid에 `:`가 포함되면 인증 자체가 동작하지 않는다.

password에 `:`가 포함되는 것은 괜찮다.
