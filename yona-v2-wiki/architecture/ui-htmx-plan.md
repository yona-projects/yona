# 새 UI의 htmx 활용 설계

> **상태: 설계 제안(`decisions.md` D-136).** 선생님이 "htmx도 적극 활용하라"고 지시하셨다. 이 문서는 **어디에 어떻게 쓸지**, **지금 구조와 부딪히는 곳**, **결정할 것**을 정한 제안이다. 구현하지 않았다. IA 제안(`ui-ia-gitlab.md`), 저장소 설계(`ui-client-storage.md`)와 함께 브랜치 `ui-improvements`에서 진행한다.

## 1. 목표와 제약

- **목표**: 새 UI의 화면 이동, 폼, 부분 갱신, 지연 불러오기를 **서버가 만든 HTML 조각을 htmx가 바꿔 끼우는 방식**으로 통일한다. JSON API와 클라이언트 렌더링은 늘리지 않는다(Vue 컴포넌트와 2단 보기 개편은 그 뒤의 일이다, D-96).
- **지킬 것**
  1. **JS가 없어도 링크와 폼이 동작한다**(점진적 향상). `hx-boost`는 정상 `href`와 `action`이 있는 요소에만 쓴다.
  2. 주소(URL)와 요청, 응답 계약은 바꾸지 않는다(IA와 같다). 같은 주소가 일반 요청에는 전체 페이지를, htmx 요청에는 조각을 준다.
  3. 보안: CSRF, XSS 책임은 지금 그대로이며(11절), 서버의 권한 검사는 htmx 헤더와 무관하다.
  4. 지금 쓰는 화면이 깨지지 않는다. **전체 화면을 한꺼번에 바꾸지 않는다**(5절의 옵트인).

## 2. 지금의 htmx(코드에서 확인, 2026-11-11)

- 도입은 D-96이다(jquery-pjax를 htmx 2.0.11로 대체). **범위는 목록 화면에 한정**된다: 이슈 목록, 내 이슈 목록, 풀 리퀘스트 목록, 조직의 이슈와 풀 리퀘스트 목록의 `div[list-container]` 영역 하나를 바꾼다. 사용하는 속성은 `hx-get`, `hx-target`, `hx-select`, `hx-swap`, `hx-push-url`, `hx-request`와 페이지 링크의 `hx-boost`뿐이다(템플릿 5개).
- **서버 계약**: htmx가 모든 요청에 붙이는 `HX-Request: true`로 서버가 조각 응답을 구분한다(`AjaxRequests.isHtmx`, D-98). v1.6 pjax의 `X-PJAX`는 더 이상 보내지 않는다.
- **공통 설정**(`yona.Htmx.js`): 이동 이력은 저장하지 않는다(`historyCacheSize=0`, `refreshOnHistoryMiss=true`: 뒤로 가기는 서버에서 새로 불러온다. 화면 스냅샷은 jQuery로 붙인 select2 등을 되살리지 못하기 때문). 속성 정착 끔(`attributesToSettle=[]`), `allowEval=false`, `includeIndicatorStyles=false`. 서버 오류, 연결 실패, 시간 초과, 목록 표지(`list-container`)가 없는 응답(로그인 화면 등)은 **일반 이동으로 같은 주소를 다시 연다**. 진행 막대는 NProgress이다. 요청 시간 제한은 목록에서 3초(pjax에서 옮김).
- **CSRF**: `yona.Csrf.js`가 XHR과 `fetch`에 `X-XSRF-TOKEN` 헤더를 전역으로 붙이므로 htmx의 POST도 그대로 통과한다.
- **지금 없는 것**: 폼 제출, 부분 갱신, 지연 불러오기, 폴링은 htmx로 하지 않는다. 화면 이동은 전부 전체 문서 이동이다. 레거시 핀 사이드바는 iframe이다(IA 2절).

## 3. 원칙

1. **서버가 HTML을 주고, htmx가 바꾼다.** 새 화면의 부분 갱신은 Thymeleaf 조각(fragment)으로 응답한다.
2. **같은 주소, 두 가지 응답.** 일반 요청은 전체 페이지, `HX-Request` 요청은 조각이다. 조각 응답에는 반드시 `Vary: HX-Request`를 붙인다(6절).
3. **상태는 swap 대상 밖에 둔다.** 사이드바, 상단 바, 서랍과 레일 상태는 교체 영역 밖이라 이동해도 유지된다.
4. **실패하면 일반 이동으로 물러난다.** 지금의 대체 동작을 셸 전체에 그대로 쓴다.
5. **한 번에 하나씩 옵트인.** 화면이 swap-safe(5절)임을 확인한 뒤에만 htmx 이동을 켠다.

## 4. 쓸 곳(패턴)

| 영역 | htmx 방식 | 서버 응답 |
|---|---|---|
| **셸 이동**(사이드바, 경로, 페이지 링크) | `hx-boost` + `hx-target="#shell-main"` + `hx-swap="innerHTML show:window:top"` + `hx-push-url`. 이동 뒤 경로, 제목, 사이드바의 현재 항목, 배지는 OOB 교체(`hx-swap-oob`)이고 `<title>`은 htmx가 갱신한다. 좁음 구간에서는 이동이 끝나면 서랍을 닫는다(`htmx:afterSettle`) | 조각(본문과 OOB 조각) |
| **폼**(설정 저장, 토큰과 키 추가, 규칙 저장 등) | `hx-post`/`hx-put`. 중복 제출 방지(`hx-disabled-elt`), 진행 표시(`hx-indicator`). 검증 오류는 **422 + 폼 조각**으로 같은 자리에서 다시 그리고, 성공은 `HX-Redirect`나 `HX-Location` 또는 조각 교체 | 조각, 상태 코드와 `HX-*` 응답 헤더 |
| **토글과 행 갱신**(지켜보기, 별표, 라벨 추가와 삭제, 토큰 삭제, 멤버 추가와 제거, 알림 읽음) | `hx-post` + `hx-target`이 그 행이나 영역, `hx-swap="outerHTML"`. 삭제는 `hx-confirm` 또는 확인 조각 | 바뀐 행 조각 |
| **지연 불러오기** | `hx-trigger="load"`, `revealed`, `intersect once`. 탭 내용은 처음 열 때, 무거운 패널은 화면에 보일 때 | 조각 |
| **입력 중 검색**(전환기 이름 필터, 목록 필터) | `hx-trigger="input changed delay:250ms"` + `hx-sync="this:replace"`(이전 요청 취소) | 조각 |
| **폴링**(알림 배지) | `hx-trigger="every 60s [document.visibilityState==='visible']"`(보이는 탭에서만) | 배지 조각 |
| **전환기**(사이드바 목록) | `hx-get` + `hx-trigger="load"`. IndexedDB에 둔 조각을 먼저 그린다(7절) | 조각 |
| **이어 붙이기**(무한 스크롤, 더 보기) | `hx-trigger="revealed"` + `hx-swap="afterend"`. 기존 페이지 링크(`yona.Pagination.js`)는 유지 | 조각 |

**범위 밖**: SSE와 WebSocket(실시간 푸시), 오프라인 쓰기. 필요하면 별도 항목.

## 5. 가장 큰 위험: 화면의 수명주기와 "swap-safe" 문턱

지금 화면은 **전체 문서 이동을 전제로** 만들어져 있다. htmx로 본문만 바꾸면 다음이 문제가 된다.

- **모듈 최상위 코드는 한 번만 실행된다.** 화면별 `<script type="module">`은 처음 불러올 때만 평가된다. 두 번째 방문에서 초기화가 다시 돌지 않는다.
- **문서 수준 핸들러가 쌓인다.** `$(document).on(...)`을 화면마다 등록하는 모듈은 이동할 때마다 중복 등록되어 클릭 한 번에 동작이 두 번 일어날 수 있다.
- **jQuery 플러그인 초기화**(select2, 달력, 편집기 `common/editor`)와 타이머는 교체 때 정리되지 않으면 남는다. 이미 D-96에서 select2가 교체 뒤 드러난 일이 있었다(속성 정착).
- **인라인 `<script>`** 는 조각 안에 있으면 실행되지만(`allowScriptTags` 기본값, 지금 설정 파일에 값이 없다), 어떤 화면이 `$yona.loadModule(...)`로 초기화하는지는 화면마다 다르다.

**대응: 화면 단위 옵트인.**
1. 템플릿이 본문 영역에 `data-swap-safe`를 내보내고, 사이드바와 페이지 링크는 **대상 화면이 swap-safe일 때만** `hx-boost`를 켠다. 아니면 일반 이동이다(새 셸의 사이드바가 문서에 포함되므로 그래도 새 틀 안에서 동작한다).
2. **수명주기 규약**: 화면 초기화는 `DOMContentLoaded` 대신 `htmx:load`(교체된 조각 안 요소)에 걸고, 정리는 `htmx:beforeCleanupElement`에 건다. 문서 수준 핸들러는 **위임으로 한 번만** 등록한다(가드). 이를 `esm/shell/`의 작은 공통 모듈(가칭 `Page.js`)로 제공하고, 화면 스크립트는 그 화면을 옮길 때 고친다.
3. **swap-safe 판정(시험)**: 같은 화면을 (가) 일반 이동으로 열 때와 (나) htmx 이동으로 열 때, 기능이 같고(DOM 구조, 위젯 초기화), 콘솔 오류가 없고, **클릭 1회에 동작 1회**이며(핸들러 중복 없음), 같은 화면을 두 번째로 방문해도 같고, 뒤로 간 뒤에도 같아야 한다.
4. **순서**: IA의 P1(사이트 관리와 사용자 설정)은 단순 폼 중심이라 가장 먼저 후보이다. P2(프로젝트)의 코드 보기와 이슈 보기처럼 JS가 무거운 화면은 판정을 통과한 것부터 켠다. 판정하지 못한 화면은 일반 이동으로 둔다.

## 6. 서버 계약

- **구분**: `HX-Request`(지금과 같다), `HX-Boosted`(셸 이동), `HX-Target`(어느 영역). 이것은 **표현을 고르는 용도**이고 보안 경계가 아니다(헤더는 위조할 수 있다). 권한 검사는 지금처럼 요청 자체에서 한다.
- **응답 모양**: 셸 이동에는 **조각**(레이아웃 없음)을 준다. 서버가 전체 레이아웃을 렌더링하지 않아 바이트와 시간이 줄고, `hx-select`로 응답을 파싱하는 일이 없다. 응답에 셸 본문 표지(`shell-main`)가 없으면(로그인 화면, 오류 화면, 리다이렉트된 화면) 일반 이동으로 같은 주소를 다시 연다(지금의 목록 표지 검사와 같은 방식).
- **캐시**: 같은 주소가 조각과 전체를 모두 주므로 **`Vary: HX-Request`를 붙이고** 응답은 개인 응답이므로 `Cache-Control: private`(또는 `no-store`)로 한다. 안 그러면 브라우저와 중간 캐시가 조각을 전체 페이지로 보여 줄 수 있다(뒤로 가기, 새 탭).
- **상태 코드**(htmx 기본은 4xx와 5xx를 교체하지 않는다): 검증 오류는 **422 + 폼 조각**을 교체하도록 허용한다(htmx 2의 응답 처리 설정이나 `hx-target-422` 같은 방식은 구현 때 시험으로 정한다). **401(세션 만료)** 은 `HX-Redirect: /users/loginform?redirectUrl=...`로 로그인 화면으로 보낸다(로그인 HTML이 조각 자리에 들어가는 사고를 막는다). 403, 404, 5xx는 지금처럼 일반 이동으로 오류 화면을 연다.
- **리다이렉트**: htmx는 302를 따라가서 리다이렉트된 화면의 HTML을 받는다. 폼 성공 뒤 이동은 서버가 `HX-Redirect`나 `HX-Location`으로 알린다.

## 7. IndexedDB와의 접점(`ui-client-storage.md`)

- **전환기**: 서버가 준 전환기 **조각(HTML)** 을 `switcher`에 사용자별로 보관한다(이름과 링크만 있고 비밀 값이 없는 조각). 화면을 열면 보관한 조각을 먼저 넣어 보여 주고, `hx-trigger="load"`가 서버 조각을 받아 교체하고, `htmx:afterSwap`에서 보관본을 갱신한다. 저장소 설계 4절의 `switcher` 값을 "목록의 식별자와 이름"에서 "서버가 준 조각 문자열"로 고친다.
- **조각에는 CSRF 토큰, 세션 값, 사용자 입력 원문을 넣지 않는다.** 사용자가 바뀌면(로그아웃과 다른 사용자 로그인) 보관본을 지운다.
- **초안**은 htmx와 무관한 입력란 값이다(스크립트가 IndexedDB에 저장). 단, htmx로 교체되는 폼 안의 입력란은 교체 뒤에 초안 복원을 다시 붙여야 한다(`htmx:load`).
- **htmx의 이동 이력은 IndexedDB로 바꾸지 않는다.** 화면 스냅샷이 위젯 상태를 되살리지 못하는 문제가 같기 때문이다(`historyCacheSize=0` 유지).

## 8. 이동 이력(뒤로 가기)

- 지금 설정을 유지한다. htmx로 이동한 화면에서 뒤로 가면 그 주소를 서버에서 **전체 문서로** 다시 불러온다. 새 셸에서는 사이드바가 새로 그려지므로 IA의 깜빡임 방지 규칙(구간 기본 상태 + 저장값 동기 거울)에 의존한다.
- 본문만 복원하는 방식(이력 캐시)은 swap-safe 화면이 충분해진 뒤 별도로 검토한다.

## 9. 접근성

- 이동이 끝나면 새 본문의 `h1`로 초점을 옮기고(`htmx:afterSettle`), 보이지 않는 라이브 영역(`aria-live="polite"`)으로 새 화면 제목을 알린다. 교체 중에는 대상에 `aria-busy="true"`를 둔다.
- 교체 뒤 스크롤은 맨 위(`show:window:top`)이다. 경로와 사이드바의 현재 항목(`aria-current`)은 OOB로 갱신한다.
- `hx-boost` 링크도 Ctrl, Command 클릭과 가운데 클릭으로 새 탭에서 열린다(htmx 기본, D-96에서 확인).
- 서랍과 레일은 IA의 규칙을 따른다(이동 뒤 좁음에서는 서랍 닫기, 초점은 본문).

## 10. 반응형과 네트워크

- 폰과 폴드에서도 같은 방식이다. 모바일 네트워크에서 응답이 늦으면 일반 이동으로 물러나는 시간 제한이 필요하다. 목록의 **3초**(pjax에서 옮김)는 유지하고, 셸 이동은 더 길게 잡는 것이 맞을 것으로 보인다(추정: 10초). **값은 실측 없이 정하지 못했고** 구현 때 느린 네트워크 에뮬레이션으로 정한다.
- 폴링(알림 배지)은 보이는 탭에서만 돌고, 오프라인이면 건너뛴다.

## 11. 보안

- **CSRF**: 지금처럼 `yona.Csrf.js`가 XHR에 `X-XSRF-TOKEN`을 붙인다. htmx의 POST, PUT, DELETE는 그대로 통과해야 하고, 시험으로 지킨다.
- **XSS**: 조각은 서버가 만든 HTML이므로 이스케이프 책임은 서버(Thymeleaf의 `th:text`)에 있다. `th:utext` 사용처는 조각이 늘면 공격면도 늘므로 점검 대상이다. `allowEval=false`를 유지한다. `allowScriptTags`는 기본값이라 조각 안의 인라인 스크립트가 실행되므로, 사용자 입력이 스크립트 안으로 나가지 않아야 한다(지금과 같은 책임).
- **외부 요청 금지**: htmx 기본값이 같은 출처만 허용하는지(`selfRequestsOnly`)를 구현 때 확인하고 켠다.
- **헤더 위조**: `HX-*` 헤더로 응답 모양을 바꿔도 권한 검사 결과는 같아야 한다(시험).

## 12. 시험(TDD, 구현 때)

- **서버**(MockMvc): 같은 주소가 `HX-Request: true`이면 조각(레이아웃 없음)이고 아니면 전체이며 `Vary: HX-Request`가 있다. 401은 `HX-Redirect`, 검증 오류는 422와 폼 조각이다. 조각 응답에 CSRF 토큰과 세션 값이 없다. `HX-*` 헤더가 있어도 권한 결과가 같다.
- **클라이언트**(Playwright): htmx 이동 뒤 주소, 제목, 경로, 사이드바의 현재 항목이 맞다. 좁음에서 이동 뒤 서랍이 닫힌다. 뒤로 가기는 전체 불러오기이며 정상이다. 클릭 1회에 동작 1회(핸들러 중복 없음). 이중 제출이 막힌다. 오프라인과 시간 초과에서 일반 이동으로 물러난다. 6개 뷰포트(IA 4.5절).
- **swap-safe 문턱**(5절 3항): 옵트인하는 화면마다 일반 이동과 htmx 이동의 동일성 시험을 둔다.
- **구조 시험**: 화면 스크립트가 문서 수준 핸들러를 가드 없이 등록하지 않는다(옵트인한 화면에 한해).

## 13. IA 단계와의 관계

| IA 단계 | htmx 작업 |
|---|---|
| P0 셸 | 셸 본문 표지(`shell-main`), 조각 응답 규약, OOB(경로, 제목, 현재 항목), 수명주기 규약 모듈, 오류 대체 동작을 셸 전체로 일반화, 서랍 닫기 |
| P1 사이트 관리, 사용자 설정 | 폼 htmx 전환(검증 422, 중복 제출 방지), 토큰과 키 삭제 같은 행 갱신, 이 화면들의 swap-safe 판정 |
| P2 프로젝트 | 설정 화면(규칙, 배포 키, 웹훅)의 폼과 행 갱신, 목록 화면은 이미 htmx. 코드 보기와 이슈 보기는 판정 뒤 |
| P3 조직과 홈 | 같은 방식. 전환기 폴링과 캐시 |
| P4 정리 | 옛 pjax 표지(`pjax-container` 등) 정리(삭제는 확인 후) |

## 14. 결정이 필요한 것(`decisions.md` D-136, 권장안 포함)

1. **셸 이동 방식**: (가) 화면 단위 옵트인(swap-safe 판정을 통과한 화면부터), (나) 전 화면 일괄 boost. 권장: **(가)**. (나)는 모듈 한 번 실행과 핸들러 누적 문제를 한꺼번에 떠안아 깨진 화면을 찾기 어렵다.
2. **응답 모양**: (가) 조각 응답(`HX-Request`, `Vary` 필수), (나) 전체 페이지를 받아 `hx-select`로 고름. 권장: **(가)**. 서버가 레이아웃을 렌더링하지 않고 바이트가 준다. 단 조각과 전체 두 경로를 시험으로 지킨다.
3. **이동 이력**: 지금처럼 서버 재로드 유지 / 본문 이력 캐시 도입. 권장: **서버 재로드 유지**. 위젯 상태를 못 되살리는 문제가 풀리기 전에는 안전하다.
4. **시간 제한**: 목록 3초 유지, 셸 이동 10초(추정). 권장: 구현 때 느린 네트워크 에뮬레이션으로 정한다.
5. **수명주기 규약 모듈**(`esm/shell/Page.js`, 가칭)을 새 UI 공통으로 도입하고 화면은 옮길 때 고친다. 권장: 도입. 이름은 구현 때 정한다.
6. **폴링**(알림 배지 60초, 보이는 탭만)과 입력 중 검색 같은 v1.6에 없는 동작을 허용한다. 권장: 허용하고 `differences-from-v16.md`에 기록.
7. **범위 밖 확인**: SSE와 WebSocket, 오프라인 쓰기. 권장: 이번 범위 밖.
8. **htmx 버전**: 2.0.11 유지(4.x는 `next` 태그). 권장: 유지.

## 15. 확인하지 못한 것

- 화면 40여 개 가운데 **swap-safe인 화면이 어느 것인지** 조사하지 않았다(IA의 P1 때 화면별로 판정한다). 문서 수준 핸들러를 쌓는 모듈의 실태와 화면별 초기화 방식(`$yona.loadModule`, 인라인 스크립트)을 전수 조사하지 않았다.
- htmx 2.0.11에서 4xx 응답 교체(`responseHandling`, `hx-target-4xx` 확장 등)의 정확한 설정 방법은 확인하지 않았다(버전별 차이가 있다). 구현 때 시험으로 정한다.
- 지금 설정에 `allowScriptTags`, `selfRequestsOnly` 값이 적혀 있지 않아 기본값(각각 켜짐)이라고 추정했다. 실제 값은 확인하지 못했다.
- `AjaxRequests.isHtmx`(서버)의 상세 구현과 조각 응답을 만드는 컨트롤러 패턴은 읽지 않았다.
- 폴드와 태블릿 실기기에서의 htmx 이동은 확인하지 못했다.
