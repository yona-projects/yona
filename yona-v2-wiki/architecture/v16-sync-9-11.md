# v1.6 위키 9~11차 갱신분의 v2 대조 결과

v1.6 위키가 9차(Antigravity CLI 판정), 10차(소스 재검증), 11차(재확인)로 크게 바뀌었다. 로컬 위키를 GitHub(`search5/yona-v1.6-wiki`)의 최신으로 갱신하고, 5차 검증 전 백업과 현재 위키의 차이 127개 페이지(`log.md` 제외)를 v2 소스와 대조했다. 처리 기준은 [P-08, P-10](../decisions.md)이다.

## 방법과 한계

1. 페이지별 차이(`diff -u`)를 18개 그룹으로 나눠 에이전트가 `+` 줄의 동작 주장을 뽑고, 위키가 아니라 v1.6 소스(`60a5ac406`)를 직접 읽어 확인한 뒤 v2 코드와 대조했다. 약 650개 주장을 점검했다.
2. 후보(약 30건)는 다른 에이전트 6개가 v1.6과 v2 소스를 다시 읽어 확정했다. 확정된 항목만 TDD로 고쳤다.
3. **점검하지 못한 범위**: JS 서술(v2가 v1.6의 JS를 그대로 쓴다), DB 스키마 표(기존 스냅샷 테스트가 맡는다), 테스트 목록, 프레임워크 내부 동작(Play, Ebean), `git-svn-repository.md`의 JGit 파서 같은 내부 구현 서술. 그룹마다 점검한 주장 수가 14~58개로 달라서, 얕게 본 그룹에는 놓친 불일치가 더 있을 수 있다.
4. 5차 검증 전 백업과 비교했으므로 5차 이후 이미 반영한 항목도 다시 점검 대상에 들어갔다(중복은 기록된 항목으로 분류되었다).

## 판정하지 못한 항목 (소스만으로 확정할 수 없음)

- 작성자 사용자 행이 DB에 없을 때 게시판 목록과 댓글의 표시: v1.6은 `NullUser`의 "존재하지 않는 사용자입니다." 링크, v2는 `issue.noAuthor` 문구. 검색 행은 C029에 있고 게시판은 기록이 없다(G01-U01, G02-U).
- ja-JP `title.signupFor`가 두 번 정의되어 Play 파서가 어느 값을 쓰는지(G07-U01).
- `/statistics`에서 `@AnonymousCheck`와 프로젝트 검사의 순서(G11-U02), `BoardApp`에 클래스 수준 `@AnonymousCheck`가 적용되는지(G12-U01).
- 병합 알림의 null 메시지(G15-U1), 가입 요청 알림 제목의 언어(G15-U2), 포트만 설정한 SMTP의 진단 경고(G18-U01), 브랜치 삭제 푸시의 PR 삭제 시점(G18-U02).
- 마감일을 비운 열린 이슈의 `isOverDue`(비결정 값), 본문이 같을 때의 `history` 컬럼(Ebean 부분 업데이트).
- 리뷰 폼 아바타 크기(32 대 64), 커밋 작성자 이메일이 빈 문자열일 때, 비로그인 사용자의 색인 댓글 `mentioned` 클래스.

## v1.6 위키에서 발견한 오류

`web/code-app.md`(브랜치 삭제와 기본 지정은 프로젝트 구성원도 통과한다는 서술), `synthesis/porting-verify-next/C1.md`의 [12], `utils-catalog`의 `getOptionalShortDate`("week-year 기호 Y"), `web/`의 "이전 위치면 301 redirect" 서술이다. v1.6 위키 쪽에서 소스 확인 후 정정한다.
