# GitLab 방식 UI 정보 구조(IA) 제안

> **상태: 제안(선생님 확인 대기, `decisions.md` D-134).** 구현하지 않았다. 브랜치 `ui-improvements`에서 진행한다.
> GitLab의 구조는 **일반 지식**을 기준으로 적었고 현재 GitLab 버전의 화면과 대조하지 않았다(9절).

## 1. 목표와 제약

- **목표**: 화면 이동의 틀을 GitLab처럼 **맥락(전역, 프로젝트, 조직, 사용자 설정, 사이트 관리)마다 왼쪽 사이드바 하나**로 모으고, 위에는 경로(breadcrumb)와 페이지 머리를 둔다. 지금은 맥락마다 틀이 제각각이다(상단 탭, 설정 탭, 관리 사이드바가 섞여 있다).
- **지킬 것**
  1. **주소(URL)와 요청, 응답 계약은 바꾸지 않는다.** 바뀌는 것은 화면의 틀(내비게이션)뿐이다. v1.6의 주소를 쓰는 외부 도구, 북마크, 문서 링크가 그대로 동작해야 한다.
  2. 화면 안의 기능과 동작은 그대로다. 메뉴의 **이름은 v1.6 용어를 유지**한다(예: "코드 주고받기"). 이름을 GitLab 용어로 바꾸는 것은 별도 결정이다(8절).
  3. 마크업은 BS5 고유 모양으로 쓴다(호환 층 금지, `decisions.md` D-56). 페이지 전환은 htmx(D-96)를 쓴다.
  4. Vue 컴포넌트와 2단 보기 개선은 **이 작업의 범위가 아니다**(나중 UI 개편, D-96). 이 IA는 그 개편이 올라탈 틀이다.
- **v1.6 동등성 원칙과의 관계**: AGENTS.md의 "v1.6을 그대로 따른다"에 비추면 내비게이션 재구성은 **화면 모양을 바꾸는 일**이라 선생님의 승인이 필요하다(D-134). 기능, 주소, 계약은 그대로이므로 동등성 점검(`tools/v16-diff` 회귀)의 응답 비교에는 영향이 없어야 하고, 영향이 나오면 결함으로 본다.

## 2. 현재 정보 구조(코드에서 확인, 2026-11-11)

| 맥락 | 현재 틀 | 항목 |
|---|---|---|
| 전역 | 상단 바(`common/navbar`) + 사용자 메뉴(`common/usermenu`) | 로고, 프로젝트 목록(`/projects`), 피드백, 검색(범위: 프로젝트, 그룹, 전체), 사용자 메뉴: 프로필, 계정 설정, 즐겨찾기, 프로젝트, 최근 읽은 이슈, 바로가기(내 이슈, 새 이슈, 내가 만든 새 이슈), 사이트 관리, 새 프로젝트, 새 조직, 로그아웃 |
| 홈 | 탭(`index`) | 즐겨찾기, 프로젝트, 최근 읽은 이슈, 최근 방문, 내가 만든, 지켜보는, 참여 중인 |
| 프로젝트 | 머리(이름, 지켜보기) + **상단 가로 메뉴**(`project/menu`) | 홈, 코드(파일, 커밋, 브랜치, 태그), 이슈(+ 라벨, 마일스톤), 코드 주고받기, 리뷰, 게시판, 위키, 관리(톱니) |
| 프로젝트 설정 | 상단 **탭**(`project/partial-settingmenu`) | 설정, 멤버, 규칙, 배포 키, Git LFS, 이슈 라벨, 웹훅, 프로젝트 이관, 프로젝트 삭제, 코드 저장소 타입 변경 |

| 조직 설정 | 상단 탭(`organization/partial-settingmenu`) | 설정, 그룹 멤버, 감사 로그, OAuth 앱, OAuth 앱 정책, 그룹 삭제 |
| 사용자 설정 | 상단 **탭**(`user/partial-edit-tabmenu`) | 프로필 수정, 비밀번호 변경, 알림 설정, 이메일 설정, 사용자 토큰, GPG 키, SSH 키, 2단계 인증, OAuth 앱, 연결된 계정, 보안 기록 |
| 사이트 관리 | **왼쪽 사이드바**(`layout/site-mng-layout`) | 사용자, 게시물, 이슈, 프로젝트, 메일 발송, 대량 메일 발송, 업데이트, 시스템 진단, 감사 로그, 보안, OAuth 앱, LFS, SSO |

**관찰한 문제**
- 같은 종류의 "설정"이 맥락마다 다른 틀이다. 사이트 관리만 사이드바이고 사용자, 프로젝트, 조직 설정은 탭이다. 사용자 설정은 탭이 **11개**라 두 줄로 넘친다(실제 캡처에서 확인).
- 항목이 성격과 무관하게 한 줄로 나열되어 찾기 어렵다(사용자 설정의 비밀번호, 이메일, 연결된 계정은 "계정", 토큰, SSH, GPG, 2단계는 "접근과 보안"이라 묶을 수 있다).
- 프로젝트 안의 기능이 상단 가로 메뉴에 다 올라가 있어, 하위 화면(코드의 파일, 커밋, 브랜치, 태그와 이슈의 라벨, 마일스톤)이 별도의 보조 탭으로 흩어져 있다.
- 현재 위치를 알려 주는 경로(breadcrumb)가 없다.

## 3. GitLab IA의 기준(일반 지식)

- **왼쪽 사이드바 하나**가 맥락을 담는다. 맥락은 프로젝트, 그룹, 사용자 설정, 관리 영역이다. 사이드바 위에 맥락의 이름과 아이콘이 있고, 항목은 **성격별 묶음**으로 정렬되며 하위 항목은 펼쳐진다.
- **상단 바**는 전역 기능만 둔다: 사이드바 접기, 검색, 만들기(+), 이슈, 병합 요청, 할 일, 사용자 메뉴.
- 본문 위에 **경로(breadcrumb)**와 **페이지 머리**(제목, 주요 단추)를 둔다.
- 설정은 **맥락의 맨 아래 한 묶음**이고, 설정 안에서도 사이드바가 이어지거나 설정 전용 사이드바로 바뀐다.
- 프로젝트 사이드바의 묶음(버전에 따라 이름이 다르다): 개요, 관리(Manage), 계획(Plan), 코드(Code), 빌드(Build), 보안(Secure), 배포(Deploy), 운영(Operate), 모니터링(Monitor), 분석(Analyze), 설정(Settings).

## 4. 제안 IA

### 4.1 틀(셸)

```
┌──────────────────────────────────────────────────────────────────────────┐
│ ☰  Y  프로젝트 ▾  [ 검색… ]            +  이슈  코드 주고받기  🔔  사용자 ▾ │  전역 상단 바
├───────────────┬──────────────────────────────────────────────────────────┤
│ [맥락 머리]   │  경로: 조직 / 프로젝트 / 이슈          [주요 단추]          │  경로와 페이지 머리
│  홈           │ ───────────────────────────────────────────────────────  │
│  코드  ▸      │                                                          │
│  이슈  ▸      │                     본 문                                │
│  코드 주고받기│                                                          │
│  ...          │                                                          │
│  설정  ▸      │                                                          │
└───────────────┴──────────────────────────────────────────────────────────┘
```

- 왼쪽 사이드바는 맥락마다 항목만 바뀐다. 접으면 아이콘만 남고, 좁은 화면(`< 992px`)에서는 숨겨졌다가 ☰로 연다.
- 현재 항목을 강조하고, 묶음은 현재 화면이 속하면 펼쳐 둔다.

### 4.2 맥락별 구조

**① 전역(홈)**
- 상단 바: 사이드바 열기, 로고, 검색(범위 선택 유지), `+`(새 프로젝트, 새 조직, 새 이슈), **내 이슈**, **코드 주고받기**(내가 관련된 것), 알림, 사용자 메뉴(프로필, 설정, 사이트 관리, 로그아웃).
- 홈 사이드바("내 작업"): 즐겨찾기, 프로젝트, 최근 읽은 이슈, 최근 방문, 내가 만든, 지켜보는, 참여 중인. 기존 홈 탭 7개를 그대로 옮긴다. 별도로 **탐색**: 프로젝트 목록(`/projects`), 조직 목록.

**② 프로젝트**

| 묶음 | 항목 | 현재 위치 |
|---|---|---|
| (개요) | 프로젝트 홈 | 상단 메뉴 "홈" |
| 코드 | 파일, 커밋, 브랜치, 태그 | 상단 메뉴 "코드"와 보조 탭 |
| 계획 | 이슈, 라벨, 마일스톤, 게시판 | 이슈의 보조 메뉴, 상단 메뉴 "게시판" |
| 협업 | 코드 주고받기, 리뷰 | 상단 메뉴 |
| 문서 | 위키 | 상단 메뉴 |
| 설정 | 일반, 멤버, 규칙, 배포 키, Git LFS, 웹훅, **고급**(이관, 저장소 타입 변경, 삭제) | 설정 탭 10개 |

- "이슈 라벨"은 프로젝트 설정 탭에 있으나 쓰임새가 이슈 계획이라 **계획 묶음으로 옮긴다**(주소는 `/issue/labelsform` 그대로).
- 이관, 저장소 타입 변경, 삭제는 설정 맨 아래 **위험 구역**(고급)으로 모은다.

**③ 조직(그룹)**

| 묶음 | 항목 |
|---|---|
| (개요) | 조직 홈 |
| 계획 | 이슈, 게시판 |
| 협업 | 코드 주고받기 |
| 설정 | 일반, 멤버, **접근**(OAuth 앱, OAuth 앱 정책), 감사 로그, 삭제(고급) |

**④ 사용자 설정**(탭 11개를 묶음 5개로)

| 묶음 | 항목 |
|---|---|
| 프로필 | 프로필 수정 |
| 계정 | 비밀번호 변경, 이메일 설정, 연결된 계정 |
| 알림 | 알림 설정 |
| 접근과 보안 | 사용자 토큰, SSH 키, GPG 키, 2단계 인증, 보안 기록 |
| 애플리케이션 | OAuth 앱 |

**⑤ 사이트 관리**(이미 사이드바이므로 묶음만 더한다)

| 묶음 | 항목 |
|---|---|
| 개요 | 사용자, 프로젝트, 이슈, 게시물 |
| 메시지 | 메일 발송, 대량 메일 발송 |
| 시스템 | 업데이트, 시스템 진단, 감사 로그 |
| 설정 | 보안, SSO, OAuth 앱, LFS |

### 4.3 경로(breadcrumb) 규칙

`조직 또는 사용자 / 프로젝트 / 섹션 / 페이지`. 설정과 관리 화면은 `설정 / 항목`, 사이트 관리는 `사이트 관리 / 묶음 / 항목`이다. 마지막 항목은 링크가 아니다.

### 4.4 페이지 머리 규칙

제목(한 줄), 설명(선택), 주요 단추(오른쪽 정렬, 한 개는 강조). 목록 화면의 검색과 필터는 머리 아래 한 줄이다. 이 규칙은 지금 화면마다 다른 제목 크기와 단추 위치를 맞춘다.

## 5. 현재 화면 → 새 위치 대응표(전부)

| 현재 | 새 위치 | 주소 변경 |
|---|---|---|
| 프로젝트 상단 메뉴(홈, 코드, 이슈, 코드 주고받기, 리뷰, 게시판, 위키, 관리) | 프로젝트 사이드바 | 없음 |
| 프로젝트 코드 보조 탭(파일, 커밋, 브랜치, 태그) | 코드 묶음 | 없음 |
| 이슈 보조 메뉴(라벨, 마일스톤) | 계획 묶음 | 없음 |
| 프로젝트 설정 탭 10개 | 설정 묶음(고급 포함) | 없음 |
| 조직 상단 메뉴와 설정 탭 | 조직 사이드바 | 없음 |
| 사용자 설정 탭 11개 | 사용자 설정 사이드바 5묶음 | 없음 |
| 사이트 관리 사이드바 | 같은 사이드바에 묶음 추가 | 없음 |
| 홈 탭 7개 | 홈 사이드바 | 없음 |
| 사용자 메뉴의 바로가기(내 이슈, 새 이슈) | 상단 바의 `+`와 내 이슈 | 없음 |

## 6. 구현 구조

- **레이아웃**: 지금 레이아웃 파일(`layout.html`, `project-layout.html`, `organization-layout.html`, `site-layout.html`, `site-mng-layout.html`)을 **공통 셸 하나**와 맥락별 사이드바 조각으로 정리한다. 사이드바 항목은 템플릿에 흩어 두지 않고 **한 곳의 목록(데이터)**에서 만든다(맥락, 묶음, 항목, 아이콘, 주소, 보이는 조건). 조건 예: 위키 메뉴는 프로젝트 설정의 메뉴 체크박스(`menu.wiki`)가 켜졌을 때만, Mercurial이면 Git LFS 이름이 다르다(`project.lfs.hg`).
- **전환**: 사이드바 링크는 htmx로 본문만 바꾼다(D-96). 주소와 뒤로 가기는 그대로 동작해야 한다.
- **스타일**: BS5 변수와 테마 색(D-58). 옛 `yobi.css`의 규칙(206px 고정 입력란 등, A-377)이 새 셸 안에서 부딪히지 않도록 셸 영역은 새 클래스(`.shell-*`)로 격리한다.
- **접근성**: 사이드바는 `nav` 영역과 `aria-current`, 키보드로 접고 펼칠 수 있다.

## 7. 단계 계획(각 단계마다 시험 먼저, Playwright 화면 확인은 단계 끝에 한 번)

| 단계 | 내용 | 시험 |
|---|---|---|
| P0 셸 | 공통 셸, 사이드바 목록(데이터), 경로, 페이지 머리 부품. 기존 화면은 그대로 둔다(옵션으로 새 셸을 켠다) | 목록 데이터와 조건(위키, Mercurial) 단위 시험, 접근 가능한 마크업 시험 |
| P1 사이트 관리, 사용자 설정 | 이미 쉬운 두 맥락부터 옮긴다(탭 11개와 사이드바 13개) | 화면 시험(항목 존재와 강조), 주소 불변 시험 |
| P2 프로젝트 | 상단 메뉴와 설정 탭을 사이드바로 | 같은 시험 + 프로젝트별 조건 |
| P3 조직, 홈 | 조직 메뉴와 홈 탭 | 같은 시험 |
| P4 정리 | 옛 메뉴 템플릿과 규칙 삭제(삭제는 선생님 확인 후), v1.6 응답 회귀(`tools/v16-diff`, 요청하실 때) | 구조 시험(옛 메뉴가 남지 않음) |

규모(추정): P0이 가장 크다. P1~P3은 목록 데이터를 채우는 일이라 단계마다 작다. 전체는 템플릿 약 40개와 SCSS 수백 줄이 움직인다.

## 8. 결정이 필요한 것(`decisions.md` D-134, 권장안 포함)

1. **v1.6 화면 모양을 바꾸는 이 작업을 승인하시는가.** 권장: 승인. 단, 주소와 계약 불변을 시험으로 지킨다.
2. **메뉴 이름**: v1.6 용어 유지(코드 주고받기, 리뷰, 게시판)냐 GitLab 용어(병합 요청, 코드 리뷰, 토론)냐. 권장: **v1.6 용어 유지**. 사용자가 이미 아는 말이고, 용어 변경은 도움말과 번역(5개 언어)까지 퍼지는 별도 일이다.
3. **사이드바 기본 상태**: 펼침 고정(GitLab은 펼침, 접으면 기억)냐 좁은 화면에서만 접힘이냐. 권장: 펼침을 기본, 접은 상태는 브라우저에 기억.
4. **새 셸 적용 방식**: 한 번에 전부(기존 화면과 틀이 섞이지 않음)냐 단계별(P1부터 맥락별로, 잠시 틀이 섞임)이냐. 권장: **단계별**, 단 한 맥락 안에서는 섞이지 않게 맥락 단위로 전환한다.
5. **프로젝트 설정의 "이슈 라벨"을 계획 묶음으로 옮기는 것**(주소는 그대로). 권장: 옮긴다. 라벨은 이슈를 쓰는 사람이 찾는 곳이다.
6. **홈의 "내 작업"과 "탐색"을 나누는 것**. 권장: 나눈다(GitLab의 "Your work"와 "Explore").

## 9. 확인하지 못한 것

- GitLab의 현재 화면과 용어는 대조하지 않았다(일반 지식).
- 새 셸이 모바일(폭 400px 안팎)에서 어떻게 보이는지는 구현 전이라 정하지 못했다(P0에서 정한다).
- 위키 페이지 보기와 이력, OAuth 동의 화면 등 일부 화면은 이 IA에서 어느 맥락에 들어가는지(위키는 프로젝트의 문서 묶음, 동의 화면은 셸 밖의 독립 화면)만 정했고, 새 셸 안에서의 모양은 확인하지 못했다.
