# v1.6과 달라지는 아키텍처 결정

기능과 계약은 v1.6과 같게 유지하고, 구현 기반만 아래처럼 바꾼다.

| 항목 | v1.6 | v2 | 이유 |
|---|---|---|---|
| 언어 | Java, Scala 템플릿 | Kotlin (패키지 `dev.yona`) | 프로젝트 요구사항 |
| 프레임워크 | Play 2.3.10 | Spring Boot 4.1.1 (Spring Framework 7) | 프로젝트 요구사항 |
| ORM | Ebean | JPA(Hibernate) | Spring 표준 영속성 계층 |
| 빌드 | sbt | Gradle Kotlin DSL (JDK 21 toolchain) | 프로젝트 요구사항 |
| 템플릿 | `*.scala.html` | Thymeleaf | Scala 템플릿 엔진 대체 |
| DB | MariaDB | H2(기본), PostgreSQL(컨테이너), 이후 MariaDB 등 | 다중 백엔드 요구사항 |
| 개발 인프라 | 없음 | `docker-compose.yml` (PostgreSQL 16, mailpit) | 메일 확인과 DB 구성 |
| JS 라이브러리 | jQuery 3.3.1(주 화면)과 1.9.0(이전 화면, 첫 설정 화면), jQuery UI 1.10.4, autosize 4.0.2, NProgress 0.1.6, Popper 2.4.2, Tippy 6.2.3, video.js 7.8.2, moment 2.4.0 | jQuery 3.7.1 한 벌, jQuery UI 1.14.2(효과만), autosize 6.0.1, NProgress 0.2.0, Popper 2.11.8, Tippy 6.3.7, video.js 7.21.2, moment 2.31.0(`moment-with-locales`, `moment.locale`) | 선생님 요청(`decisions.md` D-91, `A-392`)으로 최신 버전으로 올렸다. 화면 동작은 같다(전 화면 순회 비교에서 새 문제 0). v1.6 화면 구조를 고정한 `MigrationPageTest`의 스크립트 목록은 jQuery 1.9.0에서 3.7.1로 바꾸었다. Yona가 v1.6에서 고친 벤더 파일(pageslide, At.js 등)은 아직 올리지 않았고 패치 이식이 필요하다(`architecture/js-upgrade-plan.md`) |
| 복사 단추 | clipboard.js, 지원하지 않으면 Flash(zclip). 코드 이력의 커밋 번호 복사는 `new Clipboard`가 실패해 동작하지 않았다(R-132) | `yona.Clipboard.copy`: 보안 연결이면 `navigator.clipboard`, 아니면 `execCommand`. 두 복사 단추(커밋 번호, 저장소 주소) 모두 동작하고 Flash는 없다 | 선생님 요청(`A-394`). Flash는 브라우저에서 사라졌고, 커밋 번호 복사의 v1.6 결함을 고쳤다 |
| JS 번들 도구 | Closure Compiler 2018년 판(`compiler.jar`, JVM)으로 번들 3개를 만든다. 번들 2개는 다시 만들어도 같은 결과가 나오지 않는다 | vite 8.3.0(Node)로 번들 3개를 만든다. 입력 목록과 순서, 전역 스크립트라는 구조는 같고 같은 입력이면 byte 단위로 같은 결과가 나온다. 번들 안에서 쓰이지 않던 zclip 코드가 빠졌다 | 선생님 요청(`D-92`, `A-395`). 압축기가 달라 번들 내용(변수 이름, 크기)은 v1.6과 다르지만 전역 이름, jQuery 플러그인 이름, `yobi` 모듈 이름은 같다(시험으로 확인) |
| JS 전역 이름 | `yobi.*`, `$yobi.*`, 파일 `yobi.*.js` | `yona.*`, `$yona.*`, 파일 `yona.*.js` (CSS `yobi.css`, 아이콘 `yobicon-*`, 쿠키 `yobi.token`, 메시지 키는 그대로) | 선생님 지시(`D-93`, `A-396`). 옛 이름의 호환 별칭은 두지 않았다. 화면 동작은 같다(전 화면 순회와 시험으로 확인) |
| select2 | 3.4.5. 선택 상자의 DOM은 `.select2-container`, `.select2-choice`, `.select2-drop`, 결과는 `.select2-result-label`이고, 담당자, 공유자, 리뷰 요청은 숨은 `<input>` | 4.1.0(공식 배포 파일)과 Bootstrap 5 테마 1.3.0. DOM은 `.select2-selection`, `.select2-dropdown`, `.select2-results__option`. 담당자, 공유자, 리뷰 요청 5곳은 `<select>`(`issue/partial-assignee`, `issue/view`, `pullrequest/view`, `pullrequest/create`). 다중 선택 라벨의 빈 `<option>`은 뺐다. 로케일 문구는 공식 4.1.0 i18n 파일의 것이다(한국어 "결과가 없습니다.", v1.6은 "결과 없음". 한국어, 일본어, 러시아어, 영어 파일을 싣고 그 밖의 언어는 영어, D-99). 선택 상자의 폭은 `data-width`(`100%`, 브랜치 `220px`)로 정한다(D-100). 컨테이너에 원본 클래스를 복사하는 일과 `data-container-css-class`는 `yona.ui.Select2.js`가 직접 한다 | 선생님 지시(`D-95`, `A-399`). 4.x는 숨은 input과 3.x 옵션 이름을 지원하지 않는다. 화면 모양은 Bootstrap 5 테마 기반이라 3.x 때의 회색 화살표 상자와 달라진다(D-56의 BS5 고유 모양). 요청과 응답 계약(담당자 API, 공유 API, 폼 이름 `assigneeLoginId`)과 동작은 같다 |
| 템플릿 엔진 | jquery.tmpl 1.0.0(`<script type="text/x-jquery-tmpl">`, `${이름}`, `$.tmpl(...)`, `$(요소).tmpl(...)`) | Mustache 4.2.0(`<script type="text/x-mustache">`, `{{이름}}`, `$yona.render(...)`, `$yona.renderElement(요소, ...)`). 값 이스케이프는 jquery.tmpl과 같은 규칙으로 걸어 같은 HTML이 나온다. Yona 자체 도우미 `$yona.tmpl`(`${}` 치환)과 그 블록은 그대로이며 블록 type만 `text/x-yona-template`이다 | 선생님 지시(`D-94`, `A-400`). jquery.tmpl은 공식 폐기 라이브러리이고 jQuery 4에서 동작하지 않는다. 화면 동작과 HTML 출력은 같다(실제 jquery.tmpl 출력을 기대값으로 한 시험) |
| 목록 영역 교체 | jquery-pjax(2012년 사본). 폼 제출과 `a[pjax-page]` 클릭을 문서 수준에서 가로채고 `div[pjax-container]`만 바꾼다. 요청 주소에 `_pjax=div[pjax-container]`가 붙는다. Firefox와 Safari는 bfcache 문제로 pjax를 끄고 일반 이동을 한다. 뒤로 가기는 pjax가 그 주소를 다시 받아 영역만 바꾼다 | htmx 2.0.11(공식 배포 파일)과 `yona.Htmx.js`. 템플릿의 `hx-*` 속성이 영역 교체를 선언한다(컨테이너의 `hx-target`, `hx-select`, `hx-swap`, `hx-push-url`, `hx-request`, 검색 폼의 `hx-get`, 페이지 링크의 `hx-boost`). 서버 계약은 처음에는 그대로(`X-PJAX`)였다가 D-98에서 `HX-Request`로 바뀌었다(위 행). `_pjax` 주소 매개변수는 붙지 않는다(서버가 읽지 않는다). 모든 브라우저에서 영역만 바꾼다. 뒤로 가기와 앞으로 가기는 그 주소를 서버에서 새로 불러온다(전체 문서). 조직 풀 리퀘스트 목록은 v1.6처럼 영역 교체 없이 전체 문서 이동이다. 교체한 뒤 "엑셀파일로 다운받기" 링크 주소에 `_pjax=...`가 섞이지 않는다(R-134). 서버 오류, 시간 초과, 목록 영역이 없는 응답은 일반 이동으로 같은 주소를 다시 열며 pjax가 내던 `rxTrim` TypeError는 없다(R-135) | 선생님 지시(`D-96`, `A-401`). 유지가 끝난 라이브러리를 대체한다. 화면 동작(필터, 탭, 정렬, 검색, 페이지 이동, 갱신 뒤 초기화, 진행 막대, 오류와 시간 초과와 목록 영역이 없는 응답의 일반 이동 대체)은 같다. 달라지는 점은 Firefox와 Safari도 영역만 바꾼다는 것(v1.6의 우회는 pjax 전용 문제였다. Chromium과 Firefox에서 확인했고 WebKit은 시스템 의존 패키지가 없어 확인하지 못했다), 뒤로 가기가 전체 문서 요청이라는 것, 위의 R-134와 R-135이다. 이전 동작과 같은지는 pjax 기준 jar와 나란히 20개 시나리오로 비교했다(`e2e/htmxparity.tmp.mjs`: 14개 일치, 나머지는 위의 의도한 차이와 코드 문자열 차이뿐). 마크업 표지는 `list-container`, `list-filter`, `list-page`로 바꿨다(위 행) |
| 목록 조각 요청 계약과 마크업 표지 | 목록 조각은 요청 헤더 `X-PJAX: true`(이슈 목록과 내 이슈는 `X-Requested-With: XMLHttpRequest`도 함께)나 `format=pjax` 매개변수로 요청한다. 마크업 표지는 `pjax-container`, `pjax-filter`, `pjax-page`이고 탭 항목에 쓰이지 않는 `data-pjax`가 있다 | 목록 조각은 htmx가 모든 요청에 보내는 `HX-Request: true` 하나로, 매개변수는 `format=fragment`로 요청한다(이슈 목록, 내 이슈, 이슈 라벨 목록, 풀 리퀘스트 목록, 조직 이슈 목록, 풀 리퀘스트 상태 조각의 JSON 판별). `X-PJAX`는 더 보지 않고 `format=pjax`는 일반 전체 화면이다. 마크업 표지는 `list-container`, `list-filter`, `list-page`이고 `data-pjax`는 지웠다. 목록 조각 응답의 컨테이너 속성 이름이 바뀐다 | 선생님 지시(`D-98`, `A-403`). pjax라는 이름을 더 쓰지 않는다. 화면 동작은 같다. v1.6 클라이언트를 그대로 쓰는 외부 호출자는 없다(이 헤더와 매개변수는 화면 스크립트만 썼다). `AjaxRequests.isPjax`는 `isHtmx`로 바뀌었다 |
| 프로필 이미지 자르기 | Jcrop 0.9.12(jQuery 플러그인). 선택 상자와 손잡이는 Jcrop 모양, 자르기는 숨은 canvas에 `drawImage`, 업로드 이벤트 `jCropUpload` | Cropper.js 2.3.1(공식 배포 파일, jQuery 불필요, 웹 컴포넌트). 선택 상자는 손잡이 8개와 눈금선이 있고 바깥을 흰 막으로 덮는다. 자르기는 `$toCanvas`, 업로드 이벤트 `avatarCropUpload`. 동작은 같다: 1:1, 최소 32px, 처음 선택은 왼쪽 위 128x128, 미리보기 갱신, 자른 128x128 PNG 업로드 | 선생님 지시(`D-101`, `A-405`). Jcrop은 jQuery 4에서 동작하지 않고 최신판(0.9.15)도 같다. 모양이 Cropper.js의 것이 된다. Jcrop의 "선택 풀기"(`onRelease`)에 해당하는 동작은 없다 |
| 제목 머리말 자동완성(이슈 작성, 이슈 수정, 게시글 작성) | `<input id="title">`에 At.js 1.5.3으로 `[` 머리말을 붙임(`yona.TitleHeadAutoCompletion.js`). 후보는 At.js의 `.atwho-view` 목록 | `<title-input>`(Lit 요소, Shadow DOM, `ElementInternals` 폼 연동, `components/title-input`에서 빌드한 단일 번들, D-102). 규칙은 At.js와 같다(`[` 질의 규칙과 20자, 정렬, 개수 10, 300ms 지연, 키 처리, 강조, 목록 모양, 라벨 선택은 `yona.TitleHeadAutoCompletion.js`가 이벤트로 처리). 달라지는 점: 후보 목록이 입력란 아래(캐럿 줄 아래가 아니라 `[` 글자 x에 맞춘 입력란 아래 2px), 같은 질의는 keyup이 와도 다시 묻지 않음, 강조는 질의를 글자 그대로 찾고 서버 값을 HTML로 해석하지 않음, 서버 오류에는 목록을 닫고 진행 막대를 끝냄, 전역 단축키(`yona.ShortcutKey.js`)가 Shadow DOM 입력란의 글자를 단축키로 받지 않도록 실제 대상(`composedPath`)을 봄. 본문 `@`, `:`, `#` 멘션은 그대로 At.js |" At.js는 2018년 이후 갱신이 없고 jQuery 4를 공식 지원하지 않는다(`peerDependencies: jquery <4.0.0`). 머리말 한 곳만 jQuery 없는 컴포넌트로 옮겨 At.js를 jQuery 4에서 떼어 내는 범위를 줄였다. 본문 멘션은 UI 개편(CodeMirror)에서 정리한다(D-102, A-407, A-408). |
| 내부 이름 `yobi` | 쿠키 `yobi.token`, 인증 영역 `Yobi`, 웹훅 `Yobi-Hookshot`, 백업 `yobi-data-*`, Git PR 숨은 참조 `refs/yobi/pull/...` | `yona.token`, `Yona`, `Yona-Hookshot`, `yona-data-*`, `refs/yona/pull/...`(Mercurial은 `yona/pull/...`) | 선생님 지시(`D-93` 보완, `A-397`). 쿠키 이름이 바뀌어 로그인 유지 사용자는 한 번 로그아웃된다. v1.6에서 이어받은 Git 저장소는 서버를 띄우기 전에 `tools/migrate-git-refs.sh`를 돌려야 한다(돌리지 않으면 기존 PR의 숨은 참조를 찾지 못한다). v1.6으로 되돌리려면 반대로 옮겨야 한다 |

## 구현하면서 확정된 차이

위 표 이후 각 단계에서 구조가 달라진 부분이다. 동작과 요청, 응답 계약은 v1.6과 같고 결정의 자세한 이유는 [../decisions.md](../decisions.md)에 있다.

| 항목 | v1.6 | v2 | 이유 |
|---|---|---|---|
| 풀 리퀘스트 병합 작업 위치 | 받는 프로젝트마다 병합용 복제 저장소(`repo/git-merging/<소유자>/<이름>.git`)를 만들고 대체 객체 디렉터리로 연결한다 | 받는 프로젝트의 저장소 안에서 보내는 브랜치를 `refs/yobi/pull/<번호>/head`로 가져와 JGit RECURSIVE 전략으로 작업 트리 없이 병합하고 결과를 `…/merged`에 둔다([../subsystems/pull-request-merge.md](../subsystems/pull-request-merge.md)) | JGit이 작업 트리 없이 병합할 수 있어 복제 저장소와 그 정리 작업이 필요 없다. 결과 커밋과 상태 흐름은 같다 |
| 비동기 작업(Akka 액터) | 병합, 푸시 훅 후처리, 메일 수신 등을 액터로 처리 | `BackgroundJobRunner`와 Spring 이벤트(`yona.background-async`) | Play 전용 액터 시스템 대체 |
| 알림 발행 | 모델 저장 시점에 `NotificationEvent`를 만든다 | 활동을 Spring 이벤트로 발행하고 리스너가 알림 이벤트를 저장한다 | 도메인 계층이 알림 계층에 의존하지 않게 한다 |
| 라우팅 | `conf/routes` 한 파일과 맨 아래 포괄 라우트(끝 슬래시 제거) | 컨트롤러별 매핑과 `GlobalErrorHandler`의 처리기 없음 규칙(A-103). 대조는 `RouteParityTest`가 맡는다 | Spring MVC의 매핑 방식. 포괄 매핑은 정적 자원을 가린다 |
| Subversion HTTP(WebDAV) | `sonia.svnkit:svnkit-dav` 서블릿을 Play 컨트롤러에서 파이프로 호출 | Maven Central의 `svnkit-dav` war에서 클래스를 꺼내 쓰고 Jakarta, javax 서블릿 어댑터와 필터(`SvnDavFilter`)로 처리한다(D-26, A-98) | 같은 jar를 공개 저장소에서 받을 수 없고 Spring 디스패처가 WebDAV 메서드를 거부한다 |

## 기존 v1.6 설치 위에서 쓰기 (2026-10-25 실제 점검)
v1.6의 `conf/evolutions/default/1~32.sql`의 `Ups`를 새 MariaDB 10.11에 적용한 데이터베이스(61개 테이블)에 v2를 붙여 확인했다.

- 기동: 오류 없이 올라오고 초기 데이터(역할 7개, 관리자)는 v1.6 `initial-data.yml`과 같다. 스키마 변화는 [decisions.md](../decisions.md) A-104의 두 가지(중복 인덱스 2개, `webhook_type` 폭)뿐이다.
- 읽기: v1.6 형태로 넣은 사용자(v1.6 해시 비밀번호로 로그인, 잠긴 사용자 거부), 프로젝트(공개, 비공개), 이슈(상태 정수, 담당자는 `assignee` 테이블을 거친다), 댓글, 라벨, 마일스톤, 게시글, 추천, 이벤트, 첨부, 감시, 즐겨찾기가 화면에 맞게 나온다.
- 쓰기: v2가 쓴 이슈, 댓글, 마일스톤, 게시글이 v1.6과 같은 형태이다(번호가 이어지고 `last_issue_number`가 늘며 상태는 정수 1=열림, 2=닫힘, 마일스톤 마감은 `23:59:59`).
- 디스크: `repo/git/<소유자>/<이름>.git`과 `uploads/<SHA-256>`을 그대로 쓴다. 저장소 HEAD가 가리키는 브랜치가 실제 브랜치와 같아야 코드 화면이 열린다(JGit이 만든 v1.6 저장소는 `master`, v2가 새로 만드는 저장소는 `main`: X-22). v1.6 저장소를 복제하고 푸시할 수 있다.
- 열거형: `issue.state`, `milestone.state`, `pull_request.state`, `webhook.webhook_type`은 선언 순서(서수)로 저장하므로 순서가 v1.6과 같아야 한다. `EnumOrdinalParityTest`가 지킨다.
- 이전(Migration) 화면: 내보내기 JSON이 위 데이터에서 v1.6 모양으로 나오고, 화면에서 원본과 대상을 골라 마일스톤, 이슈, 게시글을 옮기면 GitHub로 나가는 요청(마일스톤 생성, `import/issues`)이 서버 내용과 같다. 단 토큰 교환이 폼 형식만 해석하는 v1.6 결함(R-58 1) 때문에 GitHub가 JSON으로 답하면 토큰이 비어 인증이 반복된다.
