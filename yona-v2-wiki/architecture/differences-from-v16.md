

## v1.6에서 물려받은 결함을 고친 곳 (선생님 지시 2026-11-11 "1.6부터 있던 결함도 수정해줘", A-462)

계약 조사 재현에서 "v1.6 결함 유지"로 판정된 139건 중 사용자가 겪는 오동작 74건을 고쳤다(담당 W1~W4와 총괄 6건, 시험 먼저). 항목별 근거와 시험은 `ui-contract/verification/v16-fixes-W1~W4.md`에 있다. 나머지 SKIP 49건은 설계상 한계나 영향 없는 조건이라 그대로 두었고, ASK 20건은 `decisions.md` A-463에 선택지와 권장안을 적어 선생님 결정을 기다린다.

주요 달라진 점(v1.6은 어땠고 지금은 어떤가):

- **입력 검증과 500**: 최초 관리자 설정의 항목 누락이 500에서 필수 오류 400, 비밀번호 확인 불일치가 400, 다른 프로젝트 라벨 지정이 400, 업로드 크기 초과가 413으로 바뀌었다. 게시판 글 작성 오류 화면은 제출한 본문을 유지한다.
- **프로젝트 소속 확인**: 이슈 일괄 변경, 이슈 작성과 수정, 마일스톤 6개 경로, 댓글 삭제(board-F12)가 주소의 프로젝트에 속하지 않으면 404이거나 무시한다. v1.6은 번호만 보고 처리했고 일부는 500이었다.
- **권한과 표시**: 읽기 권한만으로 보이던 댓글 수정 단추, 구성원에게 보이던 라벨 관리 톱니바퀴(누르면 403), 코드 접근이 막힌 사용자의 `c`, `p` 단축키를 없앴다. 비공개 프로젝트에서 구성원이 아니게 된 작성자의 수정은 막힌다(`AccessControl` 작성자 규칙 전반에 적용, board-F14).
- **화면 동작**: 커밋 화면에서 파일 머리를 눌러 접고 펴기, 웹훅 형식 변경 때 푸시 체크 상태, `CTRL+SHIFT+ENTER`, 사이드바 고정 때 쿼리 유지, 즐겨찾기 실패 알림(JSON이 아닌 응답 포함), 목록을 못 읽어도 아바타 단추로 사이드바 열기(shell-F7), 이전 화면의 서버 거부(403, 404) 표시(migration-F8)를 고쳤다.
- **표시와 안내**: 도움말의 프로젝트 단축키 안내가 실제 등록 조건(메뉴 설정, 코드 접근)과 같아졌다(shell-F5). 게시판 메뉴를 끈 프로젝트의 목록에는 글쓰기 단추가 없다(board-F10). 비밀 키 안내와 재시작 안내 상자는 좁은 화면에서 폭을 넓힌다(welcome-F4). 이메일 확인 안내와 조직 화면의 고정 문구는 언어 설정을 따른다.
- **검색과 이동**: `searchType=auto`의 다음 쪽 이동이 종류를 바꾸지 않는다. 외부 `Referer`로는 이동하지 않고 목록으로 보낸다.
