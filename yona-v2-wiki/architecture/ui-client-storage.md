# 새 UI의 클라이언트 저장소(IndexedDB) 설계

> **상태: 설계 제안(`decisions.md` D-135).** 선생님이 "새 UI는 IndexedDB를 적극 활용하라"고 지시하셨다. 이 문서는 **무엇을 어디에 담을지**와 **담으면 안 되는 것**을 정한 제안이고, 세부(8절)는 확인을 기다린다. 구현하지 않았다. IA 제안(`ui-ia-gitlab.md`)과 함께 브랜치 `ui-improvements`에서 진행한다.

## 1. 목표와 제약

- **목표**: 새 UI(IA 제안의 틀)가 브라우저에 두는 값을 **IndexedDB를 기본 저장소**로 삼아 정리한다. 용량 제한(localStorage 약 5MB, 동기 호출이 화면을 멈춤), 문자열만 담는 한계, 탭 간 동기화가 없는 점을 없애고, 구조화된 값(초안, 목록 캐시)을 다루기 쉽게 한다.
- **지킬 것**
  1. **v1.6 기능은 그대로다.** 예를 들어 임시 저장(초안)은 입력 5초 뒤 저장하고 다시 열면 복원한다. 저장소가 바뀌어도 사용자에게 보이는 동작은 같아야 한다.
  2. **보안**: IndexedDB는 같은 출처의 모든 스크립트가 읽을 수 있다(XSS 때 노출). 비밀 값은 담지 않는다(5절).
  3. **첫 그림에 필요한 값은 동기로 읽어야 한다.** IndexedDB는 비동기라서 그리기 전에 읽을 수 없다(3절의 하이브리드).
  4. IA의 결정을 유지한다: 폰과 폴드 접힘(600px 미만)은 **사이드바 상태 기억에서 제외**한다(읽기, 쓰기, 예전 키 이전 모두). 이 제외는 **사이드바 상태에만** 해당하고 초안 같은 다른 저장에는 적용하지 않는다(폰에서도 초안은 저장해야 한다).

## 2. 지금의 클라이언트 저장소 사용(코드에서 확인, 2026-11-11)

IndexedDB는 지금 쓰지 않는다. 쓰는 것은 localStorage와 sessionStorage이다.

| 저장소 | 키 | 무엇 | 위치 |
|---|---|---|---|
| localStorage | 현재 경로 문자열(예: `/admin/gitproj/issueform`)과 댓글별 키 | **초안(임시 저장)**: 입력란에 친 글. 입력 5초 뒤 저장, 다시 열면 복원(v1.6 동작) | `temporarySaveHandler.js`, `issue/edit.html` |
| localStorage | 초안 키별 마지막 저장 시각을 담은 JSON 한 개 | 초안 저장 시각 | `temporarySaveHandler.js` |
| localStorage | `shallWeOpenLeftNavigation`, `sidebarActiveMenu` | 핀 사이드바를 켰는지, 그 안에서 고른 탭 | `common/sidebar.html`, `layout.html` |
| localStorage | `useTwoColumnMode` | 2단 보기 | `twoColumnMode.js` |
| localStorage | `showSubtasksAlways` | 하위 이슈 항상 보기 | `showSubtask.js` |
| localStorage | `yobitab-<id>` | 탭 목록에서 마지막에 고른 탭 | `ui/Tabs.js` |
| localStorage | `yobi-intro` | 알림 화면 안내 접기 | `index/notifications.html` |
| sessionStorage | `htmx-history-cache`, `htmx-current-path-for-history` | htmx 뒤로 가기 기록(D-96) | htmx 확장 |

## 3. 설계 원칙: 하이브리드(비동기는 IndexedDB, 첫 그림 값은 동기 저장소)

선생님의 지시는 IndexedDB를 **적극** 쓰라는 것이다. 다만 한 가지 충돌이 있다.

- IA 제안의 "깜빡임 없음"은 그리기 전에 짧은 스크립트가 저장값을 **동기로** 읽어 `<html data-sidebar>`를 정하는 방식이다(`ui-ia-gitlab.md` 4.5절). IndexedDB는 비동기라서 같은 시점에 읽을 수 없다. IndexedDB만 쓰면 사이드바가 기본 상태로 한 번 그려진 뒤 저장값에 맞게 바뀌는 **깜빡임**이 생긴다.
- 그래서 **레이아웃을 정하는 아주 작은 값(사이드바 접힘, 2단 보기)만 localStorage에 둔다**(동기 거울). 나머지는 모두 IndexedDB가 원본이다. 거울 값도 IndexedDB의 `prefs`에 함께 쓰고(원본), localStorage는 첫 그림용 사본으로만 쓴다. 그러면 localStorage가 막혀도 IndexedDB에서 값을 복원하고 깜빡임만 생긴다.
- 선택지: (가) **하이브리드**(위). (나) IndexedDB 전용(깜빡임을 받아들임). (다) 서버 쿠키 거울(동기이고 CSP 영향이 없으나 요청마다 실림). 권장: **(가)**. 8절의 결정 2.

## 4. IndexedDB에 담을 것(제안)

DB 이름 `yona-ui`, 버전 관리형 스키마. 모든 레코드의 키에 **사용자 ID와 출처(사이트 주소)를 포함**한다.

| 저장소(object store) | 키 | 값 | 수명 | 쓰임 |
|---|---|---|---|---|
| `drafts` | (사용자, 범위 키) 범위 키는 지금의 경로 문자열 또는 댓글 키와 같게 유지 | 글, 저장 시각, 길이 | 제출하거나 지우면 삭제, 최대 30일 | 임시 저장. 지금은 localStorage. 큰 글에도 화면이 멈추지 않고, 탭 간 동기화가 된다 |
| `switcher` | (사용자, 탭 이름) 즐겨찾기, 프로젝트, 최근 읽은 이슈 | 목록의 식별자, 이름, 갱신 시각(본문 없음) | 7일, 로그아웃 때 삭제 | 사이드바 전환기(IA 4.2.1절). **캐시를 먼저 그리고 서버 응답으로 갱신**(stale-while-revalidate)해 열자마자 목록이 보인다 |
| `prefs` | (사용자, 이름) | 탭 선택(`yobitab-*`), 전환기 탭, 안내 접기, 하위 이슈 보기 등 | 지우기 전까지 | 비동기여도 되는 개인 설정. 첫 그림에 필요한 것만 거울로 localStorage에도 쓴다(3절) |
| `visited` | (사용자, 종류, 대상 ID) | 이름, 방문 시각 | 최근 200건 | "최근 방문"의 빠른 표시(서버가 원본) |
| `search-history` | (사용자, 순번) | 검색어 | 최근 20건, 로그아웃 때 삭제 | 검색 입력의 최근 검색어(**새 기능**이라 8절의 결정 4) |
| `meta` | 이름 | 스키마 이전 기록, 마지막 정리 시각 | | 이전과 정리 관리 |

**처음에는 담지 않는 것(범위 밖)**: 오프라인 쓰기 대기열(작성한 글을 연결 없이 쌓아 두었다가 올리기). 충돌 처리와 권한 재확인이 필요한 별도 기능이다. 초안을 서버에 올려 두는 확장도 마찬가지다.

## 5. 담으면 안 되는 것(보안)

- **세션, 토큰, 비밀 값**: 로그인 세션, API 토큰과 OAuth 토큰(만든 직후 한 번만 보이는 값 포함), 2단계 인증 시드와 백업 코드, 비밀번호, SSO 비밀, 조직 비밀. 같은 출처의 모든 스크립트가 읽을 수 있으므로 XSS가 곧 유출이다.
- **프로젝트와 이슈의 본문**: 접근 권한이 바뀌어도 남는 캐시는 위험하다(구성원에서 빠진 뒤에도 이슈 제목이 남음). 목록 캐시는 식별자와 이름만 담고, 열 때 서버에서 권한을 다시 확인한다. 초안은 사용자가 쓴 글이므로 예외이다.
- **공용 컴퓨터**: 사용자 ID로 구역을 나누고(남의 값을 읽지 않음), **로그아웃 때 `switcher`, `visited`, `search-history`를 지운다**. 초안은 로그아웃 때 지울지 선택할 수 있게 한다(8절). 서버가 사용자가 바뀐 것을 알리면(다른 사용자로 로그인) 앞 사용자의 구역을 지운다.
- **개인정보 최소화**: 이메일, 이름, 아바타 주소 같은 값은 필요한 만큼만 담는다.

## 6. 구조

- **모듈**: `esm/store/`에 작은 ES 모듈 하나(`yona-ui` DB 열기, 저장소별 읽기와 쓰기, 스키마 이전). 화면별 스크립트는 이 모듈을 거쳐서만 저장소를 쓴다(직접 `indexedDB`와 `localStorage`를 부르지 않는다. 구조 시험이 지킨다).
- **라이브러리**: 얇은 약속(Promise) 래퍼 **`idb`**(약 1KB, gzip)를 쓴다. Dexie(약 25KB, 질의와 라이브 질의가 풍부)는 지금 필요하지 않다. 원시 IndexedDB를 직접 감싸 만드는 안은 트랜잭션 수명 같은 함정을 직접 떠안으므로 택하지 않는다. 들이는 방식은 다른 라이브러리와 같다(D-91의 vendoring). 직접 구현하지 않는다.
- **트랜잭션 규칙**: IndexedDB 트랜잭션은 이벤트 루프가 비면 끝난다. 트랜잭션 안에서 네트워크 호출이나 임의의 `await`를 하지 않는다(서버 응답은 받은 뒤 짧은 트랜잭션으로 쓴다).
- **다중 탭**: 다른 탭이 스키마를 올리면 `versionchange`에서 연결을 닫고 새로 연다. 탭 간 변경(초안, 설정)은 `BroadcastChannel`로 알린다.
- **스키마 이전**: DB 버전마다 `onupgradeneeded`에서 순서대로 이전한다. **localStorage의 예전 값은 처음 한 번 IndexedDB로 옮긴다**: 초안(경로 키)은 옮기되 사용자가 제출하거나 지우기 전에는 예전 키를 지우지 않는다(옛 UI로 되돌려도 초안이 남는다). 사이드바 키는 IA의 이전 규칙(넓음에서만)을 따른다.
- **쓸 수 없을 때**: 비공개 창, 사이트 데이터 차단, 용량 초과, 오래된 브라우저에서 IndexedDB가 열리지 않으면 **메모리 저장소로 물러난다**(그 탭 안에서만 유지). 초안은 localStorage로 한 번 더 물러난다(지금의 동작). 모든 호출은 예외를 삼키고 화면은 정상으로 동작해야 한다.
- **용량과 유지**: 오래된 레코드는 수명(4절)에 따라 시작할 때 지운다. 용량이 모자라면 초안을 제외한 캐시부터 지운다. `navigator.storage.persist()`는 초안을 오래 지키려고 요청하되, 거부되어도 정상이다.
- **폴드와 폭 변화**: 저장소는 폭과 무관하다. 폭이 구간을 넘나들어도 값은 그대로이고, 사이드바 상태만 IA의 구간 규칙을 따른다.
- **htmx 뒤로 가기 캐시**(sessionStorage)는 htmx 확장이 동기 API를 요구하므로 그대로 둔다.

## 7. 시험(TDD, 구현 때)

- **단위**: 각 저장소의 읽기와 쓰기, 수명 정리, 스키마 이전(v0에서 v1, localStorage에서 이전), 사용자별 구역 분리, 로그아웃 정리, 메모리 대체 동작. 실제 IndexedDB 동작은 브라우저에서만 의미가 있으므로 **Playwright로 실제 Chromium**에서 확인한다(Firefox와 WebKit도 같은 시험을 돌린다).
- **구조 시험**: 화면별 스크립트가 `localStorage`와 `indexedDB`를 직접 쓰지 않는다(모듈 밖). 비밀 값 이름(`token`, `secret`, `password`)이 저장 코드에 나오지 않는다.
- **동작 보존**: 초안이 입력 5초 뒤 저장되고, 새로고침과 다른 탭에서 복원되고, 제출하면 지워진다(지금과 같다). 예전 localStorage 초안이 옮겨진다.
- **실패 주입**: IndexedDB 열기 실패, 용량 초과, 트랜잭션 중단에서 화면이 정상이다.
- **깜빡임**: 사이드바 첫 그림이 IndexedDB 열림을 기다리지 않는다(3절).
- JS 단위 시험 도구가 이 저장소에 있는지(Vitest 같은)는 확인하지 못했다. 없으면 Playwright 위주로 한다.

## 8. 결정이 필요한 것(`decisions.md` D-135, 권장안 포함)

1. **IndexedDB를 기본 저장소로 삼는 범위**: 4절의 표(초안, 전환기 캐시, 설정, 방문, 검색어, 메타). 권장: 표대로. 비밀과 본문 캐시는 제외.
2. **하이브리드냐 IndexedDB 전용이냐**: 첫 그림에 필요한 값(사이드바 접힘, 2단 보기)만 localStorage 거울. 권장: **하이브리드**. IndexedDB 전용은 새로고침마다 깜빡임이 생긴다.
3. **라이브러리**: `idb`(약 1KB), Dexie(약 25KB), 직접 구현. 권장: `idb`. 직접 구현은 하지 않는다.
4. **새 기능 허용**: 검색 최근 검색어, 전환기 캐시(첫 열기 속도)는 v1.6에 없는 동작이다. 권장: 허용하되 `differences-from-v16.md`에 기록.
5. **로그아웃 때 초안**: 지운다 / 남긴다. 권장: **남긴다**(작성 중이던 글을 잃지 않게). 단 공용 컴퓨터를 위해 설정에서 "로그아웃 때 지우기"를 선택할 수 있게 한다(그 설정은 개인 설정이므로 `prefs`에 둔다).
6. **오프라인 쓰기 대기열과 초안의 서버 동기화**: 이번 범위에 넣지 않는다. 권장: 별도 항목으로 필요할 때 다시 논의.

## 9. IA와의 관계

- 사이드바 접힘의 저장(`shellSidebarCollapsed`)은 IA 4.5절 그대로 localStorage 거울이다(3절). 폰과 폴드 접힘은 읽기, 쓰기, 이전 모두 제외한다.
- 사이드바 **전환기**의 목록(즐겨찾기, 프로젝트, 최근 읽은 이슈)은 IndexedDB `switcher`에 캐시해 열자마자 보여 주고 서버로 갱신한다(IA 4.2.1절).
- 단계: IA의 P0(셸)에 저장소 모듈과 `prefs`, `switcher`를 넣는다. 초안(`drafts`)은 화면별 스크립트라 셸과 독립이므로 편집 화면을 옮기는 P2 이후에 옮겨도 된다.

## 10. 확인하지 못한 것

- Safari와 iOS가 스크립트로 쓴 저장소(IndexedDB 포함)를 **일정 기간 사이트를 열지 않으면 지울 수 있다**는 정책과 삼성 인터넷의 동작은 일반 지식이고 확인하지 못했다. 초안이 사라질 수 있다는 전제로 설계했다(`persist()` 요청, 서버 동기화는 별도 항목).
- 이 앱의 내용 보안 정책(CSP)과 동작에 영향이 있는지(인라인 스크립트)는 확인하지 못했다.
- JS 단위 시험 도구가 이 저장소에 있는지 확인하지 못했다.
- 폴드 기기에서 IndexedDB 동작은 기기 확인을 하지 못했다(폭과 무관하다고 가정).
