# 리뷰 목록 높이: 현재 방식과 CSS 방식 비교

`code.Diff`의 `_setReviewListHeight`(창 크기와 스크롤마다 `.review-list`의 `max-height`를 계산)를 CSS(`max-height: calc(100vh - 20px)` + flex)로 바꿨을 때의 화면 비교이다. **결정: 바꾸지 않는다(현행 유지, D-124).** 나중에 다시 판단할 수 있도록 남긴다.

검증 조건: 검증용 커밋(`235e479c`)에 리뷰 스레드 8개를 만들고, 화면을 34,551px로 늘리고 카드를 33개로 늘렸다. 창은 1280×700.

각 이미지의 왼쪽(빨강)이 현재, 오른쪽(파랑)이 CSS 방식이다. 위 막대에 패널 위치와 목록 높이를 적었다.

| 이미지 | 스크롤 | 설명 |
|---|---|---|
| `cmp-01.png` | 맨 위 | 현재는 카드가 모두 펼쳐져 목록이 길고(2234px), CSS는 화면 높이(634px)로 줄어 안쪽 스크롤이 생긴다 |
| `cmp-02.png`, `cmp-03.png` | 막대가 붙은 직후 | 현재 639px, CSS 634px로 거의 같다 |
| `cmp-04.png` | 중간 | 같은 모양 |
| `cmp-05.png` ~ `cmp-08.png` | 맨 아래로 | 현재는 비교 영역 끝 96px 앞에 맞춰 목록이 줄어들어 패널이 항상 보인다. CSS는 줄어들지 않고 패널이 위로 밀려 올라가 마지막 지점에서 윗부분 37px이 화면 밖으로 나간다 |

CSS만으로는 "맨 위에서 펼치고, 붙으면 화면 높이에 맞추고, 끝에서 줄어드는" 세 단계를 흉내 낼 수 없다.

## 동영상

같은 동작(① 맨 위에서 오른쪽 패널 위에 마우스를 두고 휠 ② 본문 위에서 끝까지 내리기 ③ 다시 올리기)을 녹화했다.

- `js.webm`: 현재 방식(JS가 `max-height`를 계산). 빨강 라벨
- `css.webm`: CSS 방식. 파랑 라벨

스크롤바가 보이도록 두 영상 모두 페이지 스크롤바는 회색, 리뷰 목록 안쪽 스크롤바는 빨강으로 입혔다(재현 스크립트는 `e2e/datepicker.tmp/review-video.mjs`).

## 천천히 다시 녹화한 동영상(권장)

처음 영상은 너무 빨라 차이가 잘 보이지 않아, 속도를 늦추고 화면에 수치(페이지 스크롤, 리뷰 목록 안쪽 스크롤, 목록 높이, 패널 위/아래)와 목록 영역의 주황 점선 테두리를 넣어 다시 녹화했다.

- `slow-js.webm`: 현재 방식. `slow-css.webm`: CSS 방식
- `f-js-9.png`, `f-css-9.png`: 장면 ①(맨 위에서 패널 위에 마우스를 두고 휠)의 같은 시점 프레임

실제 차이는 아래 두 군데뿐이고 크지 않다.

1. **맨 위에서 패널 위에 휠을 돌릴 때의 순서.** 현재는 페이지가 먼저 내려가 패널이 화면 위에 붙은 뒤(약 270px) 목록이 안쪽에서 움직인다. CSS는 페이지가 그대로 있고 목록이 바로 안쪽에서 움직인다. 목록이 처음부터 화면 높이(634px)로 제한되기 때문이다.
2. **페이지 맨 아래 근처.** 현재는 비교 영역 끝에 맞춰 목록이 줄어든다. CSS는 줄어들지 않고 패널이 위로 밀려 올라가 마지막 지점에서 윗부분 약 37px이 화면 밖으로 나간다.
