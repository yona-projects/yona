# 실제 git·svn 클라이언트 검증 (2026-10-27)

v1.6은 Play 2.3 빌드 라이브러리가 저장소에서 사라져 실행할 수 없으므로, v2를 실제로 띄우고(`java -jar`, 포트 19100, 자체 데이터 폴더) 명령줄 클라이언트(`git` 2.53, `svn` 1.14.5)로 한글 경로, 큰 저장소, 인증 흐름을 확인했다. 계정 `tester`(구성원)와 `other`(비구성원)로 공개·비공개, Git·Subversion 프로젝트를 만들어 시험했다.

| Git | 한글 프로젝트 이름, 한글 폴더·파일·커밋 메시지·브랜치·태그 푸시와 복제 | 통과 |

## 찾아서 고친 문제

- 한글·공백 프로젝트 이름의 SVN 저장소 커밋이 늘 거부됨 (A-148).
- `.txt`, `.json`, `.js`, `.xml`로 끝나는 주소의 코드 보기가 HTML인데 `text/plain` 등으로 나감 (A-150).
- 50MB를 넘는 Git 파일의 코드 보기와 원본 보기가 500 (A-149, R-115).
- 한글 이름의 압축 파일 내려받기에서 파일 이름 헤더가 사라짐 (A-147).

## 한계

- 이 검증은 v2만 대상으로 한 실제 클라이언트 시험이다. v1.6과 나란히 비교한 것이 아니며, v1.6 동작은 소스와 위키 기준이다.
- `svn` 1.14의 익명 쓰기와 틀린 비밀번호 거부는 서버가 올바른 `401`과 `WWW-Authenticate: Basic`을 보내는데도 클라이언트가 "인증 방식 미지원"으로 보고한다(비대화형 모드의 클라이언트 동작). 서버 응답은 `curl`로 확인했다.
