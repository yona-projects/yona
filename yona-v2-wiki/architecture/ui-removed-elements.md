# 화면 리팩터링에서 없앤 구성 요소 장부

새 셸(`ui-ia-v2.md`)로 화면을 옮길 때 **옛 요나 화면에 있던 구성 요소가 새 화면에 없으면, 왜 없는지를 나중에 볼 수 있도록 이 표에 남긴다.** 선생님 지시(2026-11-11)이다.

## 규칙
1. 화면을 새 셸로 옮기는 변경과 **같은 커밋**에서 이 표에 한 줄을 더한다. 없어지는 요소가 없으면 더하지 않는다.
2. 한 줄에는 옛 요소, 옛 위치(템플릿), 새 상태, **왜**, 근거(결정 번호나 계약 문서), 대신 쓰는 곳을 적는다.
3. 새 상태는 셋 중 하나이다.
   - **옮김**: 기능과 글자는 그대로이고 자리만 바뀐다(예: 가로 메뉴가 사이드바로).
   - **합침**: 같은 일을 하는 둘을 하나로 줄인다(예: 같은 목록이 두 곳에 있던 것).
   - **없앰**: 새 화면에 대응하는 요소가 없다. 이때는 "왜"가 가장 중요하다.
4. 근거가 아직 결정되지 않은 것은 **확인 필요**로 표시하고, 선생님이 정하시면 근거를 채운다.
5. 구현 열은 **계획**으로 시작해 화면을 옮기면 커밋 해시를 적는다. 화면 캡처는 `shots/`의 해당 단계 폴더에 둔다.
6. v1.6의 기능, 주소, 요청과 응답 계약은 이 장부에서 바꾸지 않는다. 장부는 화면의 구성 요소(단추, 링크, 탭, 띠, 패널)만 다룬다.

## 아직 없어지지 않은 것(참고)
새 설계에서도 **그대로 두는** 대표 요소: 코드의 파일, 커밋, 브랜치, 태그 탭과 코드 주고받기의 열림, 닫힘, 보냄 탭(화면 안 탭), 홈의 소개 블록과 접기 단추, 관리자 알림 띠, 사이트 관리 사이드바의 모든 항목(`데이터`가 추가된다), 검색 결과의 분류 목록.
