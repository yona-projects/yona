# next와 next2의 v1.6 소스 근접도

두 브랜치를 v1.6 소스(`60a5ac406`)와 소스 수준에서 대조했다. 실행 결과를 비교한 것이 아니다. 공통 조상은 `60a5ac406`이고 next는 482커밋, next2는 186커밋 갈라졌다.

| 항목 | v1.6 | next | next2 |
|---|---|---|---|
| 라우트(메서드+정규화 경로) 일치 | 300 | 193 (64%) | 285 (95%) |
| 라우트 경로만 일치(메서드 다름) | | 4 | 3 |
| 라우트 찾지 못함 | | 103 | 12 |
| v1.6에 없는 경로 수 | | 219 | 1 |
| 메시지 키 일치 | 1,093 | 1,089 | 1,093 |
| 메시지 값 동일(기본) | 1,093 | 1,083 | 1,092 |
| 한국어 메시지 값 동일 | 1,093 | 1,086 | 1,092 |
| 정적 자원 파일 이름 일치 | 723 | 629 | 723 |
| 정적 자원 내용 동일 | 723 | 604 | 723 |
| v1.6에 없는 정적 자원 | | 99 | 0 |
| 테이블(v1.6 `create table` 61개) 일치 | 61 | 51 (v1.6에 없는 테이블 17) | 51 (없는 테이블 0) |
| 템플릿 | 242 | 이식 원본 표시 없음(이름 대조 111) | 이식 원본 표시 182, 이름 대조 149 |

## 읽는 법과 한계

- 라우트는 Kotlin의 매핑 애너테이션을 정규식으로 읽은 것이라 한계가 있다. next2의 "찾지 못함 12"는 필터가 처리하는 `/svn/**`, `/files/*`, `!`가 든 경로, 로그인 경로 등 해석 한계이고, 런타임에서는 306개를 모두 요청해 확인했다(`coverage.py`). next의 103건은 같은 방식으로 확인하지 않았으므로 일부는 해석 한계일 수 있다.
- 템플릿은 두 브랜치의 이름 규칙이 달라 이름 대조가 부정확하다. next2에만 원본 표시(`이식 원본`)가 있어 182개가 확정된다.
- 테이블 51개는 두 브랜치가 같다. 나머지 10개는 v1.6 마이그레이션에서 만들었다가 지운 테이블로 보이나 개별 확인은 하지 않았다.
- 컨트롤러 내부 로직의 일치는 측정하지 못했다. next2는 공식 v1.16.0과 응답을 대조해 별도로 확인했고([v16-release-differential-test.md](v16-release-differential-test.md)), next는 그런 대조를 하지 않았다.

## 결론

소스 수준의 모든 항목에서 next2가 v1.6에 더 가깝다. next는 v1.6에 없는 경로 219개, 정적 자원 99개, 테이블 17개를 더 갖고 있고, 정적 자원 25개와 메시지 일부가 v1.6과 내용이 다르다. next에서 v1.6에 없는 기능은 D-28의 추가 개발 항목(`roadmap.md`)으로 next2에 단계적으로 가져온다.
